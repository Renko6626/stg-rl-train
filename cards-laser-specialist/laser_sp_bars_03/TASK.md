# 斜向错列短棒流

卡片 `laser_sp_bars_03`，batch3 contract v1，family `bars`，split `train`。机制只有一条：静止预警后，有限长激光棒沿斜向射线前进；无普通子弹和其他压力源。

## 敌人与时限

主入口以 `spawn_enemy(0,64,1000000,0,0,1,boss_main)` 生成固定 boss（四至六参分别是 drop table、score、sprite），不伪造 spawn flags 参数。boss 主任务立即设置 65,535 帧无敌和 `ENEMY_NO_BODY`，之后运行 `phase_begin(0, bar_pattern, 1800, 0)`，等待该段自然结束。血线阈值为 0；boss 不移动、不碰撞自机，激光任务以它为 owner。段结束后的 boss 任务只让出执行，不清除卡片的来源字段或激光。

主模式任务先等 90 帧。引擎的主任务/子任务首跑调度后，实测第一条激光在第 95 帧出现；第 94 帧仍为 0 条。每 42 帧创建一条激光，共 32 条，最后一条在第 1397 帧出生。单条生命周期为 `warn + active + fade`，fade 完成后自然回收。按调度与完整轨迹，最后回收帧 rank 0/1/2/3 为 1709/1679/1649/1619，均早于 1750；段结束约第 1803 帧，实测 1860 帧时激光为 0 条。42 帧是出生间隔。由于最长生效周期（rank 3 的 warn+active=210）仍大于 42 帧，首次出现后直到末波消退，warn/state 0 与 active/state 1 始终至少有一条；契约意义的最大内部无预警/生效空档为 0 帧。末波结束到 time limit 的终端空场不计作内部空档。

## 斜线、错列与空间余量

两条近似平行的斜线组成一组，第二条晚 42 帧出生。每组共用一个法向 lane 偏移 `n=rand(49)-24`，整数闭区间 `[-24,24]px`；经 `int as fx` 按 Q16.16 乘 65,536，再乘 `0.7071fx` 得坐标分量 `q`。正斜率线用偏移 `(-q,+q)`，负斜率线用 `(+q,+q)`；向量长度至多24px，实际线法向平移至多24px。两条共享同一偏移，所以64px纵向中心线间距不会被独立抽样压窄。每条确定性lane中心周围有完整闭区间 ±24px 的法向支持。

每 4 波把 pair 起点道铺过四条方向：左侧朝45°、右侧朝225°、左侧朝315°、右侧朝135°。四个lane center为 `[32,128,256,384]px`，第二棒沿y错开64px。位置依次为 `(-192,lane/lane+64)`、`(192,448-lane/384-lane)`、`(-192,448-lane/384-lane)`、`(192,lane/lane+64)`，每组两条再加共享法向 n。全部中心线 intercept 集合由 `192±lane±{0,64}` 与 `256±lane±{0,64}` 构成，覆盖场地相关斜线截距 `[-192,640]`，相邻 deterministic intercept 最大间距64px；法向随机支持 ±24px 对应的 intercept 移动约±33.94px，各邻带相交，不留下由稀疏固定lane构成的宽连续区。最远边缘线从边角进入有限楔区，相邻方向补上沿边支撑；每条棒本身行程从 `speed×active + length` 得到，rank0最小272px，rank3最小386px。两条同行pair中心线垂距恒为45.25px；rank3净通道下界33.25px、rank0 39.25px。不同方向/相邻道会在场内交错；pair净空不代替联合波次的真实动作检查。

方向按组轮流，四组都从相应侧边进入；lane中心与法向支持合起来覆盖场地相关截距全域，不是在中心或一个角落加单条“补丁线”。`lane=32` 的斜率线经 n 扰动支持 `c=224±33.94`，中心 `(0,224)` 在结构支持区；`lane=256` 的反向斜率线支持 `c=0±33.94`，近 `(0,0)` 也在支持区。rank0从对应边缘到中心/左上角的射线距离约271.53px；最短棒104px加生效行程168px共272px，支持区内的精确lane值可在Easy下抵达这些区域。其他lane中心把 intercept 贯穿 `[-192,640]`，各波覆盖全场。随机采样不是对所有实例可解的证明，实际玩家和固定点基线仍由协调者检查器验证。

每条激光出生时 `end=bar_len`、`start=0`，预警期间棒体完全静止。生效后逐帧用 `lz_origin` 将整根固定长度棒沿方向平移；这是本卡声明的原点平移机制，不用 `lz_speed`（该 API 会把 `end` 重置到 `start`），也不改变长度或方向。每帧位移分量为 `speed*cos(direction)`、`speed*sin(direction)`；首次进入 active 就移动一个速度步，没有跳角/跳位重定位。

## 逐档参数和联合范围

| rank | width | warn | active | speed (px/frame) | length (px，含端点) | 最大行程 `speed×active` | 生命周期 |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 0 | 6 | 90 | 210 | 0.8 | 104–120 | 168px | 312 帧 |
| 1 | 8 | 75 | 195 | 1.2 | 88–112 | 234px | 282 帧 |
| 2 | 10 | 60 | 180 | 1.6 | 72–104 | 288px | 252 帧 |
| 3 | 12 | 45 | 165 | 2.0 | 56–96 | 330px | 222 帧 |

长度在各档均匀整数抽样、端点包含。rank 0 使用 `104+rand(17)`；rank 1 使用 `88+rand(25)`；rank 2 使用 `72+rand(33)`；rank 3 使用 `56+rand(41)`，int 转 fx 是 Q16.16 数值转换。速度与预警不随机，随 rank 上升/缩短；length同时逐档收短而width变宽。每档总扫过距离（棒长+生效原点行程）的最小/最大值为272–288、322–346、360–392、386–426px；随机原点法向偏移至多24px。rank0在相应lane截距附近的最小扫过距离272px，可达边缘到中心的271.53px；是否实际被碰到还取决于随机法向、棒长和出生时间，不把潜在支持当作全部实例可解证明。没有使用 `int as angle`；方向使用四个 angle 字面量。

每档首出生均为帧 95、末出生均为帧 1397；关键状态边界按实测为 `first_spawn + warn`。每42帧一个出生，理论并发不超过 `ceil((warn+active+fade)/42)`：rank0为8、rank1为7、rank2/3为6。最终4 rank × seed1/7轨迹实测visible/live峰值均为8/7/6/6；warn+active与含收缩预算分别低于16/20。内部无state0/1间隔实测为0帧，42帧只记作出生间隔。

## 作者验证与边界

使用 `/data/sunyunbo/www/stg-engine/target/release/stg-harness`。已运行 `check`；rank 0–3、seed 1/7 各运行 1860 帧，八次六诊断字段均存在且为0。并用同版本 `laser-trace` 扫描8条完整无输入轨迹：state 1有限棒段到中心 `(0,224)` 的最近线距在八条轨迹中均≤4px；到左上角 `(0,0)` 均≤5px。各rank的collision reach（半宽+玩家半径）为5.5/6.5/7.5/8.5px，因此每条轨迹都至少有一次有限active棒段经过这两处；帧因随机法向lane变化而异。这是seed1/7的几何/时序证据，不代表所有随机抽样、动作策略或整场生存。

machine-spec 每 rank 的唯一关键帧覆盖首波、交接、warn/active、两条中心 crossing 和两条角点 crossing 的 seed样本、峰值/中段、末波、收缩、精确回收及 frame1800 空场。关键帧几何由seed1/7的`--at`样本合并，并由专项 validator 与逐帧 trace 对拍。

这仅为基础 harness 编译、时序和几何自检。随机验证只覆盖 seed 1/7 与任务声明的范围采样，不穷尽全部组合；共享偏移和单条长度的端点由代码范围推导，未声称每种实例都能通关。尚未运行真实玩家避让、固定角落/顶部站桩检查器，也没有证明训练收益；这些由协调者后续门检查。
