## `--at` 活弹表在 1024 行截断，§4.2b ① 的离线 640 重放对峰值 >1024 的卡不可用

影响面：疑似全池

证据：本单元原文直写（L 档）峰值 2432，跑

```
$ stg-harness run <card> --rank 3 --frames 512 --at 511
活弹 2432 条
输出总行数: 1071
数据行数(7列): 1025      # 只有 1024 颗弹被打印
最后一行:   idx  ox  oy ... （后面直接是激光表表头，弹表被截断）
```

`mapping.md §4.2b` ① 推荐的 `pool640/poolsim.py`（`th06_s3_w12` 用过）逐帧 dump 活弹再按 640 重放；
弹表被截断后，它导出的无上限峰值只有 1024（实测 2432），拟合出的截止规则无意义 → 本单元只能退回 ②。
`s3_w12` 未触发是因为其无上限峰值（H 676 附近）< 1024，弹表没到截断线。

建议：引擎侧把 `--at` 活弹表的行数上限提高/去掉（或在超过时明确标注「已截断」），
否则 §4.2b ① 对所有峰值 >1024 的卡都不可用，而这些恰恰是最需要 ① 的卡。
