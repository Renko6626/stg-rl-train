## `angle` 类型上做角度差 / 取绝对值会失效，必须用 int 存 BAM 手动归一

影响面：疑似全池

证据：本单元 Sub64 有一句经典的「F2 = |F1 − F0|，< 15° 才补发大玉扇」。
- 初次照契约把 `F0/F1/F2` 都声明成 `angle`，写
  `f2 = f1 - f0; if f2 > 32768bam { f2 = 0bam - f2; } if f2 < 2731bam { …发弹… }`：
  `stg-harness run out --rank 4 --frames 3300` 峰值 **弹 4376**（大玉扇几乎每轮触发）。
- 把三个变量改成 `int` 存 BAM、用 `if f1>=65536 {f1-=65536;}` / `if f2<0 {f2=0-f2;}` /
  `if f2>32768 {f2=65536-f2;}` 手动归一后再 `f2 as angle` 传给 `sh_angle`：
  同一命令峰值 **弹 678**，大玉扇触发帧序列与浮点原件逻辑逐帧一致。
- 最小复现（单任务，每帧 `f1 += 2833bam`，圆距离 < 2731 时发 1 颗速度 0.3 的弹，跑 700 帧）：
  - 三个变量为 `angle`（条件 `f2 = f1 - f0; if f2>32768bam {f2=0bam-f2;} if f2<2731bam`）→ 峰值 **289**；
  - 三个变量为 `int`（同上手动归一）→ 峰值 **24**。
  两条卡都 `check` OK、`run --rank 0` exit 0，只有弹数差一个数量级。

建议：改对照表 §2.3 / §2.4（或 ecl-lang 角度类型说明），明确「角度作差、取绝对值、按符号分支时必须
用 `int` 存 BAM 手动回绕；`angle` 类型只用于直接交给 `sh_angle`/角度参数，别在其上做减法+比较」。
