# 简洁的 headless 转写流水线

2026-11-06。用户已认可“薄执行器、后端适配、共用写审约定、复用校验”的路线，并要求检查代码和文档，准备重做。本文记录已确认方向；2026-11-06用户随后授权实施，代码已落地，验证记录见实施计划。后续替代 [11-05 设计](2026-11-05-transcribe-modular-design.md) 中的批量编排方案，已完成的 cards 来源目录调整继续保留。

## 目标与取舍

通过命令行和脚本大量启动便宜的 headless coding agent，执行 ECL 转写和独立审核。批次、作品和模型变化通过清单及资料表达，不再复制调度程序。

采用 Python 标准库薄脚本，复用现有 validate/harness。纯 Shell 在并发和进程退出处理上不够方便；继续扩展旧 TH06 pipeline 会携带不需要的状态和重试逻辑。不要数据库、服务、插件注册框架、自动恢复、自动换模型或自动返工循环。

用户认可 Luna 级作者的大批量派发方向；这不等于本轮启动新付费批次，也不等于作者和审核必须使用相同模型。并发和两种角色的模型由批次明确选择，不沿用复杂度分级表作为永久门槛。

## 执行与文件

```text
已明确边界的任务 → 作者 → 完整机器验收 → 独立审核 → 待收卡
                     任一步失败：记录原因，停止此卡，其余继续
```

- 一个 JSON 清单列任务 id、目录、作者/审核配置；共用配置放清单顶部，单卡只写必要覆盖。不再有作者清单、审核清单和配对清单三份相互关联的输入。
- 每卡 `task.md` 写源版本、入口、依赖、rank、时间窗、已批准简化和参考位置；`source.txt` 保存带来源定位的摘录。
- `card/<id>/` 是唯一目标代码目录，作者直接写，校验和审核直接读。作者说明放任务根 `report.md`，不夹入成品，不另存 out 副本。
- `review/` 是独立审核者的工作目录，保存 `verdict.json` 和数值检查；作者与审核者使用新会话，审核不写目标代码。
- `logs/<本次运行>/` 保存实际提示词、调用参数、进程输出、校验结果和该次结论；不再维护全局事件状态机。保留旧运行记录，重跑只用本次结果判定。
- 正常全链由同一执行器串行推进单卡，卡之间有界并行。提供按 id 选择及 write/check/review 分步入口；write 使旧通过结论失效，review 前需要当前代码的机器验收。
- 同一卡不并发运行多个写审任务；首版按操作约定执行，不增加跨进程锁服务。用户手工修改代码后从 check/review 重跑，不自动监视文件。
- 用户随后明确要求官方最简headless方式：writer/reviewer直接存官方CLI的argv数组，共用stdin启动。取消后端参数转换和对本机dsh-flash的依赖，不用MCP或DSH派发skill。权限按各 CLI 实际能力配置，不能把提示词中的“只读”宣称为操作系统权限隔离。

## 可复现的范围

能够找回“给了哪些输入、用什么命令跑、产出了什么、依据什么通过”，并能重新执行；不承诺云端模型每次输出相同。

- 保留实际源摘录、任务说明、渲染后的写审提示词和命令参数（backend/model/effort/timeout）。不要记录认证信息或整个环境变量。
- 批次保留实际采用的参考页普通副本及来源位置；共享资料每批一份即可，保留相对路径。仅记录 Git commit 不足以说明未提交参考内容。
- 记录 CLI 可取得的版本、项目/引擎版本信息、harness 路径和固定运行 seed。无法取得的版本写未知，不造专门探针或阻塞框架。
- 同一批次保留实际执行后的代码与检查证据；返工前将旧代码作为普通历史备份放到旧运行日志中，当前可执行代码仍只有 card 一份。不做内容寻址、hash、签名、只读冻结或环境镜像系统。
- 新机器需按现有 uv.lock/wheel 安装环境并调整本地路径。原文及参考副本留忽略的 work，不入库，不假装已提供可公开分发的数据包。

## 必要校验与质量边界

执行器检查退出码、交付文件和可解析的结论。失败或 blocked 不能使用旧产物继续推进。机器验收对最终代码完整执行一次：编译、各声明 rank 完整运行、正常段结束、元数据/外壳、池耗尽、开场安全；contract_viol 从警告提升为错误。复用现有测试与工具，不另造验收框架。

作者可做必要编译和局部调试，不再强制完整自验一遍。审核者读原文和作品规则，检查源依赖、参数、时序、难度分支、随机共享及已接受简化，并按本卡复杂度独立推导1–3个数值锚点，不凑数或追小数末位，实际调用 harness 观察。审核者不重复完整 validate；无行为变化不反复跑全套检查。

脚本检查 verdict、重大问题及锚点字段完整，不能证明期望确实独立推导或源语义等价。审核通过仍只表示待收卡；不自动训练、收卡、commit/push。现有 DSH→Opus 抽检及当前批次主会话复核约定仍保留；不把它强加为所有后端的固定第三阶段，也不默认取消已有要求。

## 多作品与输入准备

共用提示词只包含职责、权限、输入、交付和通用审核要求。坐标、opcode、弹型、EX、时序和已接受差异由作品文档维护，避免在每份契约和 brief 重复全文。

输入准备使用已有切分记录及摘录工具，交付统一任务目录。TH06 解析器仍只解析 TH06；不建现代 ECL 通用分析器，不要求主会话替作者预先算好整卡答案。入口和依赖不足时由准备/审核报告具体缺口。新作品可能需要扩充 validator 的编号与预算规则，但不应复制执行器。

## 收敛完成的标志

同一入口能接受 TH06/TH18 任务、选择 Codex/DSH，换批次只改清单。只有一份目标代码，完整机器验收不被写审双方重复执行；失败能定位到单卡日志。通用操作说明只维护一处，旧批次脚本退出当前入口，旧生产证据保留。训练、引擎机制和原作精度政策不在本次重做范围。
