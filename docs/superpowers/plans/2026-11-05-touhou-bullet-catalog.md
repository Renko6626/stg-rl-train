# TH06 / TH18 弹型表与图集接入计划

> 执行：主会话负责集成、图源、生成器、渲染与训练接入；独立任务负责原作数据核查和内核/CLI改动。按用户要求直接在main工作，不提交或推送。

**目标**：让引擎在出生时直接取得按作品区分的弹型半径和外观，覆盖TH06十型与TH18四十八型；保留旧卡编号和物理行为。

**已确认方案**：用户确认外观可共用、弹型/半径按作品区分，碰撞算法选择后置；随后明确授权完整表及运行时接入，准许合成TH06、TH18两份更大裁切图源。

**实现边界**：沿用Rust内核、现有WorldTables v6、Q16.16、16色逻辑行与现有PNG裁切工具路线；不增加World字段。`BulletPool.sprite`保留现有字段但明确存逻辑appearance，表现端经`AppearanceCfg.sprite`取实际图集格。旧192项保持编号/半径/贴图不变，新项追加。出生减速和出生无判定省略，碰撞公式不改；现有换图操作仍保留“只换外观、不刷新半径”的语义，本轮不扩展动态HITBOX/SIZE。

## 约束与需要核实的数据

- 经典TH06与TH06NC分别标识；不以经典尺寸冒充NC已核结果。原作数据/原文留忽略目录，可入库的是少量事实、映射元数据和用户准许的合成图源。
- 从原作普通飞行态取贴图，不能拿出生动画首sprite当普通弹；颜色按原作配置槽核对。保留静态帧与原作动画的区别。
- 图集按最大普通弹片尺寸采用统一格，小弹居中留白，保持逻辑像素大小；两份分作品图源可人工维护，生成器支持离线重跑。
- 原作颜色缺槽明确标无效，不循环补色。无效格指向透明图块，保持部分换色可落透明格的既有约定。
- 保留旧192项，不迁移旧卡或176份旧派生输入；新卡查独立生成的作品词表。
- 确定性：core无浮点；定点数由生成器按round-half-to-even转为整数；表字节必须可重烘一致。
- 表格式仍v6；逻辑编号与物理贴图的含义变化评审为ENGINE_VER31，训练wheel同步升级四处依赖。

- [x] 生成器输出物理图集、图集布局JSON、整数appearance Rust数据和ECL常量词表；相同图块可复用，旧图块0–191保留。

接口：生成的`crates/stg-core/src/tables/touhou_appearances.rs`提供`TOUHOU_APPEARANCES: &[(i32,u16,bool)]`，不含旧192项；按逻辑行追加。`WorldTables::bullet_sprite(appearance: u16) -> u16`给表现端查询；表外手工编号保留旧回退，无效逻辑格映射透明物理图块。

- [x] 在真实发弹路径建立有判别力的覆盖：同贴图、不同半径的两个逻辑弹型，在fire/batch/sh_fire后仍有独立逻辑身份和正确半径。
- [x] 三条发弹入口存逻辑appearance，出生半径仍取表；换图/换形/换色继续在逻辑域运算。
- [x] builder追加生成数据，旧192项测试只检查旧前缀；表往返覆盖非identity映射。
- [x] harness viewer和`run --at`的sprite列输出物理图号，Godot实时/影子/消弹淡出同样查表；RL TYPE继续保留逻辑appearance。

## 验证重点

旧identity数据不能证明映射接线正确；必须有共享贴图但不同radius的行为样本。缺色不得画成别的有效弹。普通态图源和出生动画分开。NC与经典差异如未完全核实，明确保留，不能混用名字。已有变形只换外观的语义不能随新表静默改变。
