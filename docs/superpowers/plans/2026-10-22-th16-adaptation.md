# TH16 接入实施计划

> 执行时按任务推进；原生字段与 ABI 的未决项先核验，不能用猜测填入生产代码。用户的工作范围、架构决策与验证约定优先于技能默认流程。

**目标：**为 TH16 v1.00a 接入现有躲弹模型，提供可交给用户 Windows 试玩的 thcrap 方案。

**架构：**用户于 2026-10-22 选择 thcrap 加载 32 位共享 AI 能力插件，由逐版本 patch 保存 TH16 地址、预期原字节和挂点。游戏抽取器产生 `ap_world_t`，复用 `stg-agent-proto` 的模型输入适配、ORT 推理和运动层。现有模型与图版本 6 沿用，不启动训练。

**技术：**C、thcrap patch、Windows x86 CPU ONNX Runtime、现有 ONNX 模型。

**决定来源：**[用户决定与后续安装包需求](../../agent-memory/project-context.md#游戏接入)。原生研究与产物遵循 renkolab 的 `METHOD.md`、`mods/README.md`、`mods/thcrap-platform.md`；公共接口遵循 `stg-agent-proto/SPEC.md` 和 `c/world.h`。

## 全局约束

- 不创建分支或 worktree，不提交、推送或发布；保留各仓现有改动。
- 沿用现有模型；特殊判定需要改变公共协议或模型输入时，先提出方案并取得用户确认。
- 季节释放保留手动，不自动增加季节策略或资源管理系统。
- 模式与手动优先沿用已有行为，TH06NC 的八帧激光平滑要求不能因共享代码调整而丢失。
- 外部游戏的字段、原生状态枚举和 ABI 逐项核验，不能直接复制 TH06NC 的数值。
- 不带原作 exe、资产、原文摘录或大段反编译内容入库／分发。
- 验证集中运行相关既有检查；新增测试限于新抽取／输入行为及关键 ABI，不启动训练或浏览器交互测试。

## 任务 1：冻结 TH16 抽取与输入约定

**责任范围：**renkolab 的 TH16 自机／弹幕研究条目，以及后续 `mods/th16.v1.00a/autoplay/TARGET.md`。

- [x] 核实本机 exe 位数、样本哈希和既有输入／自机状态字段的指令证据。
- [x] 核实子弹活动链、生成／飞行／消亡时的致死条件及圆／矩形分支。
- [x] 核实敌人位置、稳定标识、Boss 标记与实际体碰范围。
- [x] 核实直线／无限激光的实际致死几何、预警时序、活动链和跨帧运动信息。
- [ ] 明确曲线激光与矩形判定在现有表示下的适配办法；存在新架构决策时单独确认，不静默漏掉危险物。
- [x] 确定观察时点、按住／上升沿／下降沿写入时点，以及暂停、回放、过场和新局的边界；记录 AI 录像尚不支持。

**验收证据：**字段与消费指令相互对应；`TARGET.md` 登记实际样本和全部写入点；将已有文档中的矛盾项与新核验结论区分。

## 任务 2：复用共享推理与控制代码

**责任范围：**`stg-agent-proto/c/` 的现有共享模块；renkolab 中必要的模型控制公共代码与 TH16 抽取器。

- [x] 在任务 1 的接口确定后，列出最小文件变更与函数签名，保持“游戏状态抽取 → 世界快照 → 模型输入 → 动作”的依赖方向。
- [x] 复用模型填表、动作表、ORT 和运动层；直接编译既有纯 C 控制源文件，没有移动所有权或新建通用框架。
- [x] 编译为 x86，准备官方 x86 CPU ORT；核对已有权重来源和签名契约。
- [x] 运行受影响的主机检查；既有 policy／policy_model 通过，原 TH06NC 和公共协议源文件未修改。
- [ ] 在 Windows 实际运行 x86 ORT，核验真实输入／输出与游戏表现；不能用主机测试冒充此项完成。

**验收证据：**真实共享代码的检查结果、x86 构建结果、模型签名与哈希；不以编译通过代替游戏实跑。

- [ ] 接通自由躲弹、射击、手动优先；锚点／引导与炸弹安全网按照已核验的原生机制接入。
