# TH18 转写文档去重与工作包整理计划

> 状态：2026-11-07，用户已批准执行；文档整理、基础检查和Sol实际试用反馈处理已完成。
> 执行者：主会话按 `superpowers:executing-plans` 顺序整理。用户后续明确授权Sol一线worker试用；此次原生subagent试用单独记录，不改变生产流水线，不提交或推送。

**目标：** 作者的常规输入收敛为角色说明、本卡原作 ECL 工作包、TH18 语义与转写规则书、引擎 ECL 手册，减少重复阅读和自行研究。

**结构：** 保留现有官方 CLI → 完整机器验收 → 独立审核的薄执行器。整理现有文档的内容归属和引用路径；两本规则书都是可按章查询的入口，不拼成两个必须通读的大文件。

**技术范围：** Markdown、现有任务模板和清单示例；沿用 Python 执行器与 release harness，不新增依赖或工作流框架。

**依据：** 当前对话已认可的四个常规入口；[现行 headless 设计](../specs/2026-11-06-headless-transcribe-design.md)；[作者批次交接](../../investigations/2026-11-07-th18-dsh-authors-handoff.md)。本计划已在当前对话获准执行；实施结果另附记录。

旧研究记录的存在本身不算错误。需要去掉的是它们作为普通作者必经材料、或向作者发出研究任务的作用。

## 二、推荐归并方式

保留三种不同用途的入口，但去掉各自的重复正文：

- `transcribe/README.md`：操作者的流程说明。维护清单、目录、准备责任、运行命令、状态含义和后续收卡边界。
- `.claude/skills/th18-transcribe/SKILL.md`：主会话的短导航。仅将准备/运行导向流程 README，将整关切分导向切分指南，将知识维护导向规则书；不再复制教学、政策或角色契约。
- `transcribe/contracts/transcribe.md`、`review.md`：两份直接注入的角色说明。分别完整说明作者和审核的职责、权限、自检/抽查、停止和交付。

不把三者合成一份大文档：那会把批次操作和主会话准备步骤重新交给单卡worker。也不增加一份“通用worker总则”让角色说明再引用一次。

TH18的两份写审补充不再承担规则维护。将独有语义并回知识章节，当前入口全部改指通用角色说明；原文件保留极短迁移指针以便旧链接可读，不再列为新任务参考。切分契约保留，因为它属于不同任务角色。

### 唯一维护位置

| 内容 | 维护位置 |
|---|---|
| 命令、批次清单、文件布局、步骤和状态 | `transcribe/README.md` |
| 作者职责、自检范围、report格式、停止条件 | `transcribe/contracts/transcribe.md` |
| 审核职责、抽查范围、fail/pass与verdict格式 | `transcribe/contracts/review.md` |
| 工作包字段与两本书的位置 | `transcribe/templates/task.md`；流程README说明如何填写 |
| 本卡入口、原文、依赖、rank、时限依据、特殊取舍 | 本次 `task.md` / `source.txt`，必要时附明确的本卡边界摘录 |
| TH18规则书目录 | `transcribe/th18/README.md` |
| 原作语法、栈、时间、共享变量及常用转换基础 | `transcribe/th18/mapping.md` |
| 已接受的省略、数值差异与暂缓范围 | `transcribe/th18/transcription-policy.md`，作为规则书一章 |
| 各机制的参数、语义、配方与适用边界 | 现有对应专题，不另造一套速查规则副本 |
| 目标语言、API签名、运行约束 | 引擎现有 `docs/ecl-lang.md` 及分章；扩展手册按需附入 |
| 卡编号、meta字段、TH18外壳和机器验收项 | `transcribe/th18/validation.md`，作为规则书的卡格式附录 |
| 切分步骤、切分产物与交接要求 | `splitting.md`；切分契约只补角色权限/输入/产出 |
| 原生地址、推导过程、历史验证表和旧状态 | 已有调查记录；没有适当归宿的内容集中到一份维护者依据记录 |

允许一句就近提示加链接，不要求读者为了理解一个关键限制往返跳页；完整规范只维护一处。具体机制要求与例子不因文字相似被机械删除。

### 目标阅读路径

```text
主会话：短skill → 流程README → 切分/准备材料（按当前任务）

作者：已注入角色说明 → task/source → 两本书的相关章节 → 写卡/必要自检 → report结束
审核：已注入角色说明 → task/source/card/机器报告 → 同样两本书 → 抽查 → verdict结束

研究记录、旧批次、整关切分履历：由主会话按需使用，不是作者的默认依赖。
```

## 三、实施约束

- 仅在 main 工作；工作区已有大量其他改动，逐文件保留，不还原、不自动commit/push。
- 本次不改 `runner.py`、`worker.py`、validator逻辑、任务JSON协议、状态枚举和CLI后端配置。
- 不改引擎源码或邻仓文档。引擎公开手册中的维护者段落不成为本卡研究授权；若确需上游修正文档，另列问题。
- 不重跑77卡、恢复暂停任务或开始生产审核/收卡/训练。后续用户授权的Sol实际试用使用独立工作包，不覆盖历史任务。
- 不覆盖现有 `work/` 中的task/source、参考副本、prepare.py、prompt、日志或结论；新约定只进入未来工作包。
- 不新增hash、预算计数器、工具拦截、自动恢复、资料生成框架或强制通读清单。
- 保留已批准出生阶段省略及其自然时序后果、圆周/椭圆精度取舍、独立波和奖励波范围、曲线暂缓及现有DSH审核后Opus抽检约定。
- 未核机制仍明确未核，不以删限定语冒充支持，也不新增物理近似。正常读原作ECL、恢复参数/控制流、组合公开API和修自己的实现错误属于作者职责。
- 通用角色说明由TH06共用：只做角色层去重，不把TH18政策塞入其中；TH06/synthetic不做整套文档重构。
