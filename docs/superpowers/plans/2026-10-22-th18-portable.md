# TH18 自包含启动包实施计划

**目标：**除用户自备的 TH18 游戏文件与 Windows 系统组件外，所需加载器、AI、模型和运行库全部随包提供。解压后双击启动器，首次选择游戏，后续直接启动。

**已确认方案：**2026-10-22 用户选择“封装现有 thcrap”，不改成独立代理 DLL。沿用现有 graph6 模型和游戏适配，保持手动默认、控制键、特殊形状暂定门和自动炸弹关闭状态；不借打包扩大游戏功能。

**技术：**现有 C／Win32 启动器、官方 thcrap x86、现有模型和官方 x86 ONNX Runtime；运行库随包配置。目标 Windows 10／11，无 Python／开发工具／联网要求。路径、版本识别与依赖查找是本次关键行为。

## 范围与约束

- 在训练仓 main 工作，不提交、推送、创建 worktree 或发布；保留所有已有改动。
- 本轮打包代码住 `tools/th18-portable/`，构建产物住已忽略的 `dist/`；外仓仅作为既有源码／样本输入，不再修改。
- 不包含游戏 exe、dat、素材、存档或 Ghidra 工程；只读取用户选择的 exe 核对支持版本。
- 启动器不覆盖游戏目录文件；模型和依赖留在包内。包内记录路径与生成配置，子进程继承所需 DLL 搜索路径。
- 官方依赖固定版本、登记来源和 SHA，并保留声明。禁用整包自身的网络更新，以便离线启动。
- 不搭建新的故障恢复／更新器／安装器框架；错误用可理解提示与日志处理。
- 验证只覆盖新增启动配置、打包清单、依赖闭包、编译和必要独立审阅；不重跑训练，不用主机检查冒充 Windows 实跑。

## 分工

1. 主 agent：取得官方发行文件，核对许可和 x86 依赖；准备固定清单与打包脚本、中文使用说明。
2. 启动器 worker：负责 `tools/th18-portable/launcher.c` 与其构建入口。原生选择文件、版本核验、保存路径、生成配置并启动包内加载器；以真实生产逻辑验证关键字符串／路径处理。
3. 独立核对／审阅：确认 thcrap 识别文件、配置／参数／工作目录、关闭更新与注入链，以及最终源码和产物的关键行为。
