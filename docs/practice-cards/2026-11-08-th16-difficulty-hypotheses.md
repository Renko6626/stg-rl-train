# TH16 难度差异：击杀压力与运动对照（2026-11-08）

这轮测试支持两个有限结论：允许实际击杀能改善部分道中段落，但本机现有武器在若干段落中几乎没有减压；持续转向对另两段的生存表现有很大影响。后者尚不能单独归因于缺少加速度输入或 TH06 训练覆盖。

用户随后判断击杀假设未必能解释主要差异，研究重点转向高版本持续转向弹更多时的泛化问题，明确保留“编码器表示不足”和“训练数据覆盖不足”两个候选解释。现有结果不将二者合并成已证实结论；用户在会话收尾进一步确定数据丰富性优先，大注意力层／Perceiver延后；具体数据生产与训练方案另定，统一见[下一步](../next-steps.md)。后续盘点应区分发射器旋转与子弹出生后的真实转向，并关注进入近身区时运动效果是否仍在生效。

用户指定的追敌版本已完成：目标点为 `(选中敌人x，自机当前y)`，保持射击，以当前模型横向追敌并自行躲弹。所有结果来自工作区转写稿，不是 TH16 原作保真验收或人类难度排名。

## 1. 追敌射击与道中压力

取六段不同机制的道中：一面普通自机狙、三面双侧编队及螺旋敌群、四面减速米弹、五面延迟再瞄准幽灵、六面绕圈敌机的直线弹。它们在首次评测中有明显弱项，适合检查无敌外壳的影响；这些是代表段，不是对所有道中段落的随机抽样。

四组均保持射击，使用引擎当前机体、满火力400。自由组目标点锁自机；追敌组通过既有 `track_world` / `target_xy` 接口改目标点，不改模型输入结构。

追敌取点参考 `renkolab/mods/th06nc/autoplay/native/policy_model.c:182`：池序第一只可碰撞敌人，Boss 优先，x 按场界 margin 钳制。按用户要求，y 设为自机**当前** y；这与插件原来的固定 `anchor_y` 有区别。没有敌人时 x 回中，y 仍取当前值。目标点只是指引，模型仍可纵向避弹；本次没有增加压力触发切自由的规则。

可击杀组只在实验副本中解除真实小怪的无敌，控制实体继续无敌，原敌 HP、发弹安排、运动和时限保留。已发出的弹继续存在。满火力使用引擎现有射击表，**尚未标定为 TH16 某机体的 DPS**。

另有原已完成的体碰对照：s3_w07 关闭敌人体碰后为12/30，原样0/30；s6_w02 关闭体碰仍0/30。s3_w07 的无敌外壳同时包含难以消除的敌机接触压力，因此改善不能全归结为少发弹。回放只记录附近接触候选，未直接读取碰撞命中源，不把候选表当作精确死因分类。

## 2. 持续转向对照

选 s4_b3 旋转御札非符、s6_b11 春季终符、s7_b6「弾幕の玉繭」，另以 s6_b2 的直线弹作为控制。只把实验副本中的 `set_ang_vel(...)` 置零；保留标量加速度、等待、发射时间、数量、出生几何及随机调用。保留其他一次性转向，所以此处是**持续角速度**消融，不是删除所有运动效果。

| 段落 | 原样存活 | 持续角速度置零 | 共同时间窗内弹数变化 |
| --- | ---: | ---: | ---: |
| s4_b3 旋转御札非符 | 2/30 | 29/30 | −18.3% |
| s6_b11 春季终符 | 7/30 | 6/30 | −0.03% |
| s7_b6 玉繭 | 0/30 | 10/30 | −27.4% |
| s6_b2 直线弹控制 | 30/30 | 30/30 | 0.0% |

为检查实际近身运动，对保存的物理动作作 native 回放，按弹池 index+generation 匹配弹身份。每5帧取自机128px边缘范围内最近64颗弹，用当时位置／速度作10、20、30帧直线外推，再与真实位置比较。只对相应时域后仍存活且身份匹配的弹计误差；这会排除已消失的弹。诊断未送入策略，也不是碰撞风险预测器。

| 原样段落 | 近身弹中有连续运动效果／STEP的采样占比 | 20帧外推平均横向偏差 |
| --- | ---: | ---: |
| s4_b3 | 71.8% | 7.220px |
| s6_b11 | 13.1% | 0.005px |
| s7_b6 | 91.0% | 5.370px |
| s6_b2 | 0.0% | 0.000px |

“横向偏差”是对原速度方向的垂直分量；单纯沿原方向加速主要体现在纵向误差。因此春季终符的0.005px不代表完全没有速度变化，其20帧总外推误差均值仍约1.270px。四面御札在关闭角速度后总外推误差仍约3.273px，而胜率大幅提高，说明“没有显式标量加速度输入”不足以单独解释这段弱项。

结果较强地支持持续转向及其形成的弹幕几何是当前模型的弱点；但关闭转向也改变了驻留时间和弹量（两张改善卡分别少18.3%和27.4%），不能把胜率收益全部归为编码器问题。训练分布覆盖、观测缺少运动历史／加速度／角速度、当前空间布局与弹密度尚未被完全拆开。未启动新结构或新训练。

## 3. 春季终符需要修正的判断

首次10局的 s6_b11 是5/10；补成三批后分别为5/10、2/10、0/10，合计7/30。此前样本偏乐观，当前模型在这段也并不轻松。关闭持续角速度只有6/30，没有显示稳定改善。

这段还有一个已核实的口径差异：原作摘录 `source.txt` 的1630、1638、1648行条件分别为 `LIFE>3500 && TIME<=1800`、`LIFE>2500 && TIME<=3600`、`LIFE>1500 && TIME<=5400`。当前副本因 Boss 无敌、没有扣血，按30/60/90秒推进，并保留阶段清弹；实机射击可以通过血线提前推进。这是解释人机难度排序差异时必须考虑的另一因素，本轮没有对它单独做 DPS／血线实验。

当前子弹 token 是相对位置、速度、半径五维，模型没有跨帧子弹历史状态；用户提出的缺少加速度信息确有结构依据。但以上实验只能说明哪些机制影响表现，尚不足以证明补输入或补 TH16 训练一定能解决问题。

## 核验与边界

- 四路原试验和四路追敌试验均完整结束，正式120个任务各10局，无执行错误或超时。
- 原样 seed12345 的10张代表卡逐局 done/frames 对回首次试测一致。六个道中无敌条件在初始火力0与满火力400下的30条 done/frames/kills均一致；这只是控制检查，不作为击杀减压的研究结论。
- 追敌选择器的普通敌、Boss优先、空场与场界检查通过；360局中所有决策帧 `target_y == current_player_y`，实际动作保持SHOT。
- 用现有公开 Env / World 读口回放全部1200局，结束码、帧数、击杀数、自机弹命中数全部一致，回放中观察到的诊断计数为0。临时 Rust 工具没有改引擎源码或新增接口。
- `python analyze_trials.py` 重新核算逐局分子／分母、配对共同时间窗及控制关系；CSV与JSON已生成。`uv run --frozen python plot_results.py` 生成图并目视检查。
- 产物与脚本留在被忽略的 runs 目录；未收卡、训练、修改模型／正式插件、提交或推送。现有原作转写还没有完成独立保真审核，原作机体 DPS 也未标定。
