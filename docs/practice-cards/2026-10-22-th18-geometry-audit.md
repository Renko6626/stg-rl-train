# TH18 r3 漏弹与判定编码审计

2026-10-22，用户报告部分圆弹和激光似乎未被发现或判定尺寸有误，明确要求子代理深入逆向，并追问 ECL 中哪些普通子弹属于矩形。三名子代理分别核对原生碰撞、普通弹状态与时序、共享填表及实际 ONNX。只读调查，无运行代码或模型改动。

核验对象是 TH18 v1.00a，MD5 `9969cac756098c1da05a81de45437a70`；r3 包 SHA256 `f109e39a7dea898c59e343c6e46a6f54d717c3f774ec53c4ad78d64da7a59186`。包内提取器、插件与策略源码均和当前原仓逐字节相同，固定模型 SHA256 `e47016c892fc7b0a9667b959d6e06ee10bff4261ea805022b7b8f4e04b7bc7f1`。[身份记录](../investigations/2026-10-22-th18-geometry/package-baseline.json)。

## 确认的漏采与时序差异

| 项目 | 证据与影响 | 验证范围 |
| --- | --- | --- |
| Line／Infinite 激光状态未归一化 | 原生 Line 初始化为2；Infinite 使用2/3/4，提取器原样写 world；共享 `sa_model_fill` 丢掉 state>1 | 真实提取器+填表复现，并确认 r3 DLL 也有该过滤 |
| 超640颗时先按链序截断 | 前640颗远处弹占满槽后，第641颗近身圆弹被丢掉，ONNX TopK 无法补回 | 真实提取器+填表复现；未证明用户失败帧超过640颗 |
| 冻结等待到期的首个恢复碰撞 tick | 提取器先按 state1&flags0x200 跳过；原生随后可清0x200并在本 tick 移动、致死判定 | 原生可达控制流确认，未捕获用户实机触发频率 |
| state2 转为 state1 的运动 | 可先走半步并判定，再转态走完整一步并再次判定；固定半速描述不覆盖第二段 | 原生控制流与生成 ANM 样本确认，非所有 state2 都如此 |

Line 初始化证据 `0x449108`；共享过滤在 `sa_model.c:139`，实际 r3 DLL 对应 `0x100089c4` 的 `cmp bl,1`。原生 Infinite2/4可碰撞、3为预警，不能简单把所有原生状态改成相同值。候选修复是 Line2→共享active1、Infinite2/4→active1、Infinite3→warning0，仍需按原生时序补现有回归验证。警告：图中 state0 代表预警、state1代表有效，不能只为通过过滤一律写0。

0x200到期路径为 `0x42444e`–`0x42447c`，后续 `0x4245a9`–`0x424612` 仍可移动并致死。state2转态在 `0x424007`–`0x424019`。相反，生成 timer+0xf70 在本体／碰撞之后才增加，未发现把>=8门改为>=7的依据；0x100过滤也有原生仅擦弹路径支撑，不能盲目放宽。

## 圆弹尺寸没有发现统一读错偏移

当前圆弹读取 `bullet+0x658`，flags0x40时乘实时 `+0xf38`；玩家聚焦／非聚焦半径、卡牌影响与条件缩放也已读取。原始48类型的基础尺寸为2至28，EX可以覆盖或缩放，当前下游没有半径32钳制，ONNX可接收半径56。不能把贴图尺寸当作致死半径。

但原生圆碰撞 `0x45ce02`–`0x45ce11` 是严格 `d² < br² + pr²`；训练物理是 `d² <= (br+pr)²`。相同正半径下训练侧危险区域更大：br4、pr3时原生阈值5，半径相加是7。这一差异本身偏保守，不能直接解释危险区域被低估，也不证明学习策略一定安全。

实际 graph6 只为64颗弹提供逐弹 token，其余已入640输入的弹进入粗密度图；这属于现有模型的信息压缩，和适配器先丢掉第641颗是不同问题。实际图也基本不暴露自机半径变化：相同输入只将 pr3改为30，TopK与动作logits完全相同。训练的实际碰撞半径有随机化，不能据此声称模型固定按3像素碰撞，或通过改一个输入值就能完成几何适配。

激光本体的长度与宽度映射和原生包装函数相符；原生激光与玩家的判定使用玩家矩形半宽高，训练侧用圆。默认玩家半宽高1.5、圆半径3，按同一半径比较时圆包住该矩形；仍须和策略网络的学习误差、卡牌及实际训练范围分开判断。

## 哪些普通弹是矩形

已查48种普通弹的原生初始化和完整普通EX写入，以及22份原版ECL资产。普通初始化在 `0x425795` 无条件设置圆形标志0x10；换类型也设置该位，未找到这些已核对路径把它清掉。ECL `etSprite` 选择type／颜色，缩放和尺寸EX也不等于切矩形。因此本次没有建立一个可确认的普通矩形弹种清单，不能凭长条、刀、札等外观贴标签。

原生确实保留矩形普通弹消费分支，但存在函数不代表原版关卡使用它。ECL712可被命名为 `hitboxRect`，实际 `0x435a6a` 调用矩形消弹 `0x4294b0`，并非改变弹的致死形状。动态ECL表达式、未穷尽的间接回调和外部mod仍是边界。激光是另一套集合，其矩形判定不能反推普通弹形状。

当前插件遇到任一已计数的矩形弹、曲线／未知激光或特殊敌机几何会整帧交回手动，日志为 `unsupported_geometry`，并不是只忽略该对象后继续AI控制。这个暂定门此前尚待用户决定，本次没有改动。
