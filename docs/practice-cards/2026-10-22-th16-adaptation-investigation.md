# TH16 接入前置核验

2026-10-22。用户选择 thcrap 加载 32 位共享 AI 插件的接入路线，独立代理 DLL 与“傻瓜安装包”列为后续待办。[决定与边界](../agent-memory/project-context.md#游戏接入)，[实施计划](../superpowers/plans/2026-10-22-th16-adaptation.md)。

> **版本**：TH16 v1.00a，imagebase `0x400000`，本机 exe MD5 `cb9caf54ce5738f70086e783ec88fd2a`。本页 TH16 裸地址均属此样本。证据来自本机样本反汇编、PE 常量及 renkolab 已有资料；没有启动游戏或打开 Ghidra 工程。

## 已确认的运行基础

- TH16 为 PE32/i386。既有 TH06NC 插件与随包 ORT 为 x64，不能直接载入 TH16；模型文件可沿用，但 x86 运行尚未验证。
- 本机已有 llvm-mingw 的 i686 编译器文件；本轮未执行构建。未找到已配置的 Wine／thcrap 游戏运行环境，不自行安装。
- 官方 ORT 1.22.0 的[发布资产](https://github.com/microsoft/onnxruntime/releases/expanded_assets/v1.22.0)包含 `onnxruntime-win-x86-1.22.0.zip`。本轮仅核对资产清单，未下载。
- `stg-agent-proto/c/sa_model.*`、`sa_onnx.*`、`sa_motor.*` 可作为共享代码来源；TH06NC `policy_model.*` 与 `policy.*` 为纯 C 控制参考。尚未移动、复制或修改这些模块。
- thcrap 的断点回调为 x86 cdecl，入口与 `BP_*` 导出应使用 `.def` 保持无装饰名。推理挂点应使用 `type: 3`，让 thcrap 保存完整 flags 与 FPU/SSE 状态；默认 type 0 不满足外部推理库的浮点状态保护要求。依据为本机 thcrap 源码 `breakpoint.h`、`expression.h`、`bp_entry.asm`、`breakpoint.cpp`。

## 直线激光映射依据

设原点为 P、方向为 d、当前长度为 L、显示全宽为 W。Line 与 Infinite 的碰撞全宽参数为：`W<32 ? W*0.5 : W-(W+16)*0.5`，碰撞函数再取其一半作为几何半宽。

- Line 要求 `L>16` 且 `W>3`。`+0x608 &2` 时原点／长度为 P／L，否则为 `P+d*(L/10)`／`0.8L`，两端各裁掉一成。
- Infinite 仅在原生 state 2／4 判定，要求 `L>16`，有效长度为 `0.9L`；不能按视觉可见与否推断致死。
- 原生激光碰撞使用旋转坐标中的自机盒扩张，和现有协议说明中的圆形自机存在角部行为差异。运动量、设定棒长与预警倒计时仍须继续核验。

依据：Line `0x43352b`–`0x433615`，Infinite `0x435623`–`0x4356a3`，实际命中盒 `0x443c1f`–`0x443c5c`。未据此实现新的近似算法。

## 必须留给后续核验的缺口

1. **矩形弹与原生碰撞组合。** 现有协议只有单一弹半径，无法精确表达所有 AABB；共享安全网使用的几何也不能直接宣称与 TH16 一致。任何形状近似或协议扩展需要先明确选择。
2. **曲线激光。** 原生数组指针在 `+0x1524`、计数在 `+0x5f4`、段 stride 为 `0x20`；段位置、角度与长度可读。拆成直线段的容量、选择和跨帧身份尚未确定，不能默认 64 行／模型 K8 足够。
3. **敌人体碰。** 活动链与位置有线索，但实际体碰尺寸、状态门、Boss 标记仍须回消费点核验。
4. **输入与录像时序。** 自机更新前是候选挂点，但已在输入边沿派生之后，不能只写 held；录像记录可能早于 AI 最终动作，须核实回放／记录状态，不提前宣称支持录像。
5. **暂停与阶段门。** 子弹／激光的暂停门不同，不能仅检查自机是否存在；模拟帧号与阶段标记仍待确定。
