# d / t 对照实验（M0 ‖ Q1 ‖ Q2）设计

2026-09-25 立项。父实验 M（`configs/exp-m-edgehug.toml`），在新观测语义（`stg_rl` 0.2.0）下重训为 M0。

## 1. 为什么做、为什么现在做

09-21 的诊断把「r3 跟点档差距」指向几何：一半的死亡是「有安全走法却撞上去」，闭环救援探针替换 0.65% 的帧就 +14pp。
当时的下一步是「动作危险度特征」——把每个动作的短期净距算好喂进去。

用户 09-25 定的方向是 **少喂我们构造的信息**（bitter lesson）：手工特征往后排，**优先级：本实验 → 动作 query 架构 → 动作危险度特征**。
在改结构之前，先回答两个一直没回答的问题：

1. **目标点耦合伤不伤**：现在的弹 token 按「假想自机朝目标点走」构造，目标点一换，速度列、d / t、入选的 64 颗弹一起跳
   （同帧入选集合的 Jaccard 只有 0.44，`experiments.md` 诊断记录第七节）。
2. **没有 d / t 学不学得会**：评测时把 d / t 清零，M 从 0.82 / 0.64 掉到 0.21 / 0.08——但那只说明「已训好的模型依赖它」，
   「不给 d / t 从头训」从没做过。答案决定动作 query 架构能不能用纯原始量做 token。

模型结构（`set_attn_v1`）本轮**不动**，只动特征化里与 d / t、目标点耦合有关的部分。

## 2. 现在的模型到底是什么（M / M0，特征化 `danger_topk_v5` + 模型 `set_attn_v1`）

### 2.1 一帧的数据流

```
引擎 VecEnv（stg_rl，Rust，60 Hz，每帧一步 frame_skip = 1）
   │  Tier 0 表：弹 [x, y, vx, vy, 半径, …]、敌 [x, y, 判定宽, 是否 boss, vx, vy]、自机 [x, y, 判定半径, 速度, 低速位]
   ▼
EnvWrapper._decode → RawObs（按局随机左右镜像；目标点 target_xy 由意图生成器给，见 2.3）
   ▼
特征化 danger_topk_v5（GPU，录成 CUDA 图）→ 7 组张量（2.2）
   ▼
网络 set_attn_v1（28.3 万参数）→ 18 路动作 logit + 价值
   ▼
采样（训练）/ 取 argmax（评测）→ 「想按的」动作 want
   ▼
手部运动层 MotorLayer —— 操作闸门（2.4）：决定这一帧**实际执行**哪个动作
   ▼
动作 id → 按键位（方向 + 低速；射击恒按、炸弹永不按）→ 引擎下一帧
```

### 2.2 输入：七组特征（全部相对自机、已按镜像处理）

| 组 | 形状 | 每行内容 | 和目标点有关 |
|---|---|---|---|
| `bullets` | 64 × 7 | 相对位置 (2) ÷192 · **相对速度 (2)** ÷8 · 半径 ÷8 · **d** ÷128 · **t** ÷60 | 速度、d、t 都有关 |
| `bullets_mask` | 64 | 这一行有没有弹 | 入选集合有关 |
| `enemies` | 8 × 8 | 相对位置 (2) · 判定宽 ÷32 · **d** · **t** · 是否 boss · 敌速 (2) ÷8 | d、t、入选有关 |
| `enemies_mask` | 8 | | |
| `density` | 2 × 14 × 12 | 全屏 32 px 一格：弹数、「朝自机逼近的速度」之和（用**绝对**弹速） | 无关 |
| `player` | 15 | x、y ÷192 · 低速位 · 上一步实际执行的方向 one-hot (9) + 低速位 (1) · `dir_held` · `slow_held`（已执行帧数，封顶 16） | 无关 |
| `cond` | 4 | 到目标点的向量 (2) ÷192 · 距离 ÷448 · 是否在 24 px 圈内 | 这就是目标点本身 |

**d / t 的定义**（`danger_topk_v1.closest_approach`）：假想自机速度
`vp = 当前速度 × (目标点方向单位向量)`，到了 24 px 圈内为 0。弹相对自机的位置 `p`、相对速度 `v = 弹速 − vp`，
匀速外推 60 帧，`d` = 这段时间里的最近**边缘**距离（中心距 − 弹半径 − 自机判定半径），`t` = 达到它的时刻。
**入选规则**：按 `d` 升序取前 64 颗，且 `d ≤ 128`。敌人同理取 8 个（敌速同样减 `vp`）。

也就是说：**速度列、d / t、入选集合三样都由同一个 `vp` 驱动**，都假设「自机正朝目标点走」。

### 2.3 目标点（指令）从哪来

意图生成器每局按比例抽一档（`mixed_v1`：跟点 60 / 锚点 30 / 自由 10）：跟点 = 下半屏随机点、每 2–5 s 换；锚点 = 开局一个点、整局不动；
自由 = 目标点锁在自机上（`vp` 恒为 0）。评测主判据固定用跟点档（`lower_half_uniform_v1`）。部署时目标点来自 mod（boss 正下方 / 鼠标 / 无）。

### 2.4 网络（`models/set_attn_v1.py`）

| 部件 | 做什么 | 参数 |
|---|---|---|
| `ctx` | `player ⊕ cond`（19 维）→ 64 维上下文向量 | 1.3k |
| 弹编码器 | 每颗弹**独立**过 2 层 MLP → 64 维 token；然后三路汇总：均值池化、最大池化、**以 ctx 为唯一 query** 的 4 头交叉注意力 → 192 维。**弹与弹之间没有自注意力** | 17k |
| 敌编码器 | 同上，8 个 token | 17k |
| 密度图 | 两层 3×3 卷积 → 展平 → 64 维 | 46k |
| 主干 | 上面拼起来（192 + 192 + 64 + 64 = 512）→ 256 → 256 | 197k |
| 头 | 策略 18 路 logit、价值 1 路 | 5k |

「动作」只在最后一层才出现：前面对弹的所有汇总都与动作无关，逐动作的判断全靠主干 MLP 从汇总向量里解出来。

### 2.5 输出与操作闸门（手部运动层，`envwrap.MotorLayer`）

网络输出 18 路 logit：动作 id = 方向 × 2 + 低速位，方向 0 不动、1 上、2 右上……顺时针到 8 左上（`actions.py`，冻结）。
选出来的只是「**想按的**」。运动层是一道闸门，模拟人手，方向和低速键各一路**互相独立**的状态机：

- **最短保持**：每换一次取值，抽一个 L ~ U{2..6} 帧，这一段没执行满 L 帧不许再换；
- **生效延迟**：想换时抽 d ~ U{0..2} 帧，d 帧后才生效；等待期间改主意就重抽，改回当前取值则撤销；
- 抽到的 L、d **对模型不可见**；模型只看得到 `dir_held` / `slow_held`（当前取值已经执行了几帧）和上一步**实际执行**的动作。

所以一次决定至少作用 2–6 帧、还可能晚 0–2 帧才生效——躲弹从「每帧纠正的反馈控制」变成了「提前算准的前馈规划」，
这正是 M 的 r3 比无约束的 J 低 20+pp 的来源。训练和评测都开着这道闸门（`eval.motor = "train"`）。

### 2.6 部署时的 ONNX 图

特征化和网络**一起**导出成一张图，输入是原始表（弹 `[B, 5]`、敌 `[E, 6]`、自机 `[5]`、目标点 `[2]`、上一步动作、
`dir_held`、`slow_held`，图版本 4），输出 18 路 logit。运动层不在图里，在 mod 的 C 端。

## 3. 三臂

每相邻两臂只差一件事：

| 臂 | 配置 | 速度列 | d / t | 入选规则 | 和前一臂的差 |
|---|---|---|---|---|---|
| **M0** × 2 种子 | `exp-m0-rebase.toml`（v5） | 相对「朝目标点走」 | 朝目标点外推 | 按该 d 取前 64，`d ≤ 128` | — |
| **Q1 静止假设** | `exp-q1-static.toml` | **绝对速度** | **按自机不动外推** | 按不动的 d 取前 64，`d ≤ 128` | `vp ≡ 0`：弹 / 敌 token 与目标点完全无关 |
| **Q2 无 d / t** | `exp-q2-raw.toml` | 绝对速度 | **去掉这两列** | **按当前边缘距离取最近的 64 颗，不设距离上限** | 去掉外推量（含「按外推选弹」） |

- Q1 的 token 形状与 M0 相同（弹 7 维、敌 8 维）；Q2 弹 5 维（位置 2、速度 2、半径）、敌 6 维（位置 2、判定宽、boss、速度 2）。
- Q2 不设距离上限：原来的 `d ≤ 128` 是「128 px 内会接近的弹」，换成当前距离后若保留 128 px，远处高速来弹会看不见；
  取最近 64 颗、不截断，稀疏局面下多看到的远处弹由网络自己决定要不要理。敌人同理取最近 8 个（边缘距离 = 中心距 − 判定宽 − 自机判定半径）。
- 密度图、`player`、`cond`、网络结构、reward、运动层、训练预算（4096 env × 64 步 × 3500 轮 = 9.18 亿帧）全部与 M0 相同。
- 字母：K 取消、P 是探测 run 的前缀，所以这一组叫 Q。

## 4. 实现

新特征化器 `danger_topk_v6`（`src/stgtrain/featurize/danger_topk_v6.py`），继承 v5，两个配置键（`featurize` 段本来就允许自由键）：

| 键 | 取值 | 默认 |
|---|---|---|
| `frame` | `"target"`（`vp` 朝目标点，v5 行为）/ `"static"`（`vp ≡ 0`） | `"target"` |
| `dt` | `true`（带 d / t、按 d 选）/ `false`（去掉两列、按当前边缘距离选、不截断） | `true` |

`dt = false` 时列**删掉**而不是清零，spec 的形状随之变化；`set_attn_v1` 按 `spec()` 建层，不用改。

**测试**（`tests/test_featurize_v6.py`）：
1. 默认值（`target` + `dt`）与 v5 在随机 RawObs 上**逐元素相等**——保证 v6 是 v5 的超集，M0 与 Q 臂只差开关；
2. `static`：同一帧换任意 `target_xy`，`bullets` / `bullets_mask` / `enemies` / `enemies_mask` 逐元素不变；
3. `static` 的速度列等于弹的绝对速度 ÷8；
4. `dt = false`：形状为 64 × 5 / 8 × 6；入选的恰是边缘距离最小的 64 颗（与朴素排序对拍）；弹少于 64 颗时掩码正确；
5. 三种组合下 `set_attn_v1` 能建出来、前向不出 NaN（含全空掩码）；
6. 相关测试在 Magnus 同版本 venv（torch 2.5.1+cpu、tensordict 0.6.2）里也跑一遍。

**ONNX**：两臂的**原始输入不变**（仍是弹 `[B, 5]` 等），只是图内特征化不同 ⇒ 图签名不变、不 bump 图版本。
本轮不写导出孪生；哪一臂要部署时再补。

## 6. 判读（撑过率按末 4 次评测均值；各档 r2 / r3 分开看）

- **噪声地板 σ**：M0 两个种子的差（跟点档、自由档各一个）。以后所有「单种子 ±2pp」都换成这个实测值。
- **M0 vs M**（旧语义）：差 ≤ 3pp 算「语义变化无害」；否则查瞬移、非匀速帧。
  评测侧已先验过（09-25，M best.pt 在新语义下 × 640 局，CPU）：跟点档 0.816 / 0.628（旧语义同口径 0.812 / 0.628）、
  自由档 0.925 / 0.753（与旧语义逐位相同）⇒ **已训好的模型对这次语义变化不敏感**；M0 回答的是「在新语义下重训会不会不同」，并提供种子方差。
- **Q1 vs M0（目标点耦合）**：差 > 2σ 才算有效应。机制检查：跟点档应比锚点 / 自由档受益更多（跳变只发生在跟点档刷新时；
  自由档本来 `vp ≡ 0`，Q1 在自由档上理应与 M0 持平——这一条同时是 Q1 实现正确的旁证）。
- **Q2 vs Q1（d / t 的价值）**：
  - Q2 在 2σ 内追平 Q1 ⇒ 现有结构能从原始量学会这部分几何 ⇒ 动作 query 用纯原始 token；
  - Q2 明显落后 ⇒ 看它是**慢**还是**学不会**：u3500 时曲线是否仍在涨、u1000–3500 的斜率与 Q1 比；
    学不会 ⇒ 结构是瓶颈，动作 query 的动机更强（但它的 token 可能要保留 Q1 式的静止 d / t 作为退路）。
- 例行探针（best.pt × 640 局，CPU）：`--intent fixed_point_v1` / `follow_player_v1` / `boss_or_free_v1`（部署口径）、`--motor off`。
- 训练侧另看：末期熵、训练死亡率、运动层否决帧，与 M 的 1.66 / 43% / 62% 对照。

## 7. 本轮不做（以及排在后面的）

1. **动作 query 架构**（下一批）：18 个动作各当一个 query，由位移向量、换不换方向 / 低速位、`held`、朝目标点的进度构成，
   对弹 token 做交叉注意力 + 按动作的最大池化，弹间加 1–2 层自注意力；目标点只从 query 进来。token 用哪种由本轮 Q2 的结果定。
2. **辅助预测头**：让网络预测每个动作的短期净距（作训练目标，不作输入）。
3. **动作危险度特征**（原「A」）：最后才考虑。
4. **敌人碰撞学不到**（用户 09-25 记）：需要躲敌人本体的局面很少，敌人 token 的碰撞特征几乎得不到梯度信号，
   而敌人又是单独一套编码器 ⇒ 从大量弹碰撞里学到的几何迁移不过来。候选做法：把敌人并进弹的 token 集合
   （同一套编码器，加类型位 / 判定形状），让「会撞上的东西」共用一份碰撞几何。和动作 query 一起考虑。
5. 评测集补 5–6 关、请求历史、`ent_coef` 退火——不变，照旧待排。
