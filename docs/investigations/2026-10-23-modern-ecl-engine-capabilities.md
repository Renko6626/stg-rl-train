# TH18 ECL 指令与 stg-engine 能力核查

2026-10-23。本轮只调查、保存结论，没有修改转换器或引擎、重建 wheel、训练或提交。范围是本机 TH18 v1.00a 的 22 份 ECL，不能直接外推至所有现代作品。训练仓 HEAD `f3b8815`，引擎 HEAD `bfd2062`，实际读取包含两仓已有未提交内容；引擎 `ENGINE_VER = 24`。

## 结论与统计口径

确有引擎机制缺口，但目前大部分转换失败还不能归因于引擎。必须分开记录：导入器未接规则、现有能力可组合表达但语义需校准、现有运行时没有对应机制、原生含义尚未确认。

本轮重新用现有 `decode()` 解析全部文件，得到 **798 个 sub、22,721 条指令、164 种 opcode**。rank1/demo 下实际调用 `emit_source()`，仍只有 **13 个 sub 可生成源码，4 个是实质攻击**。旧字节码后端可生成 15 个，不能混用两个成功率。上述均为静态扫描／生成，不代表原游戏运行覆盖或保真验收。

扫描结果保存在已忽略的 `transcribe/work/th18-prototype/capability-inventory-2026-10-23.json`，只有统计、名称和诊断，没有复制原作指令摘录。既有首个阻碍分类见[上轮报告](2026-10-23-th18-semantic-audit.md)；首个阻碍数量不能当作补齐某机制后的完整攻击收益。

## 已确认的机制差距与影响

### 1. 发射器的容量和所有权不同

引擎 `ecl/shooter.rs` 明确 `SHOOTERS_PER_TASK = 4`，`TaskPool.shooters` 以任务为键；`sh_fire` 从当前任务读取配置。原作按敌共享的发射器、`I/F` 变量与 async 编排不能自动保留。

本轮在 `etNew/etOn` 中发现字面 ID **4、9**，各出现2次；其他动态 ID 还需运行分析。高 ID 本身可能经活跃槽分析重新编号，并不单独证明必须扩池；跨任务共用配置和依赖源编号的动态选择则无法靠改四个常量解决。容量、共享所有权、同步调用与 async 调度需要一起审视。

### 2. EX 指令族只接了很小的子集

`609 etExSet` / `610 etExSet2` 是指定索引写入变换记录，`611 etEx` / `612 etEx2` 是追加记录；扩展版本接受更多参数。原型只处理611中的单个EX8，以及明确省略的EX2；其余不是已经获得引擎支持。

全量静态用量：609/610/611/612分别 **190/58/593/6** 次。以 `async` 参数为1的记录分别有 **42/26/21/0** 次，说明并行需求存在于素材中；不能把它当作普通顺序记录排队。

引擎有加减速、角度变化、重力、限时插值、反弹、信号等待等真实能力，但每弹目前是一个≤16槽的序列游标。连续角速度与加速度可同时生效，不能因此声称支持任意多通道EX、跳转、重设与独立计时。`SPAWN_PATTERN` 仍是预留，不能作为已实现的分裂／派生能力；挂弹任务能表达一些派生弹，但任务数量、首跑时刻和传参均有限制。

**EX2出生状态是实际玩法缺口。** 前轮已核到原生初始 `pos -= 4*v`、半速出生移动、碰撞门和ANM I0驱动转态，EX8期间还会暂停。引擎 `delay` 是整段不移动、不变换、不碰撞，不能等同半速出生态。详见[原型README中的原生依据](../../tools/th18-import-prototype/README.md#玩法近似及下一步)。本轮未重做该段原生逐指令推演。

其他EX type实际出现多个位值，包括 `0x10/0x80/0x100/0x2000/0x4000/0x200000/0x80000000` 等；本轮未逐项确定TH18语义，不凭别作表或位值直接命名效果。后续应按真实攻击逐类补原生锚点。

### 3. 几何不能靠重命名保留

- **曲线激光711**：2处，分别在 `st07bs::BossCard3_at` 和 `BossCard3_at2`。现有 `LaserPool` 只描述原点、单一方向及射线上区间，没有曲线历史节点和对应碰撞。直线 `laserNew/Timing/On/StOn` 有现成能力可研究映射，但时序、宽度与挂靠仍需核准。用多根直线段代替曲线是待设计方案，不是当前支持。
- **敌人体碰／受击框500/501**：原作参数为宽、高，现有两个写口都只接受一个圆半径。不能随手取宽的一半就叫保真。注意这里是敌人判定，不是已证实普通子弹存在矩形弹种。
- **弹型602**：引擎有 appearance→sprite/圆半径表，但还没有TH18弹型映射；当前一律替成appearance0会改变避让空间。

### 4. 时钟、共享变量与自动插值没有完整对应

- 源goto同时写脚本时间；我方goto只改PC。当前 `clock_base` 方案仅验证独立单sub、固定步速，未覆盖调用恢复、async、冻结和547 `gameSpeed`（素材2次）。
- 91 `floatTime` 有23次：原作自动推进变量插值，敌人有多槽。我方位置／速度插值不等于通用变量插值。有限样本可能生成逐帧更新，但需保留与读变量／异步任务的执行顺序；目前没有通用对应。
- 圆周408/409/410、相对椭圆422/423、Bezier425均在素材中，现有五条运动动词没有一对一的原生运动机构。能否用脚本公式降低、误差目标与更新顺序，需要按样本判断；暂不直接要求新增所有运动器。
- f32→Q16.16、弧度→BAM是明确语义差异，已有 `0.999999f→int` 分支反例。坐标小误差与控制流差异应分别决策，不能笼统标为“数值近似”。

### 5. 原生回调和未知 opcode 仍是调查项

632 `funcSet` 设置每帧执行的硬编码函数，637 `funcCall` 单次执行。素材中632共63次，其中61次参数0，另有1、4；637两次参数2、3，均在 `st07bs::BossCard6`。须先查函数表的具体实现，再判断是否需要引擎机制；不能按函数编号套用TH08或其他作品语义。

`ins_574` 有64次、`ins_94`有2次，本机eclmap仍未命名。22 `debug22` 有207次，社区说明其发行版无实现，但本轮没有核对TH18分派分支，仍列为待确认后方可省略。

旧引擎 `docs/zun-ecl-v2-reference.md` 主表来源是TH13，部分对照也已过时：例如ins1写成loop，而当前TH18 eclmap是delete；文档称通用距离／atan2未暴露，但当前已有 `SYS_DIST/SYS_ATAN2`。不能把旧表当作本作和当前代码的事实。

## 建议的推进顺序

1. 先完善不改变运行时边界的基础转换：普通变量、难度参数、动态参数、发射模式和已有移动／清弹能力。用完整依赖闭合的攻击评估收益，不以消除首个报错为验收。
2. 明确数值与训练保真目标，再单独提出EX2出生、弹型半径、真实发射源的最小方案。
3. 以代表性攻击为依据提出敌共享状态／发射器、async取消和时钟方案；这些涉及模块边界，等待用户确认后实施。
4. 曲线激光独立设计；未知opcode、原生回调和其他EX先补语义证据，不静默省略，也不直接建设完整ZUN VM。
