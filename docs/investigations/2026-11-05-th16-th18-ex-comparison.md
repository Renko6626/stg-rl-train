# TH16 / TH18 ECL EX 转写对照

> 临时材料维护：下文日期目录及其中命令是当时执行记录，现已按用户要求清理。正式结论、来源哈希和正文示例保留；不将这些临时路径作为长期工具入口。

> **版本**：跨版本，TH16 v1.00a 与 TH18 v1.00a；函数地址均带 `th16:` / `th18:` 前缀。EX 十六进制数字是效果值，不是地址。

日期：2026-11-05。仅研究与报告；未改引擎、训练、原型或转写结果，未提交、推送。原始反编译与 Listing 留在已忽略目录，本文只记语义和复核指针。

## 结论与证据边界

两作 609–612 都直接写旧位值 type，记录布局仍为 11 dword。TH18 的 EX 程序从 18 条扩为 24 条，并新增普通弹持续追踪位 `0x40000000`。既有 29 种 TH16 位值在 TH18 仍能对应相同的配置/分派位置（包括配对数据记录），但角度哨兵、随机路径与部分计时时点有差异，不能因同名或同位值就宣称运行效果完全相同。

发现来自两作现有 Ghidra 导出中的分派、配置写入和持续 handler。候选解释用既有 TH16 一手文档与社区表交叉对名，再回到各作自身函数核控制流；关键 TH18 隐式 XMM 参数另用既有 Ghidra Listing 确认。表中的“相同”只指已列子集；消费者或数学未核处显式保留。未运行原作，也没有逐帧等价认证。

## 配置、编号与执行规则

| ECL opcode | 参数顺序 | 写入方式 |
| --- | --- | --- |
| 609 | `id,index,async,type,a,b,r,s` | 指定 index；游标=index+1 |
| 610 | `id,index,async,type,a,b,c,d,r,s,m,n` | 指定 index；游标=index+1 |
| 611 | `id,async,type,a,b,r,s` | 使用当前游标后+1 |
| 612 | `id,async,type,a,b,c,d,r,s,m,n` | 使用当前游标后+1 |

两作共同布局：`[r,s,m,n,a,b,c,d,type,async,sub_string_pointer]`，stride `0x2c`。609/611短式只写 a/b/r/s/type/async；**不会把 c/d/m/n 清零**，覆盖已有记录时须保留未写字段。610/612额外写 c/d/m/n。记录 index 是 EX 程序槽号；type 是旧式原始整数；609–612 是 ECL opcode；社区 0..33 是另一套效果序号。这四者必须分开。type是单个效果标识，分派按相等值匹配；active_fx才是组合位场，不能把任意EX值按OR拼成一个新type。`0x80000000`若以有符号整数呈现是 `-2147483648`，仍是 WAIT 位。

原生写入证据：`th16:0x4211b9`（`EnemyData__ecl_run_over_300`，入口 `th16:0x41dcb0`，导出 case `0x7b`）；`th18:0x43488a`（`FUN_00430d30`，入口 `th18:0x430d30`，导出 case `0x7d`）。以已导入 opcode labels 和内部原始 opcode `0x261..0x264` 条件共同锚定。两作都没有把type当ordinal再做移位转换。TH16发射器stride `0x380`，TH18 `0x488`。首参 id 有范围检查；不要把首参检查误读为第二参 EX index 检查。

执行入口为 `bullet_vm_exec` `th16:0x413860` / `Bullet__run_ex` `th18:0x425c60`。读取当前记录前有三种停门：type为0；async为0且存在除OFFSCREEN `0x100`之外的active效果；当前type与active位相交。故async≠0允许并行挂不同效果，但不能重复启用已经active的同位效果；它不是后台线程。一次性效果大多不置active位。

出生由 `bullet_pool_spawn` `th16:0x412cb0` / `FUN_00424fe0` `th18:0x424fe0` 复制18/24条记录、载入初始PC并立即执行EX。活跃tick由 `bullet_tick` `th16:0x411e70` / `Bullet__on_tick` `th18:0x423e10` 先解释EX，再派发handler；handler返回完成会在同一tick重入解释/派发，最后才通常位置积分。SIZE先于该循环推进；WRAP在后续裁剪前处理。不能把每条EX机械翻成“下一帧的任务”。

每颗弹独立保有程序副本、PC、一个GOTO计数器、快照和各效果状态。子弹/激光派生复制整段父EX，且可以从effect_index进入。多个弹的RNG消耗的是共享重放安全RNG流，不是发射器的单次公共随机值。

<a id="ex-1"></a>
### `0x1` SPEEDUP

**参数**：已核主路径无a/b/c/d/r/s/m/n读取。

**进入、持续、结束**：进入清私有计时；tick在counter<17时叠加5-5*t/16速度；到期清位并允许同tick续跑。

**比较与转写**：相同（已核子集）。不是永久改speed；保留初始冲量与16帧衰减。

**证据**：`th16:0x413860` bullet_vm_exec；`th16:0x414ec0` bullet_beh_speed_boost；`th18:0x425c60` Bullet__run_ex；`th18:0x423e10` Bullet__on_tick。两作EX入口均适用上文async/index/append规则。

<a id="ex-2"></a>
### `0x2` ANIM

**参数**：`a`=ANM interrupt=7+low16(a)。

**进入、持续、结束**：进入state=2，位置退4倍当前速度；state2半速移动，受8tick/ANM变量控制恢复active。出生首条有专门消费路径。

**比较与转写**：相同（已核子集）。a=1的出生路径跳过interrupt；不能当普通静止delay。

**未核**：只核共同状态转换形状，未运行原作ANM。

**证据**：`th16:0x413860` bullet_vm_exec；`th16:0x411e70` bullet_tick；`th18:0x425c60` Bullet__run_ex；`th18:0x423e10` Bullet__on_tick。

<a id="ex-3"></a>
### `0x4` ACCEL

**参数**：`a`=持续时间；`r`=加速度标量；`s`=角参数；各版本解析不同；`m`=TH18瞄准偏移/随机幅度；TH16瞄准偏移见既有一手记录。

**进入、持续、结束**：进入解析方向并存固定加速度向量；tick向速度向量加accel*dt，同时更新标量；非零向量回算角/速；到期清位。

**比较与转写**：不同。TH18用扩展角度helper；随机在进入采样，不能配置时统一采样。

**证据**：`th16:0x413860` bullet_vm_exec；`th16:0x414fb0` bullet_beh_accel_vec；`th18:0x425c60` Bullet__run_ex；`th18:0x427930` FUN_00427930。

<a id="ex-4"></a>
### `0x8` ANGLE_ACCEL

**参数**：`a`=持续时间；`r`=速度增量/帧；`s`=角速度（每步angle+=s*dt）。

**进入、持续、结束**：进入存r/s及计时；每tick角+=s*dt、speed+=r*dt并重建向量；到期清位。

**比较与转写**：相同（已核子集）。持续累积角度和速率，不是一次设角，也不是角速度再累加。

**证据**：`th16:0x413860` bullet_vm_exec；`th16:0x4153e0` bullet_beh_turn_accel；`th18:0x425c60` Bullet__run_ex；`th18:0x423e10` Bullet__on_tick。

<a id="ex-5"></a>
### `0x10` STEP / ANGLE

**参数**：`a`=每段持续时间；`b`=段数上限；`c`=角/速子模式0..7；`d`=保存进私有状态；本轮未确定用途；`r`=角参数；c=5/6为随机幅度；`s`=目标速；<=-999990保留；c=7为当前速随机幅度；`m`=TH18角helper偏移/幅度；`n`=未见主路径读取。

**进入、持续、结束**：进入取目标并清段计数；持续handler先降速，到段界更新角/速并重置计时；达到b段清位。

**比较与转写**：不同。c5/6/7有进入时RNG；c1/6在段界另查玩家角。不能用单一线性角插值代替。

**未核**：d消费与TH16高角参数>=9999990的精确输出本轮未完成Listing复核。

**证据**：`th16:0x413860` bullet_vm_exec；`th16:0x415570` bullet_beh_speed_angle_transition；`th18:0x425c60` Bullet__run_ex；`th18:0x427d50` FUN_00427d50。

<a id="ex-6"></a>
### `0x40` BOUNCE

**参数**：`a`=反弹事件次数上限；`b`=墙mask U/D/L/R=1/2/4/8；0x10抑制反射；0x20自定义尺寸；`r`=> -990时设置反弹处理后的speed，否则保留；`s`=b&0x20时宽；否则384；`m`=b&0x20时高；否则448。

**进入、持续、结束**：进入挂计数/边界；tick越界镜像位置并反射角，累计事件；到a清位；manager边界可覆盖局部尺寸。

**比较与转写**：相同（已核子集）。旧文档称r为“最小速”不准确：读取的代码是直接赋值；精确边界/角落计数仍需Listing。

**未核**：TH18内联后的extraout_EDX计数来源、同时越多墙的行为未逐指令对拍。

**证据**：`th16:0x413860` bullet_vm_exec；`th16:0x415bb0` bullet_beh_wall_bounce；`th18:0x425c60` Bullet__run_ex；`th18:0x427f40` FUN_00427f40。

<a id="ex-7"></a>
### `0x80` INVULN

**参数**：`a`=写入bullet+0x24计数。

**进入、持续、结束**：进入写bomb取消免疫计数；触碰玩家时可保留弹自身，不能据此称无致死判定；两作递减位置不同，详见时点小节。

**比较与转写**：不同。TH16 active效果循环内与函数尾各有递减；TH18仅尾部递减。a不能直接等同a个完整tick。

**证据**：`th16:0x413860` bullet_vm_exec；`th16:0x411e70` bullet_tick；`th18:0x425c60` Bullet__run_ex；`th18:0x423e10` Bullet__on_tick。

<a id="ex-8"></a>
### `0x100` OFFSCREEN

**参数**：`a`=最长保活倒计时；`b`=非0额外做视锥可见性检查。

**进入、持续、结束**：进入置0x100；同步门特意忽略此位；每tick减计时并按可见性/时限清位。

**比较与转写**：相同（已核子集）。不是单一“永不离屏删除”布尔值。

**未核**：复杂视锥投影数学未证明两作完全等价。

**证据**：`th16:0x413860` bullet_vm_exec；`th16:0x4162d0` bullet_beh_offscreen；`th18:0x425c60` Bullet__run_ex；`th18:0x428970` FUN_00428970。

<a id="ex-9"></a>
### `0x200` SETSPRITE

**参数**：`a`=弹型索引；`b`=低15位颜色；0x8000触发ANM interrupt2。

**进入、持续、结束**：进入直接刷新类型/颜色、半径、层桶、取消动画及ANM；不设持续位。

**比较与转写**：相同（已核子集）。中断位在b，不是社区文案的c；弹型数据另见主线报告。

**未核**：贴图/ANM内容不是本报告的等价结论。

**证据**：`th16:0x413860` bullet_vm_exec；`th18:0x425c60` Bullet__run_ex。

<a id="ex-10"></a>
### `0x400` DELETE

**参数**：`a`=等于1时先把cancel script设-1。

**进入、持续、结束**：进入调用cancel；非持续效果。

**比较与转写**：相同（已核子集）。a=1抑制取消动画，不是无限寿命。

**证据**：`th16:0x413860` bullet_vm_exec；`th18:0x425c60` Bullet__run_ex。

<a id="ex-11"></a>
### `0x800` PLAYSOUND

**参数**：`a`=声音id。

**进入、持续、结束**：进入播音；不设持续位。

**比较与转写**：相同（已核子集）。副作用发生在bullet EX相位；未证明声库id跨作一致。

**证据**：`th16:0x413860` bullet_vm_exec；`th18:0x425c60` Bullet__run_ex。

<a id="ex-12"></a>
### `0x1000` WRAP

**参数**：`a`=传送次数上限；`b`=墙mask U/D/L/R=1/2/4/8。

**进入、持续、结束**：进入挂状态；运动/碰撞后、裁剪前按sprite尺寸越界传送，次数达a清位。

**比较与转写**：相同（已核子集）。位移含sprite尺寸+384/448，不能只按坐标越界平移屏宽。

**未核**：各弹型sprite尺寸单独变化，未做视觉对拍。

**证据**：`th16:0x413860` bullet_vm_exec；`th16:0x415d80` bullet_beh_wrap；`th18:0x425c60` Bullet__run_ex；`th18:0x423e10` Bullet__on_tick。

<a id="ex-13"></a>
### `0x2000` SHOOTPREP / SHOOT

**参数**：`a`=aim模式；`b`=子弹起始effect_index；`c`=路数；`d`=层数；`r`=发射角/当前角/玩家角哨兵；`s`=第二角；`m`=首速；<=-999990保留父speed；`n`=末速。

**进入、持续、结束**：进入读紧随记录的sprite/color及delete参数；复制父整段EX到新描述符，立即发射；PC共前进2。

**比较与转写**：不同。TH18仅[999990,1999990)为玩家角，>=1999990按字面角归一；TH16 >=999990走玩家角。

**未核**：发射模式逐项数学、子弹取消/容量满路径未全核。

**证据**：`th16:0x413860` bullet_vm_exec；`th16:0x414da0` bullet_spawn_wrapper；`th18:0x425c60` Bullet__run_ex；`th18:0x427810` FUN_00427810。

<a id="ex-14"></a>
### `0x4000` SHOOT_DATA

**参数**：`a`=配对记录：sprite；`b`=配对记录：color；`c`=配对记录：非0删除父弹。

**进入、持续、结束**：由前一SHOOTPREP读取；单独到达该type未发现独立动作分支。

**比较与转写**：相同（已核子集）。记录必须随相邻前项保留；配对消费不依赖此记录type先被独立执行。

**证据**：`th16:0x413860` bullet_vm_exec；`th18:0x425c60` Bullet__run_ex。

<a id="ex-15"></a>
### `0x8000` REACT

**参数**：`a`=写入反应编号字段。

**进入、持续、结束**：进入写th16+0xc4c/th18+0x664并PC+1；不设持续位。

**比较与转写**：未核（消费者）。仅确认配置与写入同形，不能宣称回调语义或删去它。

**未核**：两作消费者均未在本轮追完。

**证据**：`th16:0x413860` bullet_vm_exec；`th18:0x425c60` Bullet__run_ex。

<a id="ex-16"></a>
### `0x10000` GOTO / LOOP

**参数**：`a`=目标EX记录index；`b`=<=0无条件跳；>0使用逐弹共享循环计数。

**进入、持续、结束**：当前EX内改变PC并继续取指；b计数归零后落到下一记录。

**比较与转写**：相同（已核子集）。计数器每颗弹仅一个，嵌套goto不等同独立栈；回跳本身不强制等下一帧。

**证据**：`th16:0x413860` bullet_vm_exec；`th18:0x425c60` Bullet__run_ex。

<a id="ex-17"></a>
### `0x20000` MOVE

**参数**：`a`=持续时间；`b`=低8位插值模式；0x100相对坐标；`r`=目标x；`s`=目标y。

**进入、持续、结束**：进入固定目标/原speed并启动3D插值；tick把插值差写速度，末端snap目标并恢复原speed、清位。

**比较与转写**：相同（已核子集）。相对点在EX进入读取当前位置；不是etEx配置时绑定。

**未核**：全部插值模式数学未跨作穷核；z写入顺序不作3D等价宣称。

**证据**：`th16:0x413860` bullet_vm_exec；`th16:0x415f90` bullet_beh_move_to_point；`th18:0x425c60` Bullet__run_ex；`th18:0x428710` FUN_00428710。

<a id="ex-18"></a>
### `0x40000` VEL

**参数**：`r`=<-990保留角；[-990,990)字面；>=990朝玩家+r-999；`s`=<-990保留speed，否则直接赋speed。

**进入、持续、结束**：进入立即写角/speed并重建速度向量；不设持续位。

**比较与转写**：相同（已核子集）。使用990/-990小阈值体系，不可套ACCEL百万哨兵。

**证据**：`th16:0x413860` bullet_vm_exec；`th18:0x425c60` Bullet__run_ex。

## 关键差异的独立复核

### 扩展角度哨兵与逐弹随机

TH18 helper `FUN_00425b40` `th18:0x425b40` 的实际接口使用隐式寄存器：XMM2=角参数，XMM3=偏移/随机幅度，XMM0=当前角，ECX=弹位置指针。现有decompile把若干输入输出省略，因此本轮补看Ghidra Listing。ACCEL调用点 `th18:0x425e75`，VELTIME调用点 `th18:0x426eec`（随后分别保存到+0xb1c/+0xda4）。

| 输入角 q | TH18 helper输出 |
| --- | --- |
| q<=-999990 | 保留输入当前角 |
| -999990<q<999990 | 字面q |
| 999990<=q<1999990 | 当前弹到玩家角 + m |
| 1999990<=q<2999990 | 字面q |
| 2999990<=q<3999990 | 当前弹到玩家角 + m × U |
| 3999990<=q<4999990 | 当前角 + m × U |
| q>=4999990 | 按boss0坐标减弹坐标求角 |

U来自 `Rng__randf_neg_1_to_1` `th18:0x402810`，共享对象 `th18:0x4cf288`。随机调用在 `th18:0x425bab` / `th18:0x425be0`，每次效果进入取值；持续handler `th18:0x427b60`只消费保存的向量，不逐帧重抽。既有真实ECL扫描在TH18 st05bs的Boss1_at/Boss2_at/BossCard1_at找到了3处VELTIME百万随机档，详见[2026-11-04清单](2026-11-04-ex-runtime-random.json)；本轮没有重新统计所有关卡使用率。

TH16 ACCEL/VELTIME在 `th16:0x413860` 没有这些百万随机分支，走保留/字面/朝玩家的旧解析。STEP两作都另有c=5/6取随机目标角、c=7取随机speed；TH18 STEP先走上述helper，某些c模式随后覆盖结果，所以即使最终角被覆盖，也不能据此省掉先前helper可能消耗的RNG。STEP c=7另走990阈值路径，不能套这张表。TH16旧报告对STEP >=9999990称“存档角”而当前decompile没有直接显示这一步，本报告不把该说法升级为已核事实。

boss档方向另有社区措辞风险：Listing `th18:0x425c08` 至 `th18:0x425c3b` 的减法是bossY-bulletY、bossX-bulletX，然后调用atan2包装；本报告仅据这条算式记录朝boss方向，不照抄社区“boss到弹”的反向描述。未观察boss不存在时的运行结果。

### 新增持续追踪位

发现：`th18:0x4275ea` 直接比较 `0x40000000`，命中后 `th18:0x42764a` 置同位并保存r/s/m/a。验证：tick显式派发到 `FUN_00428460` `th18:0x428460`，该函数逐tick读玩家位置，将目标角设为to_player+s、目标速度为r，然后v+=(target_v-v)*m，重新计算speed与angle，私有计时达到a才清此位。结论：TH18新增的是逐tick追踪行为；m是每步混合系数，代码没有把m再乘dt。TH16整个普通弹EX分派无此case及handler。该结论不依赖社区把它叫HOMING或序号31。

### INVULN消费者与递减时点

发现：bomb圆形消弹函数 `th16:0x416d20` / `th18:0x429370` 仅对+0x24为0的弹执行取消。碰撞函数 `th18:0x4248a0` 先调用可能致死的玩家碰撞，再在命中且计数非0时保留弹自身。因此INVULN应理解为取消免疫/弹自身存活门，不能把名字翻成“这颗弹不会致死”。TH16对应弹碰撞入口是 `th16:0x4124b0`。

发现：两作都把a写+0x24，但TH16 `th16:0x411e70` 在active效果do循环内部递减，函数尾另有一次递减；TH18 `th18:0x423e10` 只在函数尾递减。验证：对照现有两份完整函数导出，TH16内部递减在do-while返回条件前，尾部递减在离屏处理之后；TH18相同位置仅尾部一处。结论：配置结构相同，持续tick含义不能直接等同；具体次数还受active位、同tick重入和提前回收影响。本轮未用原作运行验证实际a的帧数。

### SHOOT / LASER配对与高角值

SHOOT的第二条记录a2/b2是sprite/color，c2非0可删父；第一条r/s/m/n分别为角/第二角/首速/末速，a/b/c/d分别为aim/effect_index/路/层。PC共前进2。TH18只把角 `[999990,1999990)`解释为瞄准玩家，TH16正阈值上方无同样的1999990上界；因此高字面/哨兵值不能照TH16解释。

LASER a=0为线：b/c=sprite/color，d非0删父；后记录a2/b2/c2=发射音/变换音/effect_index，r2/s2/m2=附加浮点字段/宽度/距离。a=1为无限：d低位带flags、bits8..15=effect_index、bit16=删父；后记录a2/b2/c2/d2=start/expand/duration/stop时间，r2/s2=宽度/距离。普通弹创建端的读取布局两作对应；字段的完整激光消费者未全核，尤其未把“附加浮点字段”强行命名。TH18 LASER角的1999990上界与SHOOT相同，TH16没有该上界。

### 保留的未知与非效果槽

`0x20`在两作普通弹EX分派未用；`0x10000000`作为社区LASER_DATA名没有普通弹独立动作分支，但LASER会读取相邻记录。社区ordinal32/33（ACCEL_2/NO_GRAZE_EFFECT）本轮没有在两作普通弹找到可直接绑定的新增raw type，不能凭序号构造映射。REACT消费者、STEP d字段、复杂插值模式与激光完整运行时仍明确未核。

BOUNCE旧报告把r称“最小速”，但两作已读handler是r>-990时直接赋speed，不能用max(current,r)代替。VELADD的“时限”也不可当有限duration：成功分支重置自身计时，完成分支只清1与8位；这些原生控制流应保留为转写约束，不能顺手改引擎行为。
