## 覆盖结论

**解析链路完整不等于语义转换完整。** 22 份二进制中的 798 个 sub 全部可解析，但当前 rank1、demo 模式只成功生成 13 个 sub；其中只有 st04 的 GirlD01_at／at2、GirlD02_at／at2 四个是实质攻击，其余多为空壳或等待。前轮原型主要证明单样本的执行路线，语义映射仍很窄。

以下统计只计每个失败 sub 的首个阻碍，后续可能还有其他缺口；不能把这些数字相加理解为补一条规则就能解锁同样数量的完整卡。

| 首个阻碍 | sub 数 |
|---|---:|
| 尚未实现的普通 opcode | 422 |
| 写入目标被限制为局部变量 | 121 |
| 混合类型栈运算未建模 | 89 |
| 单层环形以外的发射模式未实现 | 55 |
| 发射器编号等参数要求字面量 | 34 |

422 个普通 opcode 阻碍中，302 anmSelect 为 165、502 flagSet 为 41、300 enmCreate 为 28、625 etCountD 为 23、11 call 为 17、15 callAsync 为 9。121 个写入目标限制中可直接看到合法的负号特殊／敌人变量目标；错误信息“expected aligned source local reference”不能理解成原作损坏。89 个混合类型问题中可见合法的 float 与 int 相加，原型过于严格的栈类型检查会拒绝。

这些是当前转换器覆盖不足的证据，不是 TH18 不能转写的证据。需要按可直接映射、经确认可省略的表现操作、真实引擎缺口分开推进。ANM 某些字段会影响出生运动和碰撞，不能为了提高覆盖率批量无视。

- B：GirlD02_at、GirlD02_at2，rank2/3，四次各 240/220 帧真实 runner。
- 从原作参数独立计算锚点，不以生成注释或既有 verify 的期望作 oracle。
- runner 实际编译并运行冻结的 `.generated.ecl`；主代理核对输出源码哈希未变，并重新读取全部八份 trace 的出弹、角度和诊断计数。
- 未运行原游戏、原生 VM 对拍、训练、浏览器或全量回归。

## 训练适用性

**两组 training_readiness 均为 false。** EX2 出生回退、半速阶段、碰撞门和变换时钟未保留；发射源固定；原生随机流、弹型半径和 f32 数值语义有已声明替代。源脚本阶段本身还依赖父敌人的移动／异步生命周期。当前结果可作为受控的近似弹型实验，不应以“保真 TH18 卡”的名义收进训练池。

本轮不根据抽查扩大实现，不修改已推送转换器。下一步应先建立逐机制的实现／近似／缺失清单，提升实际攻击的语义覆盖，再让独立模型审查更复杂的成功转写。

## 会话结束交接与后续优先级

用户在 2026-10-23 要求记录局限与后续后暂时结束会话。以下为待办建议，不代表已经批准新增运行时机制、改变数值体系或启动训练。

### 先完成能力清单，避免把基础指令缺失当成引擎缺失

从已有 `inventory.json` 继续，逐类记录原生语义证据、现有引擎对应能力、转换规则、阻塞样本和验证锚点。分成三类：现有引擎可直接承接；确认不影响玩法后可省略；需要新增引擎机制。不能为了提高成功率静默忽略未知 opcode，也不能只改报错或增加 goto 就宣称完成语义支持。

优先调查普通变量／特殊变量读写、整数与浮点的原生转换规则、动态发射器参数、难度参数、普通发射模式和常用 EX。anmSelect 等高频阻碍需先查是否影响后续动画信号／出生态；调用、创建敌人、移动和 async 要结合真实攻击依赖分析，不能仅按名字换函数。

### 明确保真目标，再补确有需要的机制

- **数值**：区分允许的坐标／角度量化与不能随意改变的分支、循环次数和边界判定。原型已有 0.999999f 转整反例；采用哪种处理路线尚未确认，不能自行把核心改成浮点。
- **出生与几何**：补证 EX2 的 ANM/tick 边界、回退位移、半速阶段、碰撞门和 EX 计时，再提出最小实现；同时建立 TH18 弹型／半径映射，恢复真实发射源和父敌人移动依赖。
- **状态与时间**：当前只支持独立单 sub、固定步速。调用帧、返回时钟、async 和共享发射器、冻结／gameSpeed 都不能当成已完成；优先选实际素材需要的子集，避免直接扩成完整 ZUN VM。
- **曲线激光**：独立的几何与观测缺口，需结合原生节点、碰撞、训练观测和部署提取提出方案并确认；普通曲线弹及旋转直线激光不能替代此项。

### 扩大真实攻击覆盖后，再做复杂抽查

先使来自不同机制族的代表性完整攻击及其依赖能转换，再复用当前冻结来源、独立期望、真实 runner 的审阅方式。可从本轮已登记但拒绝的 `st05bs::BossCard2_at`（无限激光）、`st07bs::BossCard3_at/BossCard7_at`（曲线激光）、`st07bs::Boss2_at`（带参攻击）挑选；未支持前只登记缺口，不生成伪成功卡。

审查覆盖应明确报告：可解析 sub、可生成 sub、实质攻击、依赖闭合的完整阶段、已验证难度与时段。不能用空壳／等待函数或同一攻击的难度变体夸大数据扩充量。补完整循环／退出／变换切换锚点时只跑对应新增或未决行为，不机械重跑所有已有检查。

达到约定保真度后，才进入正式卡池格式与训练包装、wheel 同步、数据划分和训练实验；这些均未在本次实施。原有 TH06 卡池与流水线保持不变。

### 恢复工作时的入口

1. 读项目记忆条目与本报告，核验两个仓库当前状态；本次已推送基线是训练仓 `530dee8`、引擎仓 `bfd2062`，之后的抽查与交接文档由收尾提交保存，具体版本以 git log 为准。
2. 阅读已保留的 inventory／manifest 和两份 Luna 报告，复用原作哈希与轨迹证据；不要将两组近似范围内通过解释成训练验收。
3. 从能力清单与一个明确机制族开始。涉及新增接口、状态、模块边界或数值路线时先给方案、取舍和建议，等待确认。
