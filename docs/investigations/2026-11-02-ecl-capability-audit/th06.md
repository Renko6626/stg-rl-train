# TH06 / TH06NC ECL 能力核对

日期：2026-11-02。只读调研；本轮未运行原作、训练、导入或对拍，也未改引擎或卡池。

版本：TH06 v1.02h 的 CC0 `th06-decomp` 源码为主要行为证据；TH06NC 为 renkolab 已登记样本 MD5 `b0cc28ec904e9efce2439ad857c938b5`。我方以当前 `stg-engine` 源码 `ENGINE_VER=27` 为准，训练 `stg-rl 0.4.2` 旧 wheel 不能继承这些新源码能力。文中的“精准”均限记录写明的行为与参数域；完整攻击还须同时满足碰撞、池容量、生命周期和调度条件。

Priw8 的实抓指令/变量脚本没有 TH06 表。这里没有拿现代 ECL 名称代替红魔乡行为；基准编号来自本地 `truth/map/th06.eclm`，行为回到 CC0 和 NC 原生记录。NC 文档明确说明旧 opcode 实现集合一致，但没有逐条证明 1–135 的语义全同；本报告将这层继承证据与实际核实的 NC 差异分开。

分类：1 直接精准，2 现有组合精准，3 现有组合近似，4 经取舍可不做，5 缺少且关键；`null` 为资料不足。浮点/定点及BAM精度差异不降级。类别4的 existing 是已有训练口径，proposed 是本轮建议待用户确认；类别5同样不授权实施。

## 结论与最值得先处理的点

1. 激光九条、ex12、ex14已有接口；尤其沿激光铺弹不能继续按旧的“无几何读口”判缺。创建/读几何/改角度均回指当前源码，跨sub传句柄，读相位5推进前的实际几何；12从敌中心64px处发，14从激光near起每48px发，且14要回写I3活激光数。
2. ex7并不扫描全场激光。CC0源码是局部2×3×8几何循环，NC的几何接口可表达48次创建或发弹；但1024操作单帧预算尚无已核实配方，一般ex7保留null。当前配置仍skip的s6_b2/b3不能仅据旧注释认定需要全场遍历机制。TH06原版额外预警判定窗则仍近似；两版本分行。
3. 真正跨弹关联的ex15以及640池/池序机制值得列为5。ex8/9/11可预挂弹任务近似，但256总任务不能兜住640弹、广播相位和原池序；不能因预挂“看起来能算”便标2。ex17–19没有已查明的行为证据，保留null。
4. 旧mapping的“translate”不是精准等级：出生当帧晚1帧、move_bounds夹终点、动态EX角量化、时停压平及14/52颗改向上限、省略血量反馈等都是真实语义差异；其中血量反馈属于现有卡的训练策略，读取原语$self_hp判1、ex16公式在提供等价HP/计时条件下判2。本轮没有把这些包装成纯浮点差异。现有30缓动、共享敌变量和插值槽已查到源码，不把过时缺口继续保留。
5. 自动射击可以在同一个敌主调度任务精准组合：同帧块指令更新props之后tick计时，首发n-1（随机初相可为0），计时跨call/ret持久。伴生任务的shooter是任务私有4槽，不会自动共享敌props；delayed的k=0还会晚一帧。TH06 call则保存整个上下文，和我方裸call共享locals不同，必须显式保留/恢复寄存器与时间。

## 自动射击停火门的来源冲突

TH06 CC0的`EclManager.cpp:355–421`在67–75更新参数后以`shootingDisabled==0`控制立即发射；`shoot_now`在`:447`无此门，帧末自动射击`:980–989`只查life和shootInterval，亦未查该flag。因此本轮TH06组合按源码分别处理。已有`mapping.md:650`却说它同时影响自动射击，属于待修订的历史转换规约；本轮不改该文件或卡。NC跳表实现集合相同不足以证明本细节相同，尚未重读NC对应分支，不能直接推广。两份证据均保留，后续NC核查应优先核这处会改变弹量的门。
