# 资料结构与版本边界

日期：2026-11-02。本文记录这轮调研如何取得资料、解释表格及访问原生证据。它不宣称所有作品已完成逐指令行为考据。

## Priw8 网站

入口为[指令表（TH16）](https://priw8.github.io/#b=modding/&p=ins&table=16)和[变量表（TH16）](https://priw8.github.io/#b=modding/&p=vars&table=16)。网站是动态页面，直接抓首页只得到 HTML 外壳；这轮读取了 `content/modding/ins.md`、`vars.md` 及实际 JavaScript 数据，没有操作浏览器。

资料分为三层：

| 层 | 文件 | 解释方式 |
|---|---|---|
| 行为与参数 | `js/ecl/ins.js`、`vars.js` | 各版本只保存部分增量；不能把单个版本对象当完整表 |
| 继承与显示 | `js/ecl/main.js` | 使用网站自己的 `getOpcodeNoCheck` 展开继承；`number=-1` 是明确删除标记，`documented=false` 代表资料不足 |
| 指令与变量名称 | `eclmap/eclmap/th*.eclm` | 名称独立加载；有名字不保证有行为说明，也不证明原作存在非空实现 |

网站指令下拉提供 TH08、TH13、TH14、TH14.3、TH15、TH16、TH16.5、TH17、TH18、TH18.5。没有 TH06；TH06/NC 的依据改用本地原生逆向与 CC0 源码。TH08 与现代架构的编号不能直接对照。

`INS_17`、`INS_18` 是空对象，但会继承此前描述；这表示网站没有在这些对象里记录新差异，不能证明作品行为与 TH16 相同。例如 TH18 的 `1000..1020` 在本地命名表中有名，网站却没有足够的本作行为描述。命名表与描述表必须并读。

网站变量 UI 仍注释了 TH18 选项；JavaScript 有 `VAR_18`，但不能据此宣称 UI 或数据完整支持本作。TH18.5 缺少相应变量检索分支，目录 CSV 中的变量计数 0 表示这套提取入口未提供，**不是游戏没有变量**。TH14.3 的本地独立命名文件缺失，CSV 的命名计数 0 同样不等于原作没有指令。

当前线上 TH16/TH18 命名表已下载并与本地 vendor 表逐项对比，296/315 条命名项一致。旧 TH16 文档中的 298 等数量是历史口径，不作本轮分母。

本轮 TH16 逐项核对另补原生存在而上述两表均未收的 `41`，共 **300 个候选编号**。其中包含原作 no-op 和待核实项，仍不能当 300 个有效能力。按任务边界拆为 VM/敌人等 243 个、弹幕/激光 57 个。

现代版本的目录级变化已经提取，本轮深入判定以 TH16 为主，TH18 只附有本作证据的行为。TH13–15、TH16.5、TH17、TH18.5 的所有条目不因此自动获得 TH16 的分类。

## 本地原生证据

`renkolab/local/th16.v1.00a/state/data/functions.jsonl` 已含按地址检索的反编译与调用关系。核心例子：

| TH16 v1.00a 地址 | 名称 | 用途 |
|---|---|---|
| `0x472030` | `EclRunContext__ecl_run` | 系统指令、时间门控、栈和调用 |
| `0x41dcb0` | `EnemyData__ecl_run_over_300` | 高位指令分派、发射器写入和激光创建 |
| `0x413860` | `bullet_vm_exec` | 弹运动 EX 执行 |
| `0x414da0` | `bullet_spawn_wrapper` | 发射描述符消费与弹生成 |
| `0x402ff0` / `0x403110` | `motion_update_mode` / `motion_update_mode_full` | 运动积分与插值消费 |

查询方式是逐行解析 JSON，按 `addr` 或 `name` 选择，再查看 `decompiled`、`comments`、`callers/callees`。反编译导出是已有档案，本轮没有重新生成、打开或修改 Ghidra 工程，也没有全面审计导出与当前 exe 的生成关系。对可直接读 PE 的分派表，按具体编号与指令边界交叉核对，避免把一个 case 误配到另一个 opcode。

可重放命名脚本提供以后深入时的入口；本轮不执行。命名脚本的社区来源注释和“已确认”注释必须区分，函数名字本身不能支持行为等价结论。

## 复核输入与保存边界

[sources.json](sources.json) 保存下载 URL、SHA256、仓库 HEAD/分支及实际阅读输入的哈希。输入包含当前工作区内容，不能只用 HEAD 还原。该文件只保存元数据，没有游戏字节、第三方整段描述或反编译原文。

原始网站脚本位于 `/tmp/sunyunbo/priw8-ecl-*-20261102.js`；展开目录、原始清单和临时材料位于已忽略的 `transcribe/work/ecl-audit-20261102/`。提取脚本为 `/tmp/sunyunbo/ecl-audit-inventory-20261102.cjs`，按网站函数展开版本继承；资料元数据脚本为 `/tmp/sunyunbo/ecl-audit-source-report-20261102.py`。本轮记录这些入口供复核，不新增长期运行服务或依赖。

引用优先顺序：原作指定版本的原生行为证据 → 本作既有逆向文档 → 社区单源说明；我方能力另外回指当前源码。静态代码核对、历史动态验证和本轮实际运行必须分别说明。
