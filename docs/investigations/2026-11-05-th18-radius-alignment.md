## 需要分开的三层一致性

1. 源type/color对应目标的形/色和出生基础半径；缺型不能默默换成小弹。
2. 运行时半径：原HITBOX覆盖、SIZE缩放、SETSPRITE重新读默认半径等，不能只核出生表。
3. 最终碰撞：还涉及玩家半径、公式、判定门和时间相位。现有[原生几何审计](../practice-cards/2026-10-22-th18-geometry-audit.md)已确认，TH18普通圆弹为 `d² < br²+pr²`，当前目标为 `d² <= (br+pr)²`。即便br/pr数值一致，危险区仍不同。

例如br=4、pr=3，原作临界距离为5，目标为7；临界等号处理也不同。因此“把目标半径改对”只完成前两层的一部分。源f32转Q16.16用最近可表示值比较，正常取整不等于主动改变物理尺寸。

## 现有接口能做什么

`fire`、`batch`和`sh_fire`按所选appearance配置生成radius；现有ECL没有独立子弹半径写口。`set_hitbox`是敌人体碰写口，不能用来改弹。xform `set_sprite`只改sprite，不刷新出生radius。底层world创建已支持显式radius，静态WorldTables也能存小数；缺的是转写可用的内容/脚本路径及换型/动态半径语义。

直接改全局12行不能完整解决：源米弹2.4与旋转米弹3.2映射同一目标行；改成其中一个会错另一个，并会改变TH06/现有卡的物理。

## 调查时比较的方案

| 方案 | 能解决什么 | 取舍 |
|---|---|---|
| 修改通用12形默认半径 | 部分常用弹出生半径 | 影响旧卡，同形多半径与缺型仍未解决，不推荐 |
| 给转写保留独立弹型/半径配置和写口 | 分开图形与物理半径，支持源type、换型与动态覆盖 | 需明确内容表/脚本接口、默认行为和轮转/缩放语义；推荐作为半径对齐方向 |
| 再提供TH18碰撞规则配置 | 用原生玩家参数/判别式核最终危险区 | 涉及物理规则选择，须与半径层分开确认；不默认改变已有卡 |

调查时推荐保留现有内容默认，以原作48型/各色及动态变化为转写依据；缺失形状明确列出，不能把半径近似包装成已对齐。用户随后选择按作品区分弹型/半径并共用外观，碰撞算法选择后置；本轮不实施具体表/写口，也不将候选方案写成现有API。

## TH06与TH06NC的历史差异复核

用户随后要求确认偏差是否早已存在。结论：旧转写一直有尺寸近似，但不同游戏的原生判定不能混写。

| 版本 | 普通弹命中几何（省略无敌等状态门） | 玩家默认尺寸 |
|---|---|---|
| 经典TH06 | 玩家轴对齐盒与弹轴对齐盒重叠；弹半边长为grazeSize/2 | 半宽/半高1.25 |
| TH06NC（现有TH06流水线原文） | d² < (min(grazeSize.x,grazeSize.y)/2 + pr)² | 圆半径1.25 |
| TH18普通圆弹 | d² < br² + pr² | 圆半径3，实际可被卡牌等改写 |
| 当前目标引擎 | d² <= (br + pr)² | 默认圆半径2.5，训练实际值可另配置 |

经典TH06直接复读本机CC0 `Player.cpp` 的初始化/CalcKillBoxCollision及 `BulletManager.cpp` 的尺寸初始化与出生分支。NC复用 `renkolab/local/th06nc/state/data/functions.jsonl` 的既有Ghidra导出：`th06nc:0x14006a980` 明确先把两轴尺寸取小再除二，与 `player+0x774c` 相加后平方；`th06nc:0x140010870` 的普通弹调用传模式1；`th06nc:0x140068160` 写该玩家字段为f32的1.25。对应既有结论见renkolab `engine/player/th06nc/01-main-loop-and-collision.md` §2.7。本轮未重新枚举NC十种弹型模板、未运行游戏。

历史提交 `8e4e22d`（2026-09-16）的TH06 mapping已经列出大玉8→5、气泡16→5等尺寸差异，并接受出生特效省略；`51fbdba`（2026-09-17）补明出生减速/无判定的后果。该历史表以经典TH06尺寸为基准，不能据此声称本轮重新验证了NC全表。当前mapping的“方框”说明原本未区分实际原文NC，本轮已纠正版本说明。旧卡半径映射偏差与玩家默认尺寸差异因此早已存在；TH18相对于NC还增加了平方和/半径相加的公式差异。

用户本轮另明确接受为性能省略出生减速和出生无判定窗口，规则见[统一口径](../../transcribe/th18/transcription-policy.md#已批准省略出生减速和无判定窗口)。这不授权基础半径偏差；随后确认的按作品区分半径/外观共用方向见本文开头，具体引擎修改尚未实施。
