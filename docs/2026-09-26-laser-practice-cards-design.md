# 激光练习卡：在原作弹幕上叠加激光（设计稿）

2026-09-26 起草，**未实施**。先跑 T1（激光进观测、只用原作 11 张激光卡）拿基线，按 T1 的留出评测结果决定要不要做。

## 1. 为什么要做

T1 的激光数据（`configs/exp-t1-laser.toml`，rank 2 训练起点 156 个）：

| 项 | 数值 |
|---|---|
| 激光卡起点 | 11 / 156（7.1%），按时长加权占训练帧 10% |
| 激光卡里场上真有激光的帧 | 平均 63%（各卡 22–94%） |
| 真正看到激光的帧 | 约 6.3%，T1 预算 9.2 亿帧里约 5800 万帧 |
| 激光相关参数 | 约 6.7 万（全模型 31.7 万 → 38.3 万） |

**帧数不是瓶颈**，5800 万帧对 6.7 万参数绰绰有余；缺的是**花样**。一条激光的 token 有八个左右的连续维度：原点、角度（含自机狙）、
长度、宽度、角速度、飞行速度、预警剩余帧数，再加上同时存在的条数。11 张卡拆开大约只有 15–20 种形态（扫射、自机狙、
飞行短棒、静止栅栏几类），模型很可能背下「这张卡第几秒往哪躲」，而不是学会看激光。经验判断要 30–50 种有区别的形态
（不是推导出来的数），T1 的留出评测会告诉我们差多少。

## 2. 前置：旋转 / 移动激光在观测里看不出在动（先修引擎）

11 张激光卡在引擎里报的角速度 **全是 0**，但ムーンライトレイ（`th06_s1_mb2`）和レーヴァテイン（`th06_s7_b4`）明明在扫：
它们用脚本每帧 `lz_rotate` / `lz_origin` 转和移（`th06_s1_mb2/main.ecl:76`），不走引擎的 `lz_omega`。
观测的 `omega` 列只反映 `lz_omega`，所以这类激光在单帧观测里就是一根**静止的线**，模型看不出往哪边扫、扫多快。

这对练习卡是硬前置：练习卡如果用 `lz_omega`，模型会学着依赖 `omega` 列；到了原作卡上这一列是 0，学到的东西用不上。

**改法**（stg-engine，符合「改引擎、不在训练侧绕」）：激光行的 `omega` / `vx` / `vy` 改成**本帧实际**转过的角度与原点位移，
不论来源是 `lz_omega`、`lz_rotate`、`lz_origin` 还是挂靠——与敌人行 `vx/vy` 取「本帧实际位移」同一口径。
瞬移（第一次挂靠、`lz_origin` 跳变）要不要计入照敌人的规矩定。改完升 stg_rl 版本，按规矩**本机与 Magnus 的 wheel 一起换**，
并在新引擎上重跑对照。部署侧 DLL 的 `omega` 也要按「帧间实际差分」填。

## 3. 做法：程序叠加为主，大模型写模板

**不让大模型逐张卡重写。** 逐张重写成本高、容易出错，也不好保证公平。改成：

1. **激光模板库**（一次写好、人审）：每个模板是一个独立的 `async sub`，挂进 boss 的段任务里跑，**不改原卡的代码、
   不需要读懂原卡**。参数在卡里用 `rand()` 每局重抽，同一张卡每局都不一样，需要的卡数因此少很多。
2. **叠加器**（程序）：底子卡 × 1–2 个模板 → 一张新卡。把模板代码拼进 `main.ecl`，在 boss 的段起点 `spawn` 模板任务，
   写 meta。批量、确定、编得过。
3. **大模型的用处**：(a) 写 / 扩模板库；(b) 第二阶段的「融合型」变异——要读懂原卡的节奏，让激光和发弹对齐，
   或弹沿激光发出（レーヴァテイン那种挂弹），纯叠加做不出来。走现有 dsh / claude-worker 流水线。

### 3.1 模板（第一批 6 个）

| 模板 | 形态 | 原作参照 | 每局随机的量 |
|---|---|---|---|
| `fence` | 预警后生效的静止栅栏：几根竖线 / 斜线把场地切成通道 | 第 4 关第 15 / 16 波 | 根数、间距、倾角、生效时长 |
| `aimed` | 单条或 3–5 条扇形，预警时瞄准自机 | 帕秋莉非符 1 / 2 | 条数、扇角、预警时长、偏角 |
| `sweep` | 从 boss 或场边转过去 | ムーンライトレイ | 转向、转速、起止角、支点位置 |
| `bar` | 短激光沿射线飞出（`lz_speed`） | 琪露诺非符 2、水符 | 棒长、速度、方向（狙 / 扇 / 随机） |
| `rail` | 原点挂在一个隐形、无敌、会走的假敌人上平移（`lz_anchor`） | レーヴァテイン | 路径、速度、激光朝向 |
| `pinch` | 两条平行或成 V 的激光慢慢收拢，留一条缝 | — | 缝宽、收拢速度、位置 |

转动一律写成**脚本每帧 `lz_rotate`** 和 `lz_omega` 各半（第 2 节修好之后两者在观测里一样；修好之前别用 `lz_omega`，
免得和原作卡分布不一致）。

### 3.2 参数范围（以原作实测为界，不许更快、更宽、更密）

实测（11 张原作激光卡，rank 2 钳位，每 60 帧采一次激光表）：

- 判定宽度 3–16 px（`width`，TH06 已按「原作画面 = 判定 × 2」折半）；
- 预警 20–120 帧；生效 50–800 帧（飞行短棒 9999）；收缩 10–30 帧；
- 飞行速度 4 px/帧；扫射转速以ムーンライトレイ的 86 BAM/帧为上限量级。

练习卡取这个范围内的值；同屏条数不超过原作卡的最大值。

### 3.3 卡的命名与元数据

- 目录：`mut_<底子卡>_<模板>[_<模板>]_<k>`，例：`mut_th06_s3_b2_sweep_1`。
- `meta.toml`：`source = "mutation"`，新增 `base = "<底子卡>"`、`mutation = ["sweep", …]`，`tags` 在底子的基础上加 `laser`，
  `origin` 写一句「<底子> + <模板>」。`ranks` / `time_limit` 跟底子。
- 叠了激光明显变难：底子的弹量按需降一档（模板里读 `global(GVAR_RANK)` 自己也按档缩放）。

## 4. 校验：筛掉躲不了的卡

1. **复用 `stgtranscribe.validate`**：编译、零 fault、弹峰值 ≤ 1024、段结束事件、开局 120 帧随机游走死亡率。
2. **激光专项（新写，静态 + harness）**：
   - 开局 120 帧内没有生效态激光；
   - 进入下半屏的激光预警 ≥ 20 帧；
   - 扫射在下半屏的切向速度（转速 × 到支点的距离）不超过自机高速 4.5 px/帧。
3. **可躲性检查（新写）**：用 harness 逐帧导出弹（圆）与生效态激光（旋转矩形），在下半屏 4 px 网格上，从开局可站的格子出发，
   按自机速度做「随时间推进的可达区域」搜索；从某帧起可达集为空 ⇒ 淘汰。自机狙随自机位置变，这里按「自机站着不动」近似，
   只用来筛掉明显不公平的卡，不当作能躲的证明。
4. **人看**：抽样出预览 GIF（`python -m stgtranscribe.preview <卡> --gif`，已支持激光），比照转写流水线的抽检。
5. **开训后**：课程学习的每起点死亡率里，接近 100% 的卡剔除。

## 5. 评测与实验

- **只在原作激光卡上判好坏。** 练习卡只进训练，不进评测。T1 起留出 3 张原作激光卡（`eval/splits-laser.toml`：
  `th06_s4_w16`、`th06_s4_b12`、`th06_s1_b3`），**这 3 张及其所在的同源卡不拿来做底子**。
- 训练里激光帧的比例控制在 15–20%，保证原作激光卡不被练习卡淹没（练习卡起点整体降权）。
- **T2 = T1 + 练习卡**，同引擎同评测划分，对比留出激光卡上的撑过率 / 激光致死；非激光卡不许退步（噪声约 1–2.4pp）。
  若练习卡只让模型在练习卡上变好、留出原作卡没进步 ⇒ 分布偏了，回头调模板和参数范围。
- 可选：先做「数据量曲线」确认需求——T1 的 8 张训练激光卡里只用 4 张再跑一条，看留出卡的差距随卡数怎么变。

## 6. 风险

| 风险 | 对策 |
|---|---|
| 生成的激光与原作风格不同（分布偏移） | 参数以原作实测为界；以留出原作卡为唯一判据 |
| 激光 + 弹幕叠出死局 | 第 4 节的专项检查与可躲性检查；训练中按死亡率剔除 |
| 挂弹这类组合纯叠加做不出来 | 第二阶段融合型变异 |
| 模板写成固定节奏被背板 | 所有参数用 `rand()` 每局重抽；每个模板至少三个随机维度 |

## 7. 顺序

1. 引擎：激光行 `omega` / `vx` / `vy` 改为本帧实际值（第 2 节），升 stg_rl，两边换 wheel，重跑 T1 对照。
2. 模板库 6 个 + 叠加器 + 专项检查 + 可躲性检查。
3. 产第一批约 60 张，跑 T2。
4. 视 T2 结果决定是否做融合型变异、扩模板。
