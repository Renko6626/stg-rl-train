## 审阅时的结构

依据 `src/stgtrain/featurize/danger_topk_v7.py`、`src/stgtrain/models/set_attn_v1.py`、`src/stgtrain/models/set_attn_v2.py` 和 T1–T4 配置：

- 激光候选排除收缩态，按自机中心到当前判定盒距离取最近 16 条。
- 每条 13 维：相对原点、方向 cos/sin、start/end、半宽、生长速度、角速度、原点速度、预警标记、封顶 120 帧的倒计时。
- 激光编码器 MLP `13 → 64 → 64`，mean / max / 4 头 ctx 注意力汇总为 192 维。
- 与弹、敌、密度图、ctx 合并为 704 维，主干 `704 → 256 → 256`，输出动作和价值。
- T1–T4 使用 `laser_sa_layers=0`、`laser_local=false`、`action_query=false`；弹分支使用 `sa_layers=1`。
- 激光编码器本身 17,536 参数，连同主干加宽较 v1 增加 66,688 参数。以上是当日代码/配置事实，后续工作需重新核验。

## 已复现的边界问题

`danger_topk_v7.py` 的 `torch.topk` 没有定义等距离候选的并列规则。构造 20 条相同几何、不同预警倒计时的激光，K=16，反转原始表行顺序后，入选集合不同。源码所述「部署填表顺序不同也选出同一批」在等距离且发生截断时不成立。

复现使用 `tests/test_featurize_v7.py` 的 `laser` / `with_lasers` / `feats` 辅助函数：激光原点 `(0,0)`、方向 90°、半宽 8，预警倒计时依次 1–20 帧，自机 `(0,300)`；比较原表与反转表选中 token 的第 12 列。原表入选倒计时为 `1–5,10–20`，反转后为 `1–4,9–20`（本地 CPU 观察；具体并列结果不应视为跨设备保证）。

后续优先明确并列选取规则，并补充等距离、候选数超过 K 的验证；仅在已选 token 上测试模型排列不变性不能覆盖这个问题。

## 结构风险与候选对照

- 当前没有池化前的激光间自注意力；激光与子弹也分别汇总后才融合。通道、交叉封锁、出口被子弹堵住等组合关系依赖压缩后的主干学习。这是表达能力风险，尚未证明是训练效果差的根因。
- Top-K 只看当前几何距离，不看倒计时和运动量；超过 16 条候选时，附近长预警激光可能挤掉稍远但即将扫来的生效激光。候选不超过 K 时不受这一截断影响；没有测量实际训练中的发生率。
- `laser_local=false` 保留了几何原始信息，但 MLP 需学习相对坐标与方向的乘积关系；这是学习难度问题，不是几何信息缺失。
- 后续可单独对照 `laser_sa_layers=1`；`laser_local=true` 作为另一独立候选，不同时改多个变量。这些是审阅建议，不是用户已选定的实验方案。
- 继续遵守「少构造、改真实机制」约定；若方案引入构造的几何答案或 reward 塑形，先说明理由并征求用户同意。
