# 实验登记簿

每次上机训练在这里登记一条：**为什么跑、和谁比、改了什么、结果、结论、下一步**。
按时间顺序追加，旧条目只补结果、不改结论（结论错了就在新条目里更正并链回来）。

## 约定

- **命名**：`P<n>` 探测 / 冒烟性质的 run，`A`、`B`、`C`… 正式实验，按立项顺序取字母；取消的实验也留一行。
- **配置**：`configs/exp-<字母>-<短名>.toml`，只写和父实验不同的键，文件头注释写父实验与改动。
- **上机**：`bash scripts/run-exp.sh configs/exp-<字母>-<短名>.toml exp-<字母>`（自动选线程、配置副本放 `runs/`、终端日志 `runs/<名>.console.log`）。
- **一次只改一个变量**。要同时改两处，拆成两个实验或写明理由。
- **结果**：run 目录与 tar.gz 在 `runs/`（gitignore，不入库），这里记路径与关键数字。主判据是
  **评测集贪心指标**（`eval/<更新数>.json` 的 `overall`），训练时 `ep/*` 是采样策略、只作参考。
- **对比图**：`uv run --frozen python -m stgtrain.plots runs/<甲> runs/<乙> --out runs/cmp-<甲乙>`（横轴 env_steps = 游戏帧）。
- **噪声地板（2026-09-20 实测，见「更正：J 的代价是噪声」）**：同一条 run 内相邻评测点的撑过率自己就摆 **±3pp**，
  320 局的标准误约 1.5pp，`best.pt` 还是 14 次评测里取最大（选择偏差）。所以 **两条 run 的 best 对 best 差 ≤3pp 不算结论**。
  比撑过率要用**最后 4 次评测的均值**（每档 1280 局，名义标准误约 0.8pp）；`best.pt` 只用来挑部署模型。
  抖动类指标（方向/s、连击占比）的效应是几十个百分点，不受这条限制。
- **补测**：`uv run --frozen python -m stgtrain.eval_ckpt runs/<run>/checkpoints/best.pt [--all-cards --ranks 2,3]`。
  注意 CPU 补测和训练时的 GPU 评测同种子但浮点不同，撑过率会差 ±1–2 个百分点。
- **看操作**：`uv run --frozen python -m stgtrain.replay_gif runs/<run>/checkpoints/best.pt [--cards …] [--episodes 0,1]`
  → `runs/<run>/replay/<卡>_r<档>_e<局>.gif`，与评测同一局；黄圈 = 指令点、底部色带 = 最近 64 步方向键。

## 阶段性总结（2026-09-20，A–J 十条跑完）

### 现在最好的配置

`configs/exp-j-quickchange.toml`（= `exp-i2-stack.toml` + `quick_change`；09-20 更正后 **J 转默认**，它在活命上没有可测的代价）：

- 特征化 `danger_topk_v3` = 危险度 top-K + 密度图 + **上一步动作**（E）+ **敌人速度**（G0 并入）
- **起点难度采样**（课程：死亡率 EMA 加权 + 两级钳位，H）
- **意图混合** `mixed_v1`：跟点 60 / 锚点 30 / 自由 10（I）
- reward：`death 10 · follow_shaping 1 · hold 0.01 · key_press −0.003`（J 再加 `quick_change −0.01`）
- 4096 env × 64 步 × 3500 轮 = 9.18 亿帧，单跑约 3h40（RTX 4090 + EPYC 7702P，threads 32）

### 三条主线各自走到哪

**① 活命**：A 0.938（45 卡池 / 9 卡评测）→ 卡池扩到 84 张后跌到 G0 0.912 → 课程采样补回 H 0.950 →
I2 在新尺子上 **r2 0.947 / r3 0.909**。**训练分布内已接近这套卡池的上界**，继续投入主要买 r3（未见难度）。

**② 抖动（拟人）——收益最大的一条**：方向变化 A 26.5/s → F 7.54 → I 5.99 → **J 3.55**
（平均每 17 帧 = 0.28 s 换一次方向，进入人类区间）；连击占比（≤2 帧回抽）F 43.1% → **J 21.9%**。
三级火箭：**E** 让模型看得见上一步动作 → **F** 把无差别按键惩罚加到 −0.003 → **J** 只罚 ≤3 帧的回抽。

**③ 听指挥的鲁棒性**：G0 三档极差 **18.6pp**（锚点 0.963 / 跟点 0.919 / 自由 0.777）
→ I **0.9pp**（0.934 / 0.934 / 0.925）。部署时上层指挥稀疏或沉默的那些时段不再是短板。

### 已经定下来的（别再重开）

| 结论 | 出处 | 一句话理由 |
|---|---|---|
| `frame_skip = 1` | C | 2 帧一判只是把频率封顶，**按每次决策算比 1 帧还爱换方向**，还砍掉一半反应精度 |

### 还没解决的

1. **曲线到 u3500 仍未走平**（I2 的 r3 一路爬到 0.909），轮数还不够；但 r2 已在 0.92–0.95 震荡。
   ⚠ **09-20 更正：「轮数不够」这个推断被 LR 退火混淆了，不成立** —— 见「更正：J 的代价是噪声」第二节。
2. **卡池六成已被学会**（74 个起点死亡率中位 0.030、45 个低于 5%），需要新的难度来源 —— rank 3 进训练最直接。
3. **评测集没有 5–6 关**，而最难的三个训练起点全在第 5 关 —— 在优化一个没有度量的方向。
4. **神穿没治**：贴弹 `<12px` 占比从 F 的 21.6% 一路涨到 I2 的 29.1%，J 只降到 26.3%。
   J 治抖不治贴，对症的是 backlog 里的「判定点随机增大」。
   **09-20 更新：病根找到了 —— 活命建立在精确到帧的操作上**（执行层最短保持 3 帧，r3 撑过 0.85 → 0.33）。
   惩罚改得了习惯、去不掉能力；对症的是把人手的限制写进环境（N1 / N2），优先级排到 L / M 前面。
5. **分档统计（`ep/{follow,anchor,free}/*`）在 I 那轮是错位的**（已修），修复后还没有一轮真正用上。
6. **近一半的死亡发生在贴边处，成因是躲弹时被一路顶到墙上**（09-20 诊断，见「诊断记录：死亡是怎么发生的」）。
   贴边只占 1.8% 的时间，每帧死亡风险却是平时的 47 倍；特征里几乎没有「墙」。这是目前已知的最大单一死因。

## C frame_skip = 2（2026-09-17）

- **问题**：每 2 帧决策一次，能否降抖动、加速训练、不掉能力。
- **配置**：`configs/exp-c-fs2.toml`：`frame_skip 2`、1000 次更新（同 5.24 亿帧预算）、gamma 0.995 → 0.990、hold 0.01 → 0.02（让「按秒」的视野与跟点收入和 A 一致）。代码 `c14f9e4`。

## D 按键惩罚（2026-09-17）

- **问题**：给按键一个很小的代价，能否让策略停止无意义的抖动，同时不伤活命与跟点。

- **问题**：训练里模型永远被一个每 120–300 帧换位置的目标圈拉着跑。部署时上层指挥没这么密，
  「给个大致位置、别催你动」才是常态。

  锁自机等于抽掉位置先验，模型会自己漂到边上送死。
- **做法**：`intent.mixed_v1`，每局开局抽一档、整局不变：`follow` 60%（现状）/ `anchor` 30%

- **测量口径**：新增 `[eval].intent`，**把评测意图钉死成规范的跟点档**，训练意图换了尺子也不跟着换；

- **配置**：`configs/exp-i-freemix.toml` = G0 + `[intent].name = "mixed_v1"`。
  **判据**：锚点 / 自由两档撑过相对 G0 提升多少，且**跟点档不退化**——不能为了自由躲弹把听指挥的能力弄丢。

## J 只罚回抽（2026-09-19 立项，与 I2 并行）

- **问题**：`key_press` 是无差别惩罚，压水平不挑形状；D→E→F 一路加码边际在变差，还会把有用的移动一起压掉。
  实测四成以上的变向发生在上一次变向后 **≤2 帧**（60Hz 下 ≤33ms）——那不是反应，是振荡。
- **做法**：新 reward 项 `quick_change`，只在「上一个方向保持 ≤ `reward.quick_frames` 步就又换」时扣分，
  阈值 **3 帧（50ms）**；阈值之外一分不扣，所以不压制正常走位，只掐振荡。
  `dir_hold`（距上次变向多少步）由 `envwrap` 统一算一份，reward 与逐局统计共用，避免两处算岔。
- **系数 −0.01 的量级**：I 的方向 5.99/s、连击约四成 ⇒ 约 2.5–3.5 次/s 被罚，合计 −0.03/s，
  与 `key_press` 的 −0.05/s 同量级（hold 的收入是 +0.6/s）。没动静就按 F 的经验 ×3。
- **指标**：`quick_frac`（≤2 帧，与历史同口径）与新增 `quick3_frac` / `quick3_per_s`。
  **指标阈值固定不跟 reward 参数走**——否则换个惩罚参数，历史数字就全废了。
- **为什么不是 `frame_skip = 2`**（用户 2026-09-19 提议）：实验 C 做过，撑过 0.872 vs A 0.938，
  而且**按每次决策算它比 A 还爱换方向**（占上限 45% vs 40%）——frame_skip 只是把频率封顶，
  没让策略变安静，同时把反应精度全局砍半。要结构性封顶该用 sticky actions（见下面 backlog）。

## 更正：J 的代价是噪声；「曲线未走平」被 LR 退火混淆（2026-09-20）

更正的是「I2 / J 结果」的 ②（撑过代价 −1.9 / −2.5pp）与 ④（3500 轮还是不够），以及总表 J 行、阶段性总结里的同一说法。
③ 当时已经发现「代价按卡型拆不出结构」，这里把话说完：**不是拆不出结构，是代价本身就不存在**。

### 一、best 对 best 的 2–3pp 差不是信号

②的数字是拿两条 run 各自的 `best.pt` 比出来的。但同一条 run 内，相邻评测点之间什么都没改，撑过率自己就这么摆：

```
I2 overall：… 0.877 → 0.856 → 0.903 → 0.870 → 0.881 → 0.912 → 0.928
J  overall：… 0.842 → 0.873 → 0.856 → 0.908 → 0.884 → 0.902 → 0.906
```

相邻点 ±3pp 是常态（I2 u2500→u2750 一步掉 3.3pp，J u2750→u3000 掉 2.4pp）。三层噪声叠在一起：
① 每档 320 局，标准误约 1.5pp；② `best.pt` 是 14 次评测取最大，两条 run 各自抽中了多少运气不一样；
③ 全部实验都是单种子。**两条 run 的 best 差 ≤3pp，落在同一条 run 自己的摆幅之内。**

换成最后 4 次评测（u2750 / 3000 / 3250 / 3500）取均值，每档 1280 局：

| | r2 撑过 | r3 撑过 | 跟点 (r2) | 方向/s (r2 / r3) | 连击≤2 (r2 / r3) | <12px (r2 / r3) |
|---|---|---|---|---|---|---|
| I2 | 0.926 | 0.870 | 0.792 | 5.79 / 6.72 | 40.0% / 44.3% | 24.2% / 32.3% |
| J | 0.924 | **0.876** | 0.774 | **3.13 / 3.66** | **18.9% / 23.7%** | 22.4% / 30.1% |

**撑过 r2 −0.2pp、r3 +0.6pp —— J 在活命上没有可测的代价。** 抖动减半、贴弹略降是真的（效应几十个百分点，远超噪声）；
唯一站得住的代价是跟点率 −1.8pp。口径注意：4 个点共用评测种子、相邻 checkpoint 也相关，
所以 0.8pp 的名义标准误偏乐观；但两条 run 吃的是同一套偏差，互比公平。

**结论**：① **J 转默认**（`quick_change = -0.01`）；② K（×3）的立项理由要改 —— 不是「再花几个点买抖动」，
而是「J 还没碰到代价开始出现的那个点，弹性未知」；③ **今后比撑过率一律用末 4 次均值**（已写进「约定」）。

**回头看哪些旧结论受影响**：凡是靠 ≤3pp 的撑过差立住的都要打折 ——
D 的 −1.8pp、E 的 +1.1pp、F 的 +0.7pp（当时就标了「噪声内」，没问题）；I 的 +2.2pp（当时也标了）。
**不受影响的**：H 的 +3.8pp（分卡增益集中在难卡、且曲线形状不同：G0 平台震荡 vs H 单调爬升）、
C 的 −6.6pp、I 的自由档 +14.8pp、所有抖动类结论。

### 二、「u3500 仍未走平 ⇒ 轮数不够」不成立

`anneal_lr = true`：LR 从 3e-4 **线性退到 0**（`ppo.py:208`，`frac = 1 − (iter−1)/total`）。
所以**不管 `total_updates` 设多少，最后一段都会因为 LR 变小、策略变稳而上爬** —— 末段在涨不是「还没学完」的证据。

直接证据：同是 u2000，H（LR 已退到 0）r2 = 0.950，I2（LR 还剩 43%）r2 = 0.916；I2 跑完 3500 轮 r2 = 0.947，与 H 持平。
**3500 轮在 r2 上没有多买到任何东西。** r3 比 H 高的那约 5pp 分不清是混合意图还是加长带来的
（I2 同时改了这两样，H 又没有 r3 的训练期曲线）。⇒ **单纯加长不值得立项**；真想测长度，要同配置只改 `total_updates` 跑一对。

## 诊断记录：死亡是怎么发生的（2026-09-20）

起因是一轮关于模型结构的讨论（三个 encoder 要不要合成一个大的、密度图要不要加一张自机周围的细图、
完全无记忆好不好）。先量再动：**J 的 best.pt（u2750）× 评测集 20 组 × 32 局 = 640 局，跟点档，本机 CPU**，
共 75 次死亡。三个脚本都是包在评测循环外面的一次性诊断，没改仓库，**尚未入库**（方法写在下面，够重写）。

⚠ **口径**：单个 checkpoint、单种子、75 次死亡。分卡的数字（个位数）只能看方向；总量上的两个结论
（漏弹不重要、贴边很重要）效应都在一个数量级以上，站得住。

### 一、引擎判中弹后约 7 帧才给 `done`

命中帧（自机与某颗弹的边距 < 0）之后 6–8 帧 `done` 才置 1（决死窗口）。这段时间自机照常移动、
模型照常决策和领奖励，凶手弹则已经被清掉。两个后果：
① **找凶手要回溯**：在 `done` 前 12 帧里取「弹边距最小」的那帧当命中帧，凶手 = 那帧边距最小的弹；
直接拿 `done` 前一帧看，最近的弹在 20+ px 外，会误判成「非弹致死」。
② 训练里死亡的 −10 晚 7 帧到，这 7 帧的动作也被记了账。GAE 处理得了，影响不大，但凡是按帧对齐死亡的分析都要记得这个偏移。

### 二、top-K = 64 截掉了什么：截满很常见，但几乎不致死

特征化按「外推最近距离」取前 64 颗弹。先看截满频率（每组 4 局的小样本）：

| 卡 | 场上弹数均值 | 危险圈（≤128 px）内超过 64 颗的帧占比 r2 / r3 | 截满时第 65 颗的外推最近距离 p10 |
|---|---|---|---|
| `s2_b6` | 283 | 31% / 77% | 63–75 px |
| `s3_mb3` | 452 | 75% / 77% | 58–64 px |
| `s3_w02`（高速道中） | 162 | 45% / 47% | **21–31 px** |
| `s3_w12`（密集道中） | 236 | 51% / 53% | **13–26 px** |
| `s2_mb1`（螺旋） | 87 | 17% / 29% | 23–36 px |

多数卡上被截掉的弹在 60 px 开外，确实不用看 —— **加大 K 没有意义**。`s3_w02` / `s3_w12` / `s2_mb1` 三张是真漏：
10–22% 的帧里有此刻就在 48 px 内的弹没进网络。原因不是 K 小而是**排序键**：危险度按「假设自机全速朝锚点走」
外推，自机实际在躲弹、并不朝锚点走，按假想轨迹会擦身而过的弹排名很低。

**但它不致死**。对 69 次弹致死，沿凶手弹的速度反推它 N 帧前的位置，在那帧弹表里找 3 px 内的弹，看当时入没入选
（对照组 = 存活帧上随机抽的、一帧后离自机 < 24 px 的弹，4542 个）：

| 命中前 | t−3 | t−5 | t−10 | t−15 | t−30 |
|---|---|---|---|---|---|
| 凶手弹没入选 | 2.9% | 4.4% | **0%** | 4.8% | 24% |
| 对照组 | 0.3% | 0.3% | 1.0% | 1.7% | 4.3% |

命中前 3–15 帧内凶手曾经漏过的死亡只有 **5 / 69**（其中 4 次在 `s2_mb1` r3）。比例确实高于对照，
但**完全修好也只值约 0.8pp**（5 / 640）。⇒ 「为修漏弹而改排序键 / 加局部细图」不值得单独占一条 run。

### 三、47% 的死亡发生在贴边处，而且是被逼过去的

| | 贴边（离最近边 ≤ 16 px） | 不贴边 |
|---|---|---|
| 存活时间占比 | 1.8% | 98.2% |
| 死亡数 | 35 | 40 |
| 每万帧死亡风险 | 20.6 | 0.44 —— **差 47 倍** |

35 次贴边死亡的成因（阈值是诊断时定的，见各行）：

| 类型 | 次数 | 判据 |
|---|---|---|
| 被指挥到边上 | 4 | 目标点离边 ≤ 40 px 且自机在目标点 48 px 内 |
| 最后半秒被逼过去 | 13 | 半秒前离边还 > 32 px |
| 1–2 秒内逐步退过去 | 13 | 其余 |
| 赖在边上 | 5 | 死前 2 秒有一半以上时间贴边 |

- **轨迹**：离边距离的中位数，命中前 2 s 是 91 px → 1 s 前 37 → 半秒前 21 → 命中时 0。
- **早就放弃了指令点**：贴边死亡时自机离目标点的中位距离 153 px（35 次里 24 次 > 96 px）；不贴边的死亡只有 25 px。
- **与目标点留边无关**：目标点离边 ≤ 40 px 的帧占 22.5%，「被指挥到边上」的死亡却只有 4 次。
- **分卡**：`s2_mb1` r3（螺旋）17 次死亡里 12 次是被顶到墙上，`s1_b4` 13 次里 10 次贴边，`s3_w12` r3 7 次里 5 次。
  反例 `s3_b5`：16 次死亡只有 2 次贴边、凶手弹全程都在网络输入里 —— **另一种尚未查明的失败**。

**怎么理解**：这是退路判断的问题。每一步往远离弹流的方向让，单步看都对，连起来就把自己送进死角；
人在这种局面会横穿弹流回到中间。而**特征里几乎没有「墙」**：危险度只对弹和敌算，墙只通过自机绝对坐标
（x/192, y/192）间接进网络，往墙边退和往空地退在近身特征上完全一样。

**与 I 那节记的副作用是同一件事**：混合意图治好的是「飘到边上就死」，没治好「往边上飘」（自由档贴边率 27%）。
自由档的贴边时间是跟点档的十倍以上，部署时无目标点（th06nc mod 的 BYPASS 自 09-20 起默认 `free`）下这个死因只会更突出。

### 四、对模型结构那三个问题的结论（都未立项）

| 提议 | 结论 | 理由 |
|---|---|---|
| 三个 encoder 合成一个大的（token 间 self-attention） | 现在不做 | 上面的证据指向「看不见墙 / 没有退路感」，不是看见之后融合得不好；update 已占 44% 墙钟，self-attention 要掉吞吐，且与所有基线不可比。要判容量是否瓶颈，便宜的办法是补当年取消的 B（`d=32` / `d=128` 对照） |
| 粗密度图 + 自机周围的细局部图 | **有价值，但理由换了** | 不是为了修漏弹（只值 0.8pp），而是**加一个「墙」通道**：以自机为中心（如 16×16 格 × 8 px = 128 px = `d_max`），场外格子标成占据，墙和弹进同一种表示，退路在空间上直接可见；通道建议做成 t = 0 / 4 / 8 / 16 帧外推后的「未来占据」。要新特征化 v4 + 重导出；C 端不用改（图的输入还是原始表） |
| 加记忆（RNN / 帧堆叠） | 现在不做 | 弹带 `vx, vy`，对直线弹当前帧几乎就是完整状态；记忆买到的是弹幕节奏，更像上层指挥模型的职责。代价是循环 PPO + 截断 BPTT + CUDA graph 重做 + DLL 维护隐状态。**真要做，和「观测延迟」绑在一起**（延迟 d 帧后模型得靠最近 d 步动作推自己在哪），且优先用动作历史这种无状态输入 |

### 五、J 的活命建立在精确到帧的操作上

起因（用户 09-20）：模型很擅长「精确钻小缝」，看着稳如老狗，但那是建立在「精确向右移动 1 帧」这类人手做不到的操作上的。
先量依赖程度：**不重训，只在评测的执行层加人手约束**（J best.pt × 640 局，CPU；模型看到的「上一步动作」是实际执行的那个）。

| 执行层约束 | r2 撑过 | r3 撑过 | 变向/s |
|---|---|---|---|
| 无（基线） | **0.919** | **0.847** | 3.22 |
| 换方向后至少保持 3 帧（50 ms） | 0.628 | 0.331 | 2.91 |
| 至少保持 5 帧 | 0.309 | 0.081 | 2.60 |
| 至少保持 8 帧 | 0.125 | 0.009 | 2.29 |
| 变向随机延迟 `U{0..2}` 帧才生效（平均 1 帧） | 0.450 | 0.175 | 2.63 |
| 变向随机延迟 `U{0..4}` 帧 | 0.197 | 0.041 | 2.32 |

- **最轻的约束就崩**：3 帧比人能稳定做到的还松，r3 已掉 52pp；平均 1 帧的时机偏差就让 r2 减半。
  **十张卡无一例外**，连最稀的 `s1_w04` 也是（r3：1.00 → 0.47 → 0.06）—— 不只是钻缝时用，整套走位都建立在这上面。
- **与 E 的滞回扫描对照**：那次扔掉一半变向、撑过不掉 ⇒ 那一半是多余的。这次变向只从 3.22 降到 2.91/s，活命却崩了
  ⇒ **被禁掉的那一小部分操作正是它活命的关键**。
- **无约束下每段移动保持多久**（37 860 个移动段）：1 帧 13.1%、2 帧 12.8%、3 帧 10.1%、4–5 帧 16.0%、≥6 帧 48%。
  **四分之一的移动是 ≤2 帧的点按（0.63 次/s），三分之一以上 ≤3 帧。**
- **「方向变化 3.5 次/s ⇒ 进入人类区间」（阶段性总结 ②）要打折**：那个指标量的是换方向的**频率**，不是操作的**精度**。
  抖动确实治好了，但「像不像人手」它没量到。

**为什么 D → F → J 这条路到不了这里**：`quick_change` 是 −0.01，死亡是 −10。一次精确点按若能免掉一次死亡，
值 10、价钱 0.01，模型当然照付。惩罚压下去的只是「无所谓」的那些抖动（平局来回翻、驻留时抠位置）；
**惩罚改得了习惯，去不掉能力** —— 要去掉能力，得让环境里根本做不出来。

⚠ 口径：这张表量的是**依赖程度**，不是重训后的水平。模型没见过这种约束（起手一次点按、预期下一帧能停，
结果被锁着多走了 2 帧），是分布外输入；带约束重训的模型会提前规划，成绩会比表里好得多。
但它同时说明：**部署时在 DLL 里单方面加这层约束不可行**，等于把模型废掉。

## N1 / N2 手部运动层（2026-09-20 立项）

- **问题**：把人手的限制写进环境重训，模型能否在「做不出精确到帧的操作」的前提下重新学会活命，并因此自己留出余量。
- **目标（用户 09-17 拍板，见「待立项：拟人方向」）**：强但像人，**撑过率允许为此下降**。

### 为什么约束必须是随机的（用户 09-20 指出）

确定性的「至少保持 N 帧」只是把时间轴量化成 N 帧一格：模型照样知道「点一下 = 恰好 N 帧 = 恰好 N×速度 px」，
可以在粗一点的格子上**继续稳如老狗**。人手的限制不是格子粗，而是**结果不可控** —— 想点一下，出来的是 3 帧还是 5 帧
自己说了不算；想在这一帧按，实际落在前后一两帧。只有「同一个意图、结果有散布」才会逼出余量：
位移不确定 ⇒ 缝的宽度必须大于散布 ⇒ 窄缝自动变得不划算。而且余量会**自己按场景变**：高速移动时一帧误差对应 4.5 px、
要留大余量；静止时窄缝照样能待（人也是）。这比 backlog 里的「判定点随机增大」准 —— 那是一刀切，
连「静止待在窄缝里」这种人做得到的事也禁掉了。

### 运动层（训练包装层里，策略与 env 之间）

每个 env 一个小状态机；策略每帧输出「想按的方向」`want`，运动层决定实际执行的 `cur`：

```
状态：cur（正在执行的方向 0–8）· held（cur 已执行几帧）· L（本段的最短长度，换段时抽）
      pend / wait（待生效的方向与剩余延迟；N1 恒无延迟）

每帧：want == cur            → 清掉 pend
      want != cur 且 want != pend → pend = want，wait ~ U{delay_lo..delay_hi}     （新意图，新延迟）
      若 pend 存在：wait == 0 且 held >= L → cur = pend，held = 0，L ~ U{hold_lo..hold_hi}，清 pend
                    否则 wait = max(0, wait − 1)
新局：cur = 0（不动），held = 很大，L = 0，无 pend           （= 开局第一下不受限）
```

- **`L` 对模型不可见**：模型看得到 `held`（人知道自己按了多久），看不到「还要锁几帧」（人不知道手指什么时候真正抬起来）。
  这是散布的来源 —— 想点一下，实际 2–6 帧不等。
- **低速键不过运动层**（第一版）：只锁方向。**已知漏洞**：高速 4.5 / 低速 2 px 交替可以拼出细位移。
  盯 `shift_toggles_per_s`（J：r2 0.66 / r3 1.05），明显上升就在下一轮把低速键也接进来。
- **「上一步动作」记实际执行的**（`cur`，不是 `want`）；`key_press` / `quick_change` 与全部逐局统计也按执行的算 ——
  策略的 `want` 来回翻不花钱、也不算抖，只有真按出去的才算。`quick_change` 保留 J 的 −0.01 不动（单变量）。
- **镜像**：运动层作用在智能体坐标系的动作 id 上（镜像之前），只做相等与计数，天然对称。
- **随机数**：独立的 `torch.Generator`（种子由 run seed 派生），评测用固定种子，同一 checkpoint 两次评测逐位相同。

**参数（60 Hz，1 帧 = 16.7 ms）**：

| | `hold` = `U{2..6}` 帧 | `delay` |
|---|---|---|
| N1 | 33–100 ms，均值 67 ms。熟练玩家刻意点一下约 50–100 ms。**用户 09-20 拍板取 2–6**（比初稿的 2–5 散布更大） | 无 |
| N2 | 同 N1 | `U{0..2}` 帧，均值 17 ms。只建模**时机散布**，不是反应延迟（那是「观测延迟」，另立） |

N1 → N2 是单变量的一对：N1 回答「持续时间不可控」要多少代价，N2 再加「起手时机不可控」。
拆开跑是因为上面的诊断里这两种约束各自都能让 J 崩，不拆就分不清是谁在起作用。

### 特征化 v4 = v3 + `held`

`player` 向量追加一维 `min(held, 16) / 16`（13 → 14 维）。没有它状态不满足马尔可夫性：
同一个局面下「刚换完方向」和「已经走了 10 帧」能不能再换的概率完全不同。`held` 包装层里现成
（`envwrap.dir_hold`，给 `quick_change` 用的那个），接进 `RawObs` 即可。**不加 `pend`**：策略无状态、
每帧重新表态，延迟期间它只要继续想要同一个方向，`pend` 自然保持。

### 评测口径

- **主判据：带运动层评测**（`[eval].motor = "train"`，与训练同分布、固定种子），末 4 次评测均值。
  **对照线不是 J 的 0.92，而是 J 在同一个运动层下的成绩**（已补测，见下面「对照线」：
  N1 的层 0.400 / 0.122，N2 的层 0.184 / 0.056）。
- **新增指标**：`seg_le2_frac` / `seg_le3_frac`（移动段里 ≤2 / ≤3 帧的占比，**按执行的算**）、
  `motor/override_frac`（`want != cur` 的帧占比 = 运动层替它做主的频率）。
- **例行探针**（今后每个模型都测，CPU）：① 运动层关掉；② 加码到 `hold U{3..7}` + `delay U{0..4}`。

### 判读（立项时定）

1. **带运动层的撑过**：成功 = r2 ≥ 0.85 且 r3 ≥ 0.70（参照：实验 C 的 2 帧确定性粒度掉了 6.6pp，这里更狠）。
   r2 < 0.75 ⇒ 约束太凶、学不动，放宽到 `hold U{2..4}` 重跑，不要硬加轮数。
2. **余量是不是自己长出来了** —— 这才是这条实验的本意：`close12_frac`（J：r2 22% / r3 30%）、`close4_frac`、
   擦弹/s 应明显下降。撑过回来了而贴弹没降 ⇒ 它找到了别的精确手段（先查低速键那个漏洞）。
3. **加码探针下平缓退化**：J 在轻约束下直接崩（0.92 → 0.63）；N 在比训练更凶的运动层下应只掉几个点。
   这是「不依赖精确操作」的直接证据，比任何频率指标都硬。
4. **关掉运动层不应更差**：更差说明它学会了依赖「被锁住」这件事本身（比如靠锁定期滑过某个位置），是坏味道。
5. **跟点率会掉，可接受**：停进 24 px 的圈本身就要精细操作。掉得太多（< 0.65）再考虑把 `hold_radius` 放大。
6. **贴边死亡占比**（47%，见第三节）顺带看：余量变大后被逼到墙上的频率可能变、也可能更糟，决定 M 还要不要单独跑。

### 没选的方案

- **确定性最短保持**（09-20 最初的提议）：见上，只是把格子变粗。真想验证「随机性是否必要」，
  可加一条 `hold = [3, 3]` 的对照，再用随机运动层去探它 —— 预期它会像 J 一样崩。先不花这条 run。

### CPU 配额节流 —— 配额已确认（24.48 核），但它不是全部原因（2026-09-21；后续见「L / O 结果 · 耗时」）

**现象升级**：N3 ‖ M 同机同时跑，**N3 全程 52k/s、5.60 h 跑完；M 从 u200 起掉到 36–42k/s、7.08 h**（`env_step` 每轮
1.1–1.3 s vs 2.3–3.2 s）。二者只差一个 reward 系数 ⇒ 不是整机状态、不是实验内容，是**单个进程**的事。
`env_step` 耗时是**双峰**的（1.0–1.5 s ↔ 2.5–4 s），一个进程会长时间停在一档、偶尔翻转；N1 / N2 / M 中招，J / I2 / N3 没有。
已排除：代码（bench）、随机数、按键形态、线程数（都是 32）、线程钉核（逐核数据显示散在全部 255 个逻辑核上）。

**最可能的真因（用户 09-21 提供的信息）：租的实例只有 24 个物理核。** 容器看得见宿主机全部 255 个逻辑核（`nproc` 报 255，
逐核数据里混着别的租户），但平台给的是 **cgroup 的 CPU 时间配额**（CFS bandwidth，按 100 ms 周期结算，用满就把整个容器
掐停到下个周期）。账对得上：每条 32 个 env 线程，rollout 时每 100 ms 约 4 步 × 32 线程 × 15 ms ≈ 2.0 核·秒，配额 2.4 核·秒 ——
**单跑刚好塞得下，两条的 rollout 撞在一起就是 4.0 > 2.4，被节流**。两条迭代周期接近时相位会锁住：一条的 rollout 落在另一条的
update（GPU 阶段，几乎不用 CPU）里就没事，撞上就一直慢 ⇒ 双峰、单进程、持续、偶尔翻转、单跑从不慢，全都解释了。
最早那张基准表「63 线程 24 万步/s、127 线程 18.6 万、255 线程 4.8 万」也是它，当时误归因成了物理核 / CCD 布局。
（此前猜过 NUMA 跨插槽访存，先放一边；若下面的确认显示没有配额再回头查。）

**开跑前在训练机上确认（30 秒）**：

```bash
cat /sys/fs/cgroup/cpu.max 2>/dev/null || cat /sys/fs/cgroup/cpu/cpu.cfs_quota_us /sys/fs/cgroup/cpu/cpu.cfs_period_us
cat /sys/fs/cgroup/cpu.stat 2>/dev/null || cat /sys/fs/cgroup/cpu/cpu.stat
```

预期第一条是 `2400000 100000`（24 核；按超线程计也可能是 48），第二条里 `nr_throttled` / `throttled_usec` 是很大的数。

**修法（已写进 `scripts/run-night.sh`，未提交，等上面确认）**：线程数按「cgroup 配额 ÷ 同时跑的条数 − 2」定（钳进 4–32；
24 核跑两条 ⇒ 每条 10 线程），不再按 `nproc`；分两个终端各开一条时用 `--share 2` 告诉脚本这台机器同时跑几条；
开跑前与收尾各打一次节流计数，差值就是这批实验吃到的节流。代价：单跑 bench 里 8 线程的端到端吞吐是 32 线程的 86%、
16 线程 92% ⇒ 少开线程的损失远小于被节流。线程数只影响速度、不影响实验结果。**判据**：下一批两条都稳在 50k/s 上下、
收尾的节流计数增量很小 ⇒ 破案，每批省 1.5–3 h。

## 诊断记录：危险度特征的依赖、实机用法（2026-09-21）

### 一、现有模型几乎完全建立在手工危险度特征上

起因：讨论「每个方向按住 N 帧会怎样」这类特征要不要加 —— 原理上逐弹 MLP + max 池化学得出来（Deep Sets 的表达能力覆盖它），
那么反过来，现在喂的危险度特征（外推最近距离 d、到达时刻 t；选哪 64 颗弹也按 d 排）网络到底用没用？
**评测时**对这两列动手脚（弹与敌都改；各 640 局，CPU；量的是「已训好的模型的依赖」，不是「不给这两列重训会怎样」）：

| | 正常 | 两列清零 | 两列在同帧入选弹之间打乱 |
|---|---|---|---|
| M（带运动层）r2 / r3 | 0.82 / 0.64 | **0.21 / 0.08** | **0.03 / 0.00** |
| J（无约束）r2 / r3 | 0.92 / 0.88 | 0.02 / 0.00 | 0.00 / 0.00 |

网络并没有自己从位置 / 速度算几何，它读的就是我们喂的 d 与 t。两个推论：
① 「不加危险度特征、让编码器自己学」**风险偏高** —— 要从零学会它现在完全外包的那部分计算。
   （口径：这张表证明的是**已训好的模型依赖这两列**，不能证明「不给这两列重训就学不会几何」；那个消融没做过。）；
② 这两列背后的假设是「**假设自机朝锚点走**」，对一双每次至少走 2–6 帧的粗手，对的假设是「**每个方向按住 N 帧会怎样**」。
   换假设应当有实打实的价值，而且特征在图内用同样的原始输入算 ⇒ **图签名不变，C 端与 mod 不用动**。
为什么不指望它自己学到：J 时代是**反馈控制**（每帧能改方向，几何算个大概即可，误差 16 ms 纠正一次）；套上运动层之后是
**前馈预测**（一个动作锁 2–6 帧 + 起手延迟 0–2 帧，决定那一刻就得算准未来 0.1 s），对几何精度的要求高一个量级 ——
碰撞是几个像素的事，输入按 192 px 归一化，64 维 ReLU MLP 逼近「点积、除法、截断、开方」的误差就在几个像素。
旁证：N3 / M 关掉运动层是 0.94–0.95 / 0.84–0.87（不输 J）⇒ 反馈式躲弹学得很好，死的是需要提前规划的场景。
**立项前还差一步**：对 M 的死亡做分类 ——「死前最后一次放行时，存在安全方向但选了会撞的 / 所有方向都会撞 / 按外推安全仍然死了」，
第一类占多数才值得加特征。**未做**。

### 二、实机用法：「AUTO 跟 boss 正下方，压力大就切 BYPASS」几乎能收所有符卡（用户 09-21 实机）

用户实机打 M：平时 AUTO（锚点 = boss 正下方），目测压力大时手动切到 BYPASS（无目标点），**几乎能收所有符卡**。与数据完全一致：

- 这个用法只用到 M **最强的两档**（锚点 0.916 / 0.659、自由 0.925 / 0.753），完全避开了它最弱的那件事（每 2–5 s 大幅度换位，0.807 / 0.589）。
  boss 正下方是缓慢平移的目标点，不是瞬间跳到场地另一头。
- 「压力大就切自由档」是两级设计里留给上层指挥的那一格：高压下（r3）自由档 0.75 vs 跟点档 0.59，
  **不催它去哪是对它帮助最大的一个指令**；人每一刻选的是两档里更合适的那个，比固定用哪一档都好。
- 真机比训练环境宽松：boss 打得死（站 boss 正下方火力最集中 ⇒ 符卡更早结束、暴露时间短），训练里 boss 无敌、固定撑满 60 s。
- **运动层顺带做了时序上的域随机化**：真机从读内存到按键生效有固有延迟，J 在训练里每帧精确到位、到真机会吃时序差的亏；
  M 是在「起手延迟 0–2 帧、每段长度随机」下练的，对时序偏差不敏感（加码探针里 N2 / M 平缓退化、J 直接崩）。

⇒ ① 主判据（跟随随机目标点）是压力测试，**低估部署效果**；该补一个对应真实用法的口径（锚点 + 自由档切换）。
② 用户手动做的切换可以让 mod 自动做：危险圈内弹数 / 最小净距过阈值 ⇒ 锚点临时切成 free，压力降下来切回。不用重训；
先在仿真里验证（写一个模拟这条规则的评测意图、扫阈值，纯 CPU）。**已做，见下面第三节**。

用户补充（09-21）：这个用法下自机多数时间在 boss 正下方、火力最集中，**一般打不到 30 s 符卡就结束了**，不需要撑满；
训练 / 评测里 boss 无敌、每段固定 60 s ⇒ 评测的撑过率对实机用法偏悲观。第三节因此同时报 30 s 口径。

### 四、死亡分类：一半的死亡发生在「有安全走法、却选了会撞的」

为「每个方向按住 N 帧会怎样」这类特征找依据（见第一节）。对 M 的每次弹致死，回溯到**最后一个还来得及的决策帧**
（这一段方向开始执行的那帧与「命中前 8 帧」里较晚的那个），在那一帧的局面上用**线性外推**对 18 个动作各算「按住到命中时刻」的最小净距：

| | 死亡 | **A** 执行的会撞、且存在净距 ≥ 2 px 的动作 | **B** 18 个动作全会撞 | **C** 执行的按外推安全却死了 | 其它（非弹） |
|---|---|---|---|---|---|
| 跟点档 | 179 | **81（45%）**；r3 上 59 / 119 = **50%** | 27（15%） | 62（35%） | 9 |
| 自由档 | 103 | **58（56%）**；r3 上 48 / 79 = **61%** | 12（12%） | 24（23%） | 9 |

- **A 类的样子**：决策帧到命中的中位数是 **6 帧**（100 ms 的提前量），当时 18 个动作里中位有 **5–7 个是安全的**、最好的那个净距 8–9 px，
  而这一段方向已经走了 6 帧（多半已经过了锁定期、来得及换）。也就是：**线性外推在 6 帧之前就能看出这条路会撞、且旁边有路，模型还是撞上去了。**
- **B 类（被逼进死局）只占 12–15%** ⇒ 「粗手在高密度下根本没有路」不是主因，能力上限的说法要收回一大半。
- C 类的执行动作外推净距中位只有 1.2–1.3 px、H 中位 1：多是最后一帧才变向、或净距本来就贴着 0 的擦边死，外推口径之外（非直线弹、新生成的弹）也在这里。
- 口径上的保留：替代动作按「立刻生效」算（实际有 0–2 帧延迟），对 A 偏乐观；但 H 中位 6、且该段多已过锁定期，多数 A 仍然成立。
- ⇒ **给「换假设的危险度特征」立项的依据有了**：现有 d / t 两列回答的是「朝锚点走会怎样」，模型又几乎完全依赖它们（第一节）；
  换成「每个方向 × 高 / 低速，按住 2 帧 / 6 帧的最小净距」（18 × 2 维，图内用同样的原始输入算 ⇒ 图签名不变）。
  若 A 类能免掉一半，r3 跟点档约 +9pp、自由档约 +7pp —— 是目前找到的最大一根杠杆，远大于 L（+3pp）。

### 五、闭环救援探针：只替换 0.65% 的帧，r3 +14pp —— 几何信息确实救得活

第四节的死亡分类有两个漏洞（外部评审 09-21 指出）：替代动作按「立刻生效」算、没把两路的锁定与延迟计完整；也没证明
「躲过这一波之后还有退路」。所以做一个**闭环**探针：保留运动层，只在模型的请求按外推会撞、且另一个动作明显更安全时**替换请求**，跑完整局。

- 预测只用**当前观测**（弹的位置 / 速度 / 半径、自机状态、`dir_held` / `slow_held`），不用未来真值、不用运动层抽到的隐藏量。
- 运动层语义按**最坏情形**计入：想换方向 / 低速位时，新取值要等「剩余锁定 [lo, hi] + 延迟 [lo, hi]」帧才生效，期间继续执行当前取值；
  对最早 / 居中 / 最晚三种生效时刻各外推一条**分段轨迹**（先继续当前动作、再切换），取 8 帧内的最小净距。
- 用离自机最近的 128 颗**全部有判定的弹**，不是模型入选的那 64 颗。
- 替换条件保守：请求的最坏净距 < 0.5 px，**且**存在净距 ≥ 4 px、比请求高出 ≥ 4 px 的动作。多个安全动作时优先朝目标点进度最大的
  （避免只会逃跑）；上一帧替换过的动作只要仍安全就沿用（否则自己会反复重抽延迟）。

各 640 局，CPU；「关」与「开」同脚本、同种子成对比较：

| | r2 撑过 关 → 开 | r3 撑过 关 → 开 | 被替换的帧 | 危险且无安全替代的帧 | 跟点率 / 方向/s |
|---|---|---|---|---|---|
| **M 跟点档** | 0.812 → **0.869**（+5.7） | 0.628 → **0.772**（**+14.4**） | 0.65% | 0.36% | 不变（0.599 / 5.5） |
| **M 自由档** | 0.925 → **0.953**（+2.8） | 0.753 → **0.841**（+8.8） | 0.30% | 0.18% | — / 2.4 |
| J 跟点档（无运动层，参照） | 0.919 → 0.953（+3.4） | 0.847 → 0.884（+3.7） | 3.44% | 0.12% | 0.763 → 0.743 / 3.1 → 3.5 |

- **明显救活**，而且增益正好落在老短板上（M 跟点档 r3）：`s3_b7` 0.19 → 0.62、`s2_mb1` 0.38 → 0.69、`s3_b5` 0.19 → 0.47。
  M 自由档 + 救援的 0.953 / 0.841 已经与 J 完全不受约束时相当。
- **只动了不到 1% 的帧**，跟点率、方向频率、贴弹占比都没变 ⇒ 它不是「换了一种打法」，只是在关键的几帧上替模型做了它算不准的那道几何题。
  与第四节（一半的死亡是「有路却撞上去」）和第一节（模型的几何全靠手工特征）互相印证：**缺的是「每个候选动作的短期后果」这条信息。**
- 危险帧里约三分之一（0.36% / 1.01%）没有满足条件的替代动作 —— 剩下的死亡里有一部分是更早就形成的死局，单帧几何救不了。
- J 也受益（+3–4pp），但要替换 3.4% 的帧、跟点率略降：对一个每帧都能纠正的模型，这层信息的边际价值小得多 —— 与「运动层把问题从反馈变成前馈」一致。

⇒ 两件事都有了依据：
1. **动作危险度特征正式立项**（下一批 GPU）：每个候选动作在运动层最坏情形下的短期最小净距，图内用同样的原始输入算（图签名不变）；
   保留原有特征，第一版只追加。
2. **救援层本身就是一个不用训练的部署方案**：只改「请求」、运动层照常生效，按出去的动作仍是人手做得出来的。
   计算量每帧约 18 × 3 × 8 × 128 次距离，C 里可以忽略。**未实现**；与压力切换叠加的效果也还没量。

### 七、目标点跳变对输入的冲击；请求 → 执行的统计

**目标点跳变**（外部评审提出的机制，代码核实：目标点 → 假想自机速度 → 弹的相对速度 / 外推最近距离 / 选哪 64 颗弹）。
冻结同一帧、只把目标点换成下半屏随机一处，M / N2 / O 各约 9000 个样本：**入选的 64 颗弹的重合率（Jaccard）只有 0.44**
（三个模型一致；原来在圈内 0.45、在路上 0.44）—— 目标点一换，弹一颗没动，模型「看见」的弹就换掉了约四成。
⇒ 机制成立且量级不小：跟点档每 2–5 s 一次的目标点刷新，同时也是一次输入表达的突变；自由档 / 锚点档（假想速度恒为 0 或大多为 0）
没有这个问题，正是表现最好的两档。这给「动作危险度」特征多了一条理由：**把安全几何与目标点解耦**。
（口径上的保留：脚本里的「相邻帧自然变化」对照无效 —— 弹在缓冲里按帧重新打包，下标不保身份；策略输出的变化（最优方向翻转 74–77%）
也不干净，换了目标点本来就该换方向。站得住的只有同一帧内的入选弹重合率。）

**请求 → 执行**（运动层的 `pend` / `wait` 对模型不可见，会不会因此乱翻、自己推迟自己？）：

| | 请求数 | 兑现 | 中途改主意 | 撤回 | 兑现延迟 p50 / p90 / 均值 |
|---|---|---|---|---|---|
| M | 54 101 | 70.7% | 20.4% | 8.8% | 2 / 4 / 2.6 帧 |
| N2 | 47 340 | 71.0% | 19.8% | 9.2% | 2 / 4 / 2.5 帧 |
| O（低熵） | 30 572 | 81.8% | 13.0% | 5.2% | 2 / 3 / 2.3 帧 |

约三成的请求没等到生效就变了，但兑现的那些只等 2–3 帧（≈ 剩余锁定 + 抽到的延迟），没有被乱翻明显拖长；而且「改主意」里有多少是局面真变了、
多少是无谓的翻动，这张表分不出来。结合 N1（无延迟）≈ N2（有延迟）⇒ **「请求历史」实验的预期收益是中等**，值得做但不必抢在动作危险度之前；
它要升图版本（观测加「上一步想按的」），成本也更高。

### 二、跟点档的死亡：六成死在半路，半路的每帧风险是圈内的约 4 倍

179 次死亡：离目标点距离分位（10 / 25 / 50 / 75 / 90）= 14 / 26 / 80 / 140 / 219 px；**110 次（61%）死在离点 48 px 以外**，
圈内（< 24 px）只有 40 次，而圈内时间占 60% ⇒ 半路的每帧死亡风险约为圈内的 4.2 倍。贴边死亡 23 次（贴边帧 0.8%）。
它并不是「赶路太急」：到达用时 M 73 / 110 帧（r2 / r3），J 只要 36 / 38 帧 —— 已经走得更慢、更小心，仍然在路上死。

### 三、凶手弹有没有被看见：漏弹的份额涨了，但上界仍只有 2–4pp

| | 弹致死 | 命中前 3–15 帧凶手曾没入选 | 同口径对照（存活帧上贴身的弹） | 全修好最多值 |
|---|---|---|---|---|
| J 跟点档（09-20） | 69 | 5（7%） | 1.9% | 0.8pp |
| **M 跟点档** | 170（r3 占 114） | 13（8%；r3 10 次） | 1.9% | 2.0pp（r3 上 3.1pp） |
| **M 自由档** | 94（r3 占 76） | 14（15%；r3 12 次） | 0.7% | 2.2pp（r3 上 3.8pp） |

漏弹致死的比例确实高于对照、也高于 J 时代，且集中在 r3；但**把漏选致死全部修好也只值 2–4pp**（注意这不是 CNN 收益的上界 —— 它还可能改善更早的路线选择，这里量不到），而近距离 CNN 是几项里最贵的
（新特征化 + 镜像对称 + 重导出 + 再升一次图版本）。84% 的死亡发生在「危险圈内超过 64 颗弹」的帧上，但 r3 密集卡上这种帧本来就占
45–77%，没有基准率说明不了问题。⇒ **按目前的证据与成本，仍不优先**（不是「已被排除」）；L（rank 3 进训练）会直接改变 r3 上的局面，等 L 出来对 L 的模型重做一次这张表再定。

### 小结

两个候选都没拿到立项依据：CNN 在「漏选致死」这一条上最多值 2–4pp（其它收益未量）；指令分布只占跟点档差距的四分之一到三分之一。M 剩下的差距主要是
**「粗手下的重新定位」**与 **r3 泛化**，后者正是 L 在测的。前者目前没有现成的解法，记为开放问题。

**三档锚点对比**（E 的 best.pt，9 张评测卡 × 32 局，本机 CPU，`eval_ckpt --intent`）：

| 意图 | 撑过 | 跟点 | 方向/s | 贴边 |
|---|---|---|---|---|

- **随机换点（「瞎指挥」）的代价约 4 个百分点撑过率**；**没有锚点的代价约 21 个百分点**，因为会往边上飘（贴边 0.9% → 21%）。
  起作用的是**锚点本身（位置先验）**，不是随机性；随机只是训练期的探索/课程副产品。
- 推论：**「自由躲弹」不需要专门训练一个无指令模式**——部署时指挥模型空闲就发一个保守锚点（场底中央 / boss 正下方偏低）即可，撑过 0.97。
  原计划的「特征 v3 + 无指令段 + 贴边惩罚」降级为备选。
- 另记：方向变化 13.0 → 10.1 说明**有一部分抖动是「追点」造成的**，判读拟人指标时要和「躲弹造成的移动」分开看。

**待立项 · 指令分布更贴近实用**：现在是下半屏均匀随机、每 2–5 s 换一次，比指挥模型将来的用法激进。候选：拉长刷新间隔 /
新点靠近当前位置 / 混入长时间不动的锚点。**会改变训练分布、使既有基线不可比**，排在拟人主线之后。

**激光调查（2026-09-18，数原作 ECL）**：含激光指令的 sub 数 / 激光指令行数——
第 1 关 2/12、第 2 关 1/3、**第 3 关 0**、**第 4 关（帕秋莉）11/326**、**第 5 关（咲夜）0**、**第 6 关（蕾米）0**、第 7 关（Extra 芙兰）3/51。
⇒ TH06 的激光集中在第 4 关与 Extra；**第 5、6 关完全没有激光**，扩卡池不必等引擎。
决定（2026-09-18）：**先转写第 5、6 关**；引擎激光池仍是独立 milestone（stg-engine world-design §709 / follow-ups D23#10），
触发点改为「要打全作（含第 4 关 / Extra）或迁移验证显示激光是主要差距」。

模型侧结论（激光真来了怎么接）：**不要塞进弹的那条流**（点语义会丢掉线段几何）。正确做法是**再开一条集合流**：
每条激光一行 = 点到线段垂距 / 在哪一侧 / 自机速度与激光轴夹角 / 宽度 / **几帧后生效（预警倒计时）** / 剩余存活帧，
与弹、敌同构的 SetEncoder 共享 query；密度图另加一个「激光覆盖」通道；选前 K 用点到线段距离而不是点的最近接近公式。
预警线与现有「几帧后到达最近点」是同一类时间特征，不需要新机制。

## 裁定：卡池里的小怪也无敌（2026-09-20）

起因是个合理的质疑：真实游戏里玩家密集开火、小怪一波波死掉，道中压力远没有我们模拟的这么大，
那 J 在密集道中卡上的代价岂不是对着一个假需求？查下来事实比这更彻底 —— **两层都堵死了**：

| | 卡池现状 | 原作 |
|---|---|---|
| 小怪能否被打死 | `set_invuln(65535)`，**166 个敌 sub 无一例外** | 血量 50，打得死 |
| 自机火力 | `Loadout{power:0}` → 单发、每 4 帧 1 伤 = **0.25 伤害/帧** | 满火力秒掉一只妖精 |

即：就算去掉无敌，一只 50 血的妖精也要 **200 帧（3.3 秒）**不间断精准命中才死，而 `s2_w08`
每 10 帧下来一只 —— 压力照样掉不下去。（`enemies_killed` 事件确实在跳，但那是 `oob_guard`
的出界 `die()`，不是打死的。）

无敌这条规矩的来源：引擎侧 `docs/rl-card-pool.md` 只要求 **boss** 无敌（否则段长随模型站位变、
难度不稳定，评测不是同一把尺子）；转写契约把它推广到了每只小怪。

**裁定：保持现状，而且这是有意为之。** 理由不是「省事」或「上界更安全」，而是**目标污染**：
躲弹模型的职责只有「到指挥点 + 别死」，**火力站位是上层意图模型的职责**。小怪若能打死且收益明显，
躲弹模型会自己长出「往敌群靠能减压」的议程，在指挥点与敌群不一致时偷偷违抗指令。
无敌把两层的职责边界焊进训练分布里；训练压力是上界、部署时更低，误差方向安全。

**已知且接受的代价**：① 难度画像（`density.json` / 课程权重）系统性高估道中卡；
② 模型学不到「再撑 2 秒这波就没了」这种真实节奏。
**真实关卡（部署用的卡）另论** —— 那里小怪本来就该能打死，届时要先定自机火力档位与小怪血量的标定
（我们的引擎不是 TH06，照抄它的 50 血没有意义）。

## 待立项：拟人方向（2026-09-17 记账，未排期）

**目标（用户拍板）：强但像人**——可以比大多数人强，但操作形态像熟练玩家：有反应延迟、不无意义抖动、躲弹留余量，
**不靠 0 帧反应和像素级精度「神穿」**。撑过率允许为此下降。

`key_press`（D）只治抖动：一次救命闪避的按键代价约 −0.002，死亡 −10，神穿不受影响。`frame_skip`（C）限制的是决策频率而非反应延迟，
33 ms 离人类很远，也治不了神穿。下面几条才是针对神穿的，都只改训练仓，**一次只立一个实验**：

| 候选 | 做法 | 预期作用 / 风险 |
|---|---|---|
| **神穿指标**（前置） | 评测加每秒擦弹次数（env events 第 1 列，擦弹半径 16 px）、每步离弹最近边缘距离的分布 | 没有指标就看不出下面几条有没有效；可对 A / D 的 `u*.pt` 用 `eval_ckpt` 补测 |
| 观测延迟 | 包装层环形缓冲，模型看 d 帧前的局面（先试 d = 8，约 130 ms） | 去掉 0 帧反应，逼出预判；部署侧 C 端须同样延迟 |
| 判定点随机增大 | 每局随机取「虚拟判定半径」= 真实半径 + [0, m] px；包装层发现弹进入虚拟半径就按死亡结算（done = 1，死亡奖励照给） | 学会留余量；引擎判定不变，只在训练胶水里判「虚拟死亡」；m 太大会学得过于保守、少跟点 |
| 操作手滑 | 以概率 p 执行上一步动作（sticky action，ALE 常用 p = 0.25），或以小概率换成随机动作 | 压精确到帧的操作；评测时是否也开要单独定（开 = 测鲁棒性，关 = 测能力）。**对抖动基本无效**（与 C 的 frame_skip 同理：机械地少执行切换，不让策略「不想切换」）；环境变随机还可能增加价值估计噪声、加重平局。实现注意：v2 观测里的「上一步动作」要记**实际执行**的动作，不是策略选的动作 |

> **09-20 更新**：「操作手滑」那一行写的「对抖动基本无效」针对的是「让策略不想抖」这个目标，仍然成立；
> 但目标已经换成「让策略**不能依赖**精确操作」，这时硬约束恰恰是对的工具 —— 已立项为 N1 / N2（手部运动层），
> 设计上不用 ALE 式 sticky action，理由见那一节的「没选的方案」。顺序相应改为：**运动层（N1 / N2）→ 观测延迟 → 判定点增大**。

建议顺序（09-17 原文）：神穿指标（✅ 2026-09-17 已加，E 起有数）→ 观测延迟 → 判定点增大 → 手滑（后两条可能与延迟部分重叠，看前一个的结果再定）。
观测延迟对抖动也有机制性帮助：延迟 d 帧时，比 d 更快的来回切换看不到效果、价值自然变低，配合按键惩罚更易学成「选定方向、保持一阵」。

## 观测语义变化：敌人速度改由引擎给出（2026-09-24，stg_rl 0.2.0）

`envwrap.enemy_velocity`（按 `enemies.id` 匹配上一帧、差分坐标）连同它的上一帧状态（`_prev_enemy_ids`
/ `_prev_enemy_xy` / `_enemy_prev_valid`）已删除。敌人 Tier 0 行新增一等字段 `vx@38`/`vy@42`（步长
38 → 46），`_decode_enemies` 直接读这两列；镜像仍在 `_decode` 里对 `vx` 取负、`vy` 不变。

与旧差分相比，`RawObs.enemies[..., 4:6]` 的取值在几种情形下不同：

- **瞬移**（`move_to` 的 `dur = 0`，如第 5 关咲夜时停窗口压平后每轮一跳）：新语义下**无论跳多远都不计入速度**（记 0）；
  旧差分只在单帧位移超过 `16 px × frame_skip` 时才记 0，慢一点的瞬移会被误当成速度读出来。
- **`move_to` 插值途中与普通移动**：与旧差分结果一致，都是本帧实际位移 / `frame_skip`。
- **`frame_skip > 1`**：新语义是**最后一帧**的位移，不是 `frame_skip` 帧的均值——旧差分是「起点到终点位移 / frame_skip」，
  相当于 k 帧平均；两者在敌人匀速直线运动时数值相同，非匀速（如 `move_to` 途中变速、刚开始/刚结束瞬移那一帧）时会不同。
- **时停帧**：新语义记 0，与旧差分（坐标不变、差分自然为 0）结果一致，但原理不同。
- **新出生的敌人**：第一次被观测到时 `vx`/`vy` 为 0——ECL 里敌人的主任务不在出生那一帧跑，速度指令要到下一帧才生效，
  这一点新旧语义相同，**不是**「出生帧就有值」。
- **不再靠 `enemies.id` 匹配**：池槽号 15 位 generation 回绕导致 id 为 0 的边角问题随之消失（旧差分对 id=0 的敌人有一条
  `cur_ids != 0` 的守卫，规避的正是这个回绕）。

`GRAPH_VERSION` 不变、动作表不变，旧 checkpoint 仍可加载评测——`enemies` 的六列签名没变，只是后两列的来源换了。
但观测数值分布变了（尤其瞬移与非匀速那几帧），拿旧 checkpoint 在新语义下评测得到的数字**不能**与旧语义下的历史记录
直接比较高低；要做严格对比（如复核某个实验的撑过率结论）需要在新语义下重训或至少重新评测同一批 checkpoint。

## 候选：结构方向（2026-09-25 用户提出，排在 Q1 / Q2 定论之后）

Q2 若在 u3500 与探针上保持住，它就是新底子（纯原始 token），以下各臂都以 Q2 为父、互不依赖，可各占一张卡并行：

| 臂 | 改动 | 替代 / 回答什么 |
|---|---|---|
| **R1** | 弹间自注意力（1–2 层，仍 64 颗） | 现在每颗弹独立编码，缝 / 通道这类局部结构只能靠池化后的 MLP 拼 |
| **R2** | 18 个动作 query（位移向量、换不换方向 / 低速位、`held`、朝目标点的进度 + 可学嵌入），对弹 token 交叉注意力 + 按动作最大池化 | 现在动作只在最后一层 logit 出现；目标点只从 query 进来 |
| **R3** | Perceiver 潜变量：K = 16–32 个可学 latent 对（最近 256 颗 → 最终全部 N 颗）弹做交叉注意力 + latent 自注意力，替掉密度图 | 全局态势；最终连「选哪 64 颗」这个手工规则也去掉（O(N·K)，ONNX 输入本来就是全部弹） |

设计要点（讨论记录）：
- **瓶颈会抹掉像素精度**：动作 query 应同时看 latent（全局）与最近 K 颗的原始 token（局部），不要只看 latent。
- **位置编码**用相对位置的 Fourier 特征，否则注意力分不清几个像素（这是表示分辨率，不算构造信息）。
- **算力**：PPO 更新已占每轮约四成；R3 对全部 N 颗时激活可达数 GB / minibatch，需 bf16 或先截到 256 颗。预计单条墙钟 4–6 h。
- **组合轮**：胜出的臂叠加，顺手把敌人并进弹的 token 集合（加类型位，见 spec §7 第 4 条）。
- **代码**：另起干净的特征化器（只输出原始 token，不再继承 v1–v6）+ 新模型用开关组合三个部件，R1–R3 与组合都只是配置。

## Q1 / Q2 结果（2026-09-25，Magnus A100 各一卡 22 核，约 2.5 h）

带运动层，末 4 次评测均值（跟点档主判据）；探针为 best.pt × 640 局（CPU）。M 行是旧语义下的 M（M0 已证实与之一致）：

| | M | **Q1**（自机不动） | **Q2**（无 d / t） |
|---|---|---|---|
| 跟点档（主判据） | 0.807 / 0.589 | **0.897 / 0.778** | **0.880 / 0.795** |
| 跟点率 · 方向/s · shift/s | 0.571 · 5.63 · 1.95 | 0.615 · 4.98 · 2.12 | 0.567 · 4.61 · 1.85 |
| 贴弹 `<12px` · 贴边 | 16.0% · 1.4% | 23.3% · 0.5% | 20.6% · 0.5% |
| 锚点档 | 0.916 / 0.659 | **0.991 / 0.887** | 0.972 / 0.875 |
| 自由档 | 0.925 / 0.753 | **0.978 / 0.887** | 0.966 / **0.909** |
| 部署口径 `boss_or_free_v1` @16 | 0.959 / 0.772 | 0.959 / **0.897** | 0.959 / 0.878 |
| 关掉运动层 | 0.944 / 0.844 | 0.938 / 0.878 | 0.934 / **0.922** |

- **判据（spec §6）**：Q1 相对 M 高 +9 / +19pp，远超种子噪声（中途种子差 5–8pp）⇒ **目标点耦合是有害的构造**。Q2 与 Q1 在噪声内 ⇒ **d / t 不需要**。
- **spec 的一条预测被推翻**：原以为自由档里 M 的 `vp` 本来就是 0，Q1 在那里应当与 M 持平。实际自由档 r3 +13 / +16pp、锚点档 +22pp。
  ⇒ 收益**不只**来自跟点档的目标点跳变。更可能的机制：M 的 token 随意图档位变化（同一颗弹在跟点档与自由档被编码成不同的样子），
  三档的数据各学各的；token 与意图解耦后，所有档位的经验都在训练同一套几何。
- **r2 → r3 的落差**从 M 的 22pp 缩到 9–12pp（跟点档）、自由档只剩 6–9pp。M 系列一直以为是「粗手在高密度下的能力上限」，现在看有一大半是表示问题。
- 部署口径 r2 已饱和（0.959，三者相同），r3 +11–13pp。关掉运动层时 Q2 的 r3 0.922，与带运动层的自由档 0.909 只差 1pp ⇒ 运动层的代价几乎消失。
- **要盯着的**：贴弹 `<12px` 16% → 21–23%（活得更好，但躲得更贴）——「神穿」那条线，拟人目标下要看。
- **3500 轮仍然需要**：u1500 → u3500 之间 r2 +5–8pp、r3 约 +15pp、跟点率约 +10pp，中途的横盘只是停顿（与 LR 退火混淆的可能仍在，「压缩到 1500 轮」的短跑对照未做，优先级降低）。
- ⇒ **Q2 转为新底子**（纯原始 token：相对位置、绝对速度、半径；按距离取最近 64 颗）。下一步的结构实验都以它为父。

### 反思：从哪里开始走弯路（2026-09-25 复盘）

- **病根在 09-15 设计文档 §3.4**：`v_p = unit(指令点 − 自机) × speed`，速度列、d / t、选弹三样都从它派生。无约束的 J 时代每帧可纠正，代价没被看见（J 0.92 / 0.88；没在 J 上测过 Q1 式 token，所以只能说「没看见」，不能说「是零」）。
- **第一次擦肩（09-20 诊断第二节）**：已发现排序键「假设自机全速朝锚点走」是错的，但只量了「凶手弹有没有入选」（≤ 0.8pp）就放下 —— 量的是漏选，不是表示稳不稳。
- **真正付代价从 09-20 运动层开始**：前馈规划需要稳定的输入，而每次换目标点整个弹幕表示跳一次。当时归因为「粗手 × 激进指挥 = 能力上限」，于是 N3 / M / L / O 四条都在这个前提下找增量（L +3pp、O 负结果）。
- **第二次擦肩（09-21 诊断第七节）**：量到了 Jaccard 0.44，也注意到「自由 / 锚点档没这个问题、恰是最好的两档」，结论却写成「给动作危险度特征**多了一条理由**」—— 发现输入被构造污染，开的药是再加一层构造。
- **教训**：① 诊断发现「输入被某个假设污染」时，先做拿掉它的消融（Q1 只改一行），再考虑换更好的假设；② 「已训好的模型依赖某特征」≠「该特征不可缺」；③ 环境改变问题性质时（反馈 → 前馈），把旧设计的假设逐条重审。
