# TH18 单攻击审核契约

独立审核本任务的 TH18 转写是否忠实于原文。只读卡，不改写作者产物。按 `brief.md` 指定的范围写 `verdict.json`，必要草稿与运行日志也留在自己的 cwd；不要改原作、映射、其他卡或全局状态。

语法与转换方法见[主线教材](../mapping.md)；按本攻击查[发射模式](../aim-modes.md)、[插值](../interpolation-modes.md)、[激光](../lasers.md)及弹型/EX表。读原作后独立推导锚点，不把教学例视为该攻击的既定答案。

按[统一转写口径](../transcription-policy.md)和[敌人状态/段入口](../enemy-state.md)恢复前置状态。**曲线激光暂时不做**：实际依赖Curve的攻击写blocked、注明源位置并暂缓；不删除、不用短线近似，不能审核为pass。未选rank或确实不可达分支不因此阻塞，但须给依据。

## 输入

读 `brief.md`、`source.txt`、作者的 `out/main.ecl` / `meta.toml` / `report.md` / `validate.json`、真实运行日志，以及本任务附带的 [弹型表](../bullet-types.md)、[EX 表](../ex-effects.md) 和涉及的详细条目。引用副本须与本次任务单的源路径与版本对应；复审使用刷新后的输入，旧 verdict 保留作历史。

作者自检、语义审核和原作动态对拍分开判断。共用 `stgtranscribe.validate` 已支持 [TH18 单卡规则](../validation.md)；核对目录编号/source、声明 rank、报告对应的实际目标文件，完整验收应包含开场安全。TH18 不以旧 3000 帧/1024 弹预算拒收。缺关键原文或目标映射就指出缺口，不依据卡内注释补原意。

## 核对

- 原文入口及依赖是否完整；调用/async/共享发射器、配置后改写、跳转脚本时间及发射顺序有没有被改变。
- 每个 type/color 的原作弹种、颜色槽、我方 appearance 和半径是否对应任务单；不要把 TH06 已接受差异自动套到 TH18。换型、缩放和半径覆盖是否保持顺序。
- 是否使用同批ENGINE_VER31表及 `TH18_*` 定义，源色号是否直接保留，是否误套旧换色表；外观共用时仍按作品区分半径。当前半径相加公式是已接受口径，未来算法选择不单独构成blocked或返工理由；基础表完成不能冒充动态半径写口。出生减速和出生无判定的省略按已批准规则审核。
- EX 的 opcode、id、index、type 是否混淆，WAIT signed 值是否正确；609/611 是否误清 c/d/m/n；追加游标和相邻数据记录是否保留。
- 各方向哨兵是否在换算弧度前解码；STEP 子模式、VELTIME 固定方向与 HOMING 持续追踪有没有混用。短表未解字段是否被作者擅自删掉。
- 当前角、玩家位置、随机量的取样时点和共享范围是否正确；是否出现取中值/量化/共享随机改逐弹随机，或 STEP/等待每帧重抽。
- 出生退位移/半速/碰撞门、WAIT/DELAY、同步/异步门、同 tick 续跑和派生弹程序继承是否按原文及已接受近似处理。
- rank、时间窗、坐标、段结束和元数据是否符合任务单；拒绝将 TH06 的 x/宽度/时序换算直接当成本作规则。

关键未知只按本攻击实际使用判断：不要求补齐未使用的 EX；实际使用但未解决的机制也不能仅写“近似”便判通过。

## 数值锚点

从 `source.txt` 及本作语义独立推导至少 3 条期望，再用任务单中的 harness `run --at` 实测。期望应写具体 rank、源帧/卡帧、弹数、速度、角度/几何或效果后果；不能抄作者注释和 report 的数字。优先选不同轮次、难度差异或效果生效前后，发弹不足时可补敌人位置/出场/退场锚点。

随机效果核区间、抽样阶段、同批共享关系及样本所能支持的结论，不要求匹配原作 seed 的逐抽序列；少量样本不能证明完整分布。最多 4 次 `--at`，未实际运行时不得称审核完成。

## 结论

沿用现有审核结果的 `verdict`、`findings`、`volleys` 字段：

```json
{
  "verdict": "pass",
  "findings": [],
  "volleys": [
    {"frame": 120, "rank": 0, "expected": "从原文独立推导的具体期望", "observed": "实际命令和输出"}
  ]
}
```

示例仅示字段，实际须有至少 3 条独立锚点。发现给出原文和目标代码位置、expected/actual，严重程度为 critical（形态/机制错误）、major（参数/时序/共享范围偏差）、minor（已接受范围内的表现差异或取整）。未获接受的判定/机制近似不能自行降为 minor。

无 critical/major、锚点满足且关键依赖已解决时才 pass；否则 fail 并指出返工或补证据的位置。没有跑数值检查时记录未完成，不能用静态阅读替代。主会话后续仍需执行既定抽检与逐条复核；本结论不等于 TH18 已批量收卡或训练验收。
