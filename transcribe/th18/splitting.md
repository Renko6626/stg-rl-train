# 高版本东方 ECL 切分指南

以 TH18 v1.00a 为已核实例。方法用于现代ECL的“关卡控制sub＋敌人脚本＋异步任务＋中断”结构；换游戏或版本时先核该作入口、eclmap和中断机制，不能把本页TH18编号直接当通用编号。本文仿照[TH06切分契约](../th06/contracts/split.md)，供主会话准备和AI切分使用，不负责写目标弹幕。

**Boss的符卡声明是首要定位锚点。** 先找声明，再结合中断表和实际可达路径确定一张卡的入口、攻击内容和结束条件。道中则从main及其调用链恢复出怪编排。最后将每个单元连同依赖和入口状态交给转写者。

目前TH18尚未接入 `stgtranscribe.pipeline split` / `split_check`。本页的步骤和记录模板用于人工或AI审阅，不是已实现的JSON接口；不要直接套TH06命令、字段限制或验收状态。

## 1. 切分前准备什么

主会话为一关提供独立工作目录，至少包含：

- `brief.md`：游戏版本、源文件路径与版本、普通流程入口、目标rank、范围和可写目录。普通难度0=Easy、1=Normal、2=Hard、3=Lunatic；Extra的源/目标对应单独写明。
- 原作解码文本和对应eclmap；列出 `ecli` 依赖及跨文件同名sub。原文只读，留在忽略目录。
- 结构摘要 `structure.md`：文件/sub列表、call/async、创建敌、设置中断、符卡声明、清场和等待点。当前可由主会话整理，不假设现有TH06摘要器可直接生成。
- [转写教材](mapping.md)、[普通指令索引](instructions.md)、[敌人状态/段入口](enemy-state.md)、[统一转写口径](transcription-policy.md)。

定位必须带文件和sub。最好再带源行、标签或指令位置；行号会随重新解码变化，需注明本次解码文件与版本。原作指令内的脚本时间、从关卡启动经过的时间和目标卡帧分别记录，不能都叫“帧号”。

## 2. 单元是什么

| 类型 | 切分目标 | 通常依据 |
|---|---|---|
| 道中波次 | 一个完整编队或确有互动的一组出怪事件 | main调用链、循环、创建时序、活动敌人尾部 |
| 中Boss攻击 | 一段非符或一张符卡 | 实际Boss对象、中断目标、声明和终止路径 |
| 关底Boss攻击 | 一段非符或一张符卡 | 同上，按普通实战路径排序 |
| 组合攻击 | 单独拆开就会丢失危险区或机制的重叠片段 | 共同生效的Boss/小怪、持续任务或跨边界实体 |

保留TH06的“单次可练习攻击”粒度。一个sub可能包含初始化、若干阶段或整关；一张符卡也可能跨多个sub和文件。不要按sub数量计卡，也不要把每次发射循环各切成一张卡。

## 3. 先确定普通关卡流程

1. 找该关实际入口，TH18常见为关卡文件的 `main`；它在原作也是控制敌的脚本，不等于目标STAGE任务。
2. 先分开普通实战、符卡练习、调试跳转和未选难度分支。只在练习模式进入的入口不另算一张实战卡；可以作为原作初始化的辅助证据。
3. 沿同步调用、async、创建子敌和跨文件加载追踪，标注谁负责排程、谁实际发弹。
4. 列出“调用某编队、等待、创建Boss、等待Boss、清场、对话、下一段”的事件关系。遇到跳转重设时钟，按[时钟案例](conversion-examples.md#案例一时钟循环)恢复真实等待。
5. 时间受 `bossWait`、存活条件、随机等待或玩家击破速度影响时，先保留条件。可以写“Boss结束后N帧”，不要猜出一个整关绝对帧。

并非所有sub都要展开成一张巨大逐帧表。先用调用位置、事件顺序、局部时间/条件恢复结构；只有影响边界或同帧顺序时才继续展开循环。动态目标、缺失文件或条件不明，记录最小缺口，不凭名字补流程。

### TH18一面的已核结构

普通流程从 `st01::main` 进入 `MainFront`，通过若干 `MainSubXX` 创建道中编队；之后创建 `st01mbs::MBoss`，再进入 `MainLatter`，最后经 `MainBoss` 创建 `st01bs::Boss`。`ecli` 引入default、Boss和中Boss文件。

这里有排程上的交叉：main创建MBoss后等待160帧就调用MainLatter；MainLatter先执行MainSub05，再等待200帧，之后才 `bossWait()`。但MainSub05使用 `enmCreateF`，Boss0仍存在时跳过创建，因此不能把排程交叉直接认定为固定重叠小怪。用户确认这是奖励提前击破中Boss的编队；训练切分按下节已批准规则，把它作为中Boss后的独立一波。

以上是结构事实，不是已经完成的一面切分结果。不要仅凭这些函数名直接输出整关波次数或卡数。

## 4. Boss：从符卡标记开始，沿中断链补齐非符

### 4.1 找声明，但不按出现次数计卡

TH18已核常见声明为537 `spell`；522 `spellEx`、538 `spell2`、539 `spell3` 等作为候选入口另核具体调用和该版本语义。记录源位置、符卡ID/标题表达式、难度条件、声明时长参数、是否耐久。字符串解码不清楚时保留原位置/字节证据，不能猜标题。

随后合并同一实战阶段的声明：

- 同一位置上Easy/Normal与Hard/Lunatic各一条声明，通常是同一阶段的难度变体，不是两张同时出现的卡。
- 宣言helper被正常流程与练习入口重复调用，不重复计卡。
- 同一helper被两个不同的实战阶段调用，也不能因为sub相同就强行合并；要带调用点和参数。
- 声明ID、标题、时长相同是线索，最终以可达控制流和阶段身份为准。

523 `spellEnd` 用来核符卡退出和清理，但可能写在下一段的开头；540 `stars` 是显示信息，不能独自确定阶段数或最后一张卡。

### 4.2 找“谁让这一段结束”

跟踪当前敌上每个中断槽最近一次有效设置。TH18的514 `setInterrupt`、521 `setTimeout`、HP阈值、计时器重置以及实际跳转目标共同确定退出路径；符卡声明参数里的时长不能无条件替代活动中断的超时。

每段分别记录：

| 内容 | 要回答的问题 |
|---|---|
| 入口 | 从哪个sub/指令位置开始？初始化、宣言、开场移动是否在另一个helper？ |
| HP路径 | 哪个槽、什么阈值、跳到哪里？ |
| 超时路径 | 使用哪个计时器和阈值？是否有独立timeout目标？ |
| 内部中断 | 是换整段攻击，还是同一张卡内部换一轮/子模式？ |
| 收尾 | 清哪些弹/激光/子敌，取消哪些async，是否仍有存活危险区？ |

TH18有多个槽，可能同时存在整场中Boss超时和当前符卡中断。不能把每次setInterrupt都算新卡，也不能只取代码里最后出现的一条就认定为活动槽。源计时器从何时归零、声明前的等待是否计入，都要沿实际路径核对。

非符没有符卡声明，可通过相邻中断入口、可重复攻击内容、下一张符卡/退场边界识别。非符和符卡都列入切分记录，不能只收有名字的符卡。

### 4.3 给每段找完整入口

通常选择“准备当前段→设置中断→宣言或非符前奏→攻击循环”的完整入口。单独从 `*_at` 发弹helper开始，常会漏掉移动、框、共享变量、发射器、并行任务和启动等待。

源把旧段清理放在新段入口时，记录这段清理归哪侧执行；前后不能漏掉或各执行两遍。切分是划定源行为范围，转写时再根据实际依赖决定如何重建单段外壳，不能在切分阶段擅自删掉清理与前奏。

TH18一面普通Boss链可确认如下：

```text
Boss（登场/公共初始化）
  → Boss1（非符）
  → BossCard1（符卡）
  → Boss2（非符）
  → BossCard2（符卡）
  → BossDead（收尾）
```

链上的段名只是本例事实。实际切分依据仍是调用与中断目标、声明、HP/超时设置。Boss里的符卡练习分支不再生成一套重复的BossCard候选，BossDead也不因名字是一个sub就算攻击。

## 5. 道中：切创建事件的编排，保留重叠和尾部

1. 从main和排程helper找出非Boss的创建事件。循环中的同一创建指令可执行多次，要按调用实例/循环范围记录，不能把源行当作一次出生。
2. 按编队、规律间隔、共同任务和场景变化划波次。TH06的“间隙≥100帧”只作参考，不作为现代ECL硬阈值。
3. 继续读这些敌的行为，确定它们何时停射、退场，及最后一批弹/激光还能存活多久。波次不能在最后一只出生时立即结束。
4. 遇到同步helper等待、async排程或 `bossWait`，分清父任务继续执行与敌仍在攻击两种时间线。
5. 本轮按用户已批准规则将相邻编队分开训练，不因跨波尾部重叠强制合并；明确记录原作重叠与训练独立场景的差异。同一波内部互相作用的编队不因此随意拆散。

覆盖要求针对**普通流程的创建事件归属**：每个事件实例应有一个主归属，若作为其他候选的必要上下文再次出现，要注明引用关系。共享helper允许被多个单元引用；不能用“每个sub恰好归一个单元”检查覆盖。

条件性对话或Boss结束后的等待没有固定绝对帧时，保留边界条件与局部偏移。候选时限记录源依据与尾部估计，不能先钳成3000或为了适应旧工具先砍轮数；目标练习时限由后续任务单另定。

### 已批准：波次尾部重叠先分开训练

2026-11-05用户确认，道中波次尾部重叠暂不妨碍分开训练。保持目前按编队划定的独立单元；新卡不必携带上一波的敌人/尾弹，也不因原作跨波危险区仍存活而强制合并或继续卡住切分。

保留本波自己的出怪、移动、发射、回调等攻击内容；本波尾部和结束时限在转写时具体安排，不因这项授权删掉本波内部后续发射。原作存在重叠、训练采用独立波次的差异写入记录。同一波内部的共享et、未知物理行为或主动发弹仍保留；用户随后确认波次/阶段交接的精确位置、清场与回调暂不追逐帧复现，不能再把这些交接差异作为当前切分硬阻塞。

### 已批准：击破速度奖励编队独立成波

2026-11-05用户说明，Stage01的MainSub05使用enmCreateF奖励提前击破道中Boss；训练数据可以将它作为**道中Boss之后的独立一波**。对已确认属于这一用途的编队，采用以下规则：

- 原作仍记录“Boss0存在则跳过创建”的事实；训练中固定为Boss已结束的场景，完整保留奖励编队，不再根据原作实际击破时刻裁掉前半批。
- 单独从奖励排程入口计时，保留编队自身等待、循环、位置/参数快照、难度和敌人行为；不带入上一场Boss已运行多久的条件。
- Stage01 W05入口为MainSub05：保留其先wait100、两轮各20个计划创建实例，共40个；不附带main创建MBoss后wait160的上游时间。末次计划创建在波内760，排程返回在860；这些是源排程局部偏移，不是目标卡实际全局帧。
- 不要求保留上一场Boss及其残留危险区作为该奖励波的必要上下文。编队自身的尾部、共享变量、死亡回调和未解指令仍按原文处理；此次决定不批准额外删行为。
- 切分记录注明“原作为击破速度条件奖励，训练固定为Boss后完整独立波”。该条件本身不再列为待补/blocked；其他确实影响转写的缺口继续具体列出。

这是已批准的训练场景整理，不宣称复现原作在任意击破速度下的整关时间线。仅对已确认的奖励编队使用，不能把所有enmCreateF或其他条件分支都无条件放行。

## 6. 每个候选必须交接的依赖和前置状态

源闭包至少包含：同步调用、async创建/终止、子敌、EX创建的子敌/后续程序、激光控制、实际中断目标和跨ecli依赖。**中断后继要作为边界证据，不默认递归吞入下一张卡**；跨界仍存活的对象及其程序按需要另列。

给出入口状态的来源，不只列最终值：

- 出生/段入口位置、ABS/REL移动层、方向/速率、在飞插值、镜像、限位。
- 同敌I/F槽、参数、全局/父敌值，以及它们是快照还是持续共享读取。
- 各et槽字段、offset、EX记录、追加游标；同敌async对配置的共同写入。
- 受击/体碰框、flags、无敌/临时禁碰计时。
- 已运行的async、子敌、存活子弹/激光与相关句柄；源边界是否确实清掉它们。
- 难度、计时器基点、首次发射延迟、HP/超时终止路径。

细节沿用[敌人状态与段入口](enemy-state.md)。找不到来源就写未知，不用目标默认值填空。这里收集的是转写输入，不要求切分worker实现一个完整现代ZUN VM或运行整关。

## 7. 可转、待补和曲线激光暂缓

先把边界和依赖完整记录，再判断当前是否可交给转写：

| 标记 | 含义 |
|---|---|
| 可交接 | 入口/结束、rank、闭包和必需状态已明确；具体转写仍需编译/运行/审核 |
| 待补证据 | 入口值、分支、时间或依赖缺失，指出所缺内容 |
| 暂缓 | 实际所需机制当前不可表达或用户明确排除，注明源位置与影响 |

这些是切分记录里的人工说明，不是现有pipeline的新状态。**曲线激光暂时不做**：实际执行711 `laserCuOn` 或依赖存活Curve的候选仍要列出，标暂缓；后续作者report写 `status: blocked`。不删掉曲线、不用短线替代，也不直接漏掉整张卡。未选难度/确证不可达分支中的曲线，给出依据后不影响当前范围；其他独立单元继续。

直线激光不因含laser就跳过。未知opcode也按实际影响判断，不能仅凭函数名、全文件出现过曲线或别作skip表给全关下结论。

## 8. 建议的切分记录

当前在工作目录写 `split.md`，方便人和后续转写worker审阅。单元名按[编号约定](validation.md#编号)填写，主会话确认切分后固定；以下模板不冻结未来机器格式，不替代TH06的split.json。

```text
游戏/版本：th18 / v1.00a
关卡：1
输入：各文件路径、游戏及eclmap版本
普通入口：st01::main；练习/调试路径另列
范围：rank0..3，普通实战

单元：th18_s1_b1                 # 单卡 validate 已识别；切分本身仍需静态审阅
类型：关底Boss / nonspell
入口：st01bs::Boss1 + 指令位置/源行
前置：st01bs::Boss中的公共配置，逐项引用来源
宣言：无；相邻符卡入口为BossCard1
结束：列活动槽、HP/超时条件与对应目标，附源位置
计时：源计时器及重置点；原超时值；无依据时标未知/估计
难度：源条件→目标rank；不同入口/结束条件分别列变体
依赖：同步/async/子敌/跨文件，按关系列来源
并行与遗留：仍存活的任务/敌/弹/激光，清理归属
入口状态：已知值及设置位置；未知项单列
主归属事件：本单元覆盖的创建/阶段实例
上下文引用：重复使用的helper/创建实例及必要原因
处置：可交接 / 待补证据 / 暂缓，原因及源位置
note：只写已核事实，不猜测运动方向、参数含义或标题
```

末尾附一张总表：顺序、类型、入口、难度、声明位置、终止依据、处置、待补项。源rank不连续且行为/可达范围不同的，可分列变体；不要为了套旧 `[lo,hi]` 格式把中间并不存在的难度补进去。

## 9. 自检与交付

切分者按以下项目自检，独立审核者沿源路径复核：

- 普通流程的创建事件和Boss攻击是否覆盖；暂缓项也列出，不含重复练习/调试卡。
- 同一阶段的难度声明有没有重复计卡；共享helper是否错误合并不同阶段。
- 每个非符/符卡的入口、声明、结束和时钟基点是否有源位置；缺证据是否明确。
- 中断的HP/超时/整体计时槽是否分清，是否误把内部中断当作新卡。
- call/async/跨文件及子敌/EX闭包是否够用；下一段有没有被依赖遍历误吞进来。
- 前奏、入口状态、重叠小怪、残留危险区与尾部时间有没有漏掉。
- 曲线暂缓与其他能力边界是否按当前规则处理。

不要运行TH06 `split_check` 并将其结果当作TH18验收；harness也只能检查目标ECL，不能证明源切分覆盖。当前交付结论应写“已静态切分/仍有哪些待补”，不声称机器覆盖检查、原作动态验证或训练收卡完成。

完整交付是 `split.md` 加原文/引用路径与必要说明，不包含原作全文的版本化副本，不写目标 `.ecl`。接手转写者按[转写契约](contracts/transcribe.md)获得独立brief和source摘录；具体机器格式、自动摘要/切分检查留到后续接入任务决定。
