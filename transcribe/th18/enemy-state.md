# TH18 敌人、移动层与段入口状态

> **版本**：TH18 v1.00a；目标 ENGINE_VER30，2026-11-05 静态核对。

本表补充[教材 §3–4](mapping.md#3-时间调用栈和并行任务)，适用 TH18 v1.00a；目标为 2026-11-05 的 ENGINE_VER30。重点是单攻击转写时必须重建的状态，不要求恢复完整战斗。原作依据为既有 `functions.jsonl` 导出，只读提取；没有运行原作，也没有修改引擎。

## 1. 敌默认判定与 flags

| 状态 | TH18 已核事实 | 目标处理与边界 |
|---|---|---|
| 受击框 `500 setHurtbox` | handler 写敌 `+0x133c/+0x1340`；默认两值都是24.0。伤害路径在普通圆形模式取第一值×0.5，矩形分支另取宽高 | `set_hurtbox(r)` 管被自机弹/伤害区打中；目标默认 r=16。普通受击圆的源24对应源半径12，但这不证明两边完整伤害规则一致 |
| 体碰框 `501 setHitbox` | handler 写 `+0x1344/+0x1348`；默认两值也都是24.0 | `set_hitbox(r)` 管敌撞自机；目标默认 r=12。原作普通体碰调用使用寄存器传参，现有高层反编译漏显半径，本文不据默认24断言体碰换算公式。不能套 TH06 `min(w,h)/3` |
| 无敌 | 原作永久位与倒数计时器分别存在；无敌不自动关体碰 | `set_invuln(frames)` 是0..65535帧倒数，不是永久位。单段无敌须覆盖整段时长；不能仅因敌无敌就省掉体碰 |
| 临时禁体碰 `541 noHitboxDur` | 本作逻辑检查独立 `no_hitbox_timer` | 可在明确单一写者、已保存原状态的样本中设置 `ENEMY_NO_BODY`，等待后恢复；并发覆盖与恢复顺序需另核 |

`set_hitbox`、`set_hurtbox`、`set_enemy_flag`、`set_invuln` 都要求敌 owner。关卡 `main` 为 STAGE owner；把初始化放进新敌的主任务，再启动其发弹任务。目标 `ENEMY_NO_BODY` 只关体碰，仍可受击；需要两种都关时要分别表达。源宽高不等、旋转框或自定义碰撞函数不能用一个圆半径宣称准确复现；确实影响避让时标 `blocked` 或等待明确近似方案。

以下仅列本轮从 TH18 handler/消费者核到的位子集。数值属于原作 `enemy+0x635c`（即 `EnemyData+0x5130`），**不能原样传入目标 `set_enemy_flag`**。

| 原位 | 已核消费者/行为 | 转写边界 |
|---|---|---|
| `0x2` | `0x42ed40` 体碰入口检查 `flags & 0x22 == 0`；受击入口检查的是 `flags & 0x21` | 仅这一位的禁体碰用途可表达为 `ENEMY_NO_BODY`，清位反向映射；同时存在其他禁体碰原因时不能盲目清目标位 |
| `0x10` | 同函数伤害扣血路径要求该位为0且无敌计时器到期 | 只核到阻止扣血；`set_invuln` 有期限且目标事件行为不同，不等于复制整位 |
| `0x20` | 同时进入受击门 `0x21` 与体碰门 `0x22`；502/503还遍历ANM做状态操作 | 同时影响交互及动画，不能只解释成禁体碰或纯外观；按样本拆出必要行为 |
| `0x1000` | 伤害路径选择圆/宽高分支；体碰也切到另一几何路径 | 不能作为目标公开 flag 写入；形状/朝向按实际消费者核 |
| `0x20000` | 移动限位开关，504写入四边界并置位，505清位 | 目标无常驻限位写口，见 §3 |
| `0x80000` | 镜像开关；424按参数置清，创建helper也读取 | 保存在脚本状态；按具体移动指令与创建顺序处理，见 §2–3 |

目标公开可写另有 `ENEMY_KILLALL_EXEMPT`，但本文未确认一个能覆盖 TH18 所有清场入口的单一源位。原生清场 `0x430710/0x430910/0x430b20` 检查复合掩码 `0xc004a0`，并有 `0x100` 例外；不能从 TH16 表拷一个位号就声称等价。

## 2. 创建子敌：名字与继承顺序

精确助记名以本机 `th18.eclm` 为准。`A` 族使用绝对坐标；它不是异步标记。下面的“相对”是在父镜像处理之前，加父最终位置；不是加父 ABS 或 REL 单层坐标。

| opcode / 助记名 | 父镜像处理前的出生位置 | 子镜像初始位 | 附加条件 |
|---|---|---:|---|
| 300 `enmCreate` | 父 FINAL + 输入(x,y) | 0 | 普通创建 |
| 301 `enmCreateA` | 输入(x,y) | 0 | 普通创建 |
| 304 `enmCreateM` | 父 FINAL + 输入(x,y) | 1 | 普通创建 |
| 305 `enmCreateAM` | 输入(x,y) | 1 | 普通创建 |
| 309 `enmCreateF` | 父 FINAL + 输入(x,y) | 0 | F分派先检查boss0是否仍可找到 |
| 310 `enmCreateAF` | 输入(x,y) | 0 | 同F条件 |
| 311 `enmCreateMF` | 父 FINAL + 输入(x,y) | 1 | 同F条件 |
| 312 `enmCreateAMF` | 输入(x,y) | 1 | 同F条件 |

`0x4369e0` 中，若父 `0x80000` 置位，**在上表加父坐标之后**再把最终出生x取负，并翻转子镜像初始位；y保持前一步结果。于是普通相对创建在父镜像下的x是 `-(parent_final_x + input_x)`，不能改成 `parent_final_x - input_x`。这是创建helper的静态事实，不应外推为所有移动或发弹指令的统一镜像规则。F族检查在 `0x430d30` 的共享分派分支中，找到boss0则不执行普通创建路径；不要凭F名字解释为“继承全部flags”。

用户确认Stage01 MainSub05的F创建用于奖励提前击破道中Boss。训练切分已批准将该奖励编队固定为Boss后的完整独立一波，保留编队内部时序和参数，见[切分口径](splitting.md#已批准击破速度奖励编队独立成波)。这不改变上面的原生F门语义。

创建helper还打包父4个int和8个float槽的12值快照及父敌ID。本机TH18 eclmap将它们命名为 `I0–I3/F0–F7`（F4–F7位于-9935..-9932）；不要误用只列F0–F3的旧摘要当作完整变量表。目标 `spawn_enemy` 返回不透明句柄，不能把原作ID直接当目标句柄；目标新敌共享槽默认清零，按实际读取传参，并在子主任务首部 `set_self_int/set_self_fx` 初始化。共享值转 `fx` 或 `angle` 时按用途换单位，不能把浮点位模式原样塞进去。原作score/item与目标drop_table/score/sprite顺序不同，须逐参重排。

子敌初始化清单：

1. 确认具体创建变体、父FINAL与镜像状态、F条件是否成立；记下实际出生坐标和首次执行帧。
2. 追踪子敌会读的继承槽、父ID/跨敌查询、传参的求值时点；只读快照与持续读父状态分开。
3. 确定子敌自己的框、交互flags、无敌、移动层和发射器初始化；**没有证据时不继承父et配置/出弹偏移**。
4. 在子敌首部完成共享槽/判定设置后，再启动依赖它们的async；同敌所有async共用敌槽，目标各任务的 `sh_*` 配置却独立。
5. 核子敌退场与父退场关系、屏外继续发射时间、存活查询和取消路径。目标出生次帧首跑，不能仅靠创建坐标正确就认定调度等价。

旧 `renkolab/engine/ecl/th18/05-stage1-midstage-spawns.md` 的创建变体表存在错位与“A=async”的旧说明；本表以当前eclmap及本作 `0x4369e0` 为依据，不沿用该解释。

## 3. 绝对、相对、镜像与限位如何组合

TH18有ABS与REL两套PosVel状态，并由 `0x42ec00` 合成最终位置。`402 movePosRel` 是写REL层，不能泛化为“给当前世界位置加一段偏移”。两层都在运动、插值未结束或读回ABS/REL变量时，单次 `move_to` 无法保留这些状态。

对一个具体样本，先列以下状态，再选实现：

| 必须恢复的状态 | 目标路径 | 必须检查的差异 |
|---|---|---|
| 仅一层位置、另一层恒零、无残余速度 | `move_to(dur,x,y,EASE_*)` | 原400写位置不必然清速；目标 `move_to(0,...)` 会硬停并清在飞插值，不能机械替换 |
| 单层极坐标速度 | `move_vel`、`move_angle`、`move_speed` | 源角用弧度，目标BAM；目标转角走最短弧，源角轨迹必须核；静止时保留脚本角状态，不靠速度推角 |
| ABS和REL共同改变位置 | 保存两层位置/速度/插值状态，每帧算本帧两层贡献，再写目标位置 | 源更新、脚本读取、发弹、目标积分的相位须逐帧核；属于组合方案，不是现成双层内建 |
| 镜像开启 | 在实际指令写入点显式换算x/角/角速度，并保存开关 | `428–431 moveVelNM*` 是需要单独核的非镜像路径；不把镜像自动施加到发弹角、offset或全部坐标 |
| 504/505限位 | 样本若从不到边界可证明无效；确实到边则按帧夹位置 | 仅夹最终目标点不能替代每帧限位；当前没有原生常驻约束，碰边速度、ABS/REL回写和发弹相位未证等价 |
| 随机/圆周/椭圆/Bezier/追敌 | 先用源handler、实际参数和插值表恢复轨迹 | 不把 `moveRand` 套TH06 wander公式，也不把名字相近当精确配方 |

目标 `move_to` 会停止旧速度缓动并清除先前的速度意图；要在位置补间结束后继续飘，须在 `move_to` **之后**调用速度动词重新设置，位置补间活跃期间速度可推进但不叠加位移。将速度写在move_to前面再期望到点自动恢复，会丢掉这条意图。

组合顺序应记录为“指令写哪一层、是否受镜像、各层如何推进、何时合成、限位何时夹、发弹读取哪个位置”。不要自行认定统一顺序后套全库。本轮没有补全所有原生移动消费者；尤其复杂轨迹、镜像+双层+限位的完整组合仍属 `需上下文`，要求准确而又无法证明时 `blocked`。

## 4. 同一敌人的段入口：恢复状态而非重置模板

HP/超时中断、外部换sub通常仍在同一只敌上运行；新sub的第一行不是新敌出生。TH18的八槽HP/超时表与 `time_in_ecl` 已有本作证据，`time_alive` 又是另一计时器。`513 timerReset` 不可据名字当成清空所有时钟，`TIME`、TIMEOUT和脚本时间也不能合成一个计数。

独立取一段时，沿调用者与前一段找最近一次写入，至少交接：

- 实际位置、ABS/REL层、速度/方向、在飞插值、镜像和限位；入口前尚未完成的移动不能默认为静止。
- 受击框、体碰框、形状、相关flags、临时禁碰/无敌剩余时间。段中没有设置不代表使用构造默认。
- I/F槽、局部参数、跨敌/全局值和难度分支；保留共享与快照差别。
- 每个et槽的普通字段、offset、EX记录与追加游标；目标每任务4槽，不能把前段配置遗漏或跨async假共享。
- 仍存活的子敌、async、子弹、激光及句柄；中断到底取消哪些任务、留下哪些实体。
- 攻击首发相对入口的延迟、已消耗的随机读取、使用的计时器，以及这段终止依据。

若用户已指定固定rank、单段无敌练习，段外完整血线/UI/收卡流程可按任务单裁剪；先证明它们只在外壳边界生效。**攻击内部**回调若会再次发弹、切换配置、移动、生成/删除子敌、解冻、清弹或取消async，仍是攻击内容，不能因为名字叫“回调/中断”就整条删除。目标 `spell_begin/phase_begin` 管自身段生命周期，不是原作通用八槽中断表；`556 setDeath` 也不能写入目标死亡脚本字段就声称已执行回调。

取消边界同样重要：原 `17 killAsync` 按同敌用户ID查找，`21 killAllAsync` 遍历同敌async；目标 `kill` 的任务标识与 `KILL_CHILDREN` 的直系子树范围不同。只有能静态证明有限任务集合、取消对象和帧顺序时才改写；其他情形保留缺口，不加未经批准的通用任务管理机制。

## 6. Stage01试切后补核的非阻塞项

以下复用TH18既有Ghidra导出、社区labels与项目pe_read的只读跳表数据核对，不新建库、不自行反汇编。opcode助记名保持当前eclmap原名；unknown名称不等于功能未核。

- **573 unknown573、574（thecl显示ins_574，eclmap未命名）**：handler分别为 `0x433a4a`、`0x433a70`，调用 `0x42d020/0x42d040` 写限时额外掉落及窗口/计时。已有renkolab `engine/ecl/th18/02-item-drops.md` §5.1–5.2也已说明；这些属于击破速度奖励掉落，不是等待/发弹配置，按普通道具省略。
- **569 unknown569、570 unknown570**：handler `0x4338ab/0x433904`。569写敌 `+0x6828` 的章内计数权重，调用 `0x439ec0` 增加统计；570在自身chapter匹配当前chapter时，经 `0x439eb0` 结算并清零该权重。对应写口只累加章节统计字段，未写运动/发射配置。更上层评分用途未完整追踪，但不因其unknown名字阻塞Stage01独立攻击切分。
- **401 movePosTime在frames≤0时**：分派走 `0x431bbf`，调用 `0x439900` 只清该位置插值的持续字段；本支不把参数x/y写成当前坐标。因此Boss换段的 `movePosTime(0,0,0,0)` 不能改成目标 `move_to(0,0fx,0fx,...)` 瞬移。后续正时长移动仍从当时位置起步。
- **525 enmKillAll与死亡回调**：分派经 `0x434e1b` 调 `0x430710`，对通过源flag过滤的敌调用 `0x430240`；该函数执行非空setDeath程序。不能把原作清敌都解释成无回调静默删除。571的另一清场路径 `0x430b20` 则先清回调字符串。源事实已能区分；训练交接是否保留这些尾部按[用户已批准口径](transcription-policy.md#系统性省略与外壳接管)，不再要求逐帧复现跨波过程。

这些补核解除“名称unknown/零帧移动不明/清场是否能触发回调”的笼统疑问，不意味着已经实现每个目标行为。用户现已接受波次/阶段交接的训练牺牲；切分者列清当前攻击本体、依赖和原作差异即可继续，真正改变本波内部危险区且尚无做法的内容才具体标待补。临时原生函数和hash在 `transcribe/work/th18-stage01-blockers-20261105/`，原文不入库。
