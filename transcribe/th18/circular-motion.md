# TH18 圆周与椭圆运动：脚本方程配方

用户已明确选择用现有 ECL 脚本表达运动方程，并接受舍入、浮点尾差和零点几像素级差异。**不要求复刻原生逐层百分位 floor，不增加仿 f32 或误差补偿机制。** 保留参数语义、轨迹尺度/方向、入口快照、主要周期及基础时序。具体许可见[统一口径](transcription-policy.md#已批准圆周椭圆保留语义与基础时序容许细小数值差异)。

本页给出已核的方程和目标表达路线，整卡仍需作者实现及后续验收。

## 参数与方程

| 指令 | 参数 | 作用层 |
|---|---|---|
| 408 / 410 `moveCircle` / `moveCircleRel` | θ, ω, r, d | ABS / REL |
| 409 / 411 `moveCircleTime` / `moveCircleRelTime` | T, mode, ω目标, r目标, d目标 | ABS / REL |
| 420 / 422 `moveEllipse` / `moveEllipseRel` | θ, ω, r, d, β, s | ABS / REL |

θ是相位，ω是每帧角速度，r是半径，d是每帧径向增量；β为椭圆轴角，s为该轴的缩放比。源角单位为弧度，目标使用BAM；位置为像素。原结构的speed字段在圆/椭圆模式中保存ω，angle字段保存θ，不能按字段名字当成线速度/切线方向。

普通dt=1、无位置插值接管时，每个运动tick先推进活动插值，再计算：

```text
r ← 插值后的r + 插值后的d
θ ← wrap(θ + 插值后的ω)
```

没有活动插值的量沿用上一帧。圆周位置为：

```text
P = C + r * (cos θ, sin θ)
```

椭圆位置为：

```text
δ = θ − β
u = s * r * cos δ
v =     r * sin δ
P.x = C.x + u*cos β − v*sin β
P.y = C.y + u*sin β + v*cos β
```

先取角差、缩放局部横分量，再旋回β。s=1退化为同相位的圆；s=0退化为：

```text
P = C + r*sin(θ−β) * (−sin β, cos β)
```

**本批13个道中单元全部使用s=0、d=0。** 因而只需在ABS运动上叠加一个固定轴的正弦偏移。β在设置时求值；即使参数写的是`%ABS_ANGLE`，之后ABS转向或负速也不会自动旋转这条轴。REL是独立位置层，最终位置按ABS+REL合成，不能把两条目标移动内建当作自动叠加。

## 设置与Time的基础时序

- 非Time setter在执行当下用当前θ/r求位置并合成FINAL，**不先加ω/d**。同帧后续发弹会读这个新位置。
- 非Time setter仅在旧模式不是圆周mode2时，将当前这一层的位置抓作C。圆→圆、圆→椭圆保留旧中心；椭圆→椭圆或椭圆→圆会重新抓中心。不要统一写成每次重抓圆心。
- `CircleTime`的正时长分支不重抓C；它插值ω、r、d，**没有目标θ参数**。首次推进发生在下一运动tick；T≤0只取消相关插值，不瞬移到目标。
- 半径插值活跃时，每tick先得到插值r，再加该tick的d；插值结束后继续以d推进。当前五面样本d=0，所以就是按时长展开/缩回半径，θ持续累加。
- 一般原生顺序是运动→主ECL→已有async→后续逻辑；新async下次遍历首跑。设置指令在ECL内部还会即时更新位置，这一点须另外保留。

普通镜像位不直接作用于这组圆/椭圆setter和消费者；出生坐标、此前普通moveVel等指令的镜像结果仍须按源保留。限位先夹FINAL再回写ABS，不改圆心或相位；本批道中新生敌及五面子敌不继承父Boss限位，六面本段显式取消限位。

## 94：即时椭圆取点

2026-11-06补核。`ins_94(resX,resY,phi,radius,axis,ratio)`使用同一椭圆方程计算相对原点的坐标，前两个参数为输出引用；这里没有圆心参数，也不建立运动状态、不等待、不自动改敌位置。

```text
t = phi - axis
u = radius * ratio * cos(t)
v = radius * sin(t)
resX = u*cos(axis) - v*sin(axis)
resY = u*sin(axis) + v*cos(axis)
```

ratio=1时恢复圆上的相位phi；ratio≠1时输出点的极角通常不等于phi，不能改写成“朝phi方向的射线与椭圆交点”。当前源调用为`ins_94(%M,%N,%D,%G,%H,%J)`：D=phi、G=radius、H=axis、J=ratio，M/N随后交给`etOffset`，形成相对敌FINAL的发射口偏移。先用当前H计算，之后才H+=I；C是独立发射方向，发射后才递增C/D，原Easy/Normal修正和等待保留。

两处源位置为`st06bs:208–217`、`1432–1441`，覆盖s6_b1/b3/b5/b7/b9。参数全是本地变量，结果同帧写回，现有ECL用临时u/v和sin/cos即可表达，无需新接口。

## 用现有ECL表达

本批参数子集可用普通变量、`sin/cos/atan2`、既有敌共享槽和移动写口表达；未发现需要新增圆/椭圆接口的依据。只保存本卡实际需要的状态，不建立通用原作移动VM。

移动主任务保存ABS状态及REL的C/θ/ω/r/β；多数道中发弹只读最终位置，不需共享完整运动状态。五面圆子敌可用一个现有共享整数槽发布逻辑θ，给激光任务读取。θ必须独立于目标`$self_angle`，后者可能是位移差的方向。

目标执行顺序为ECL→积分→碰撞，可沿已有[moveRand配方](movement.md)预置下一运动点的位移：

```text
当前任务先读对应源本帧的F(k)
执行源设置；若设置即时改位置，用move_to(0, ...)使本帧新位置可见
按原顺序发弹，使用本帧位置和独立的逻辑相位
计算F(k+1)，用move_vel_xy(0, F(k+1)−当前位置, EASE_LINEAR)安排下一步
wait(1)
```

`move_to(0)`会清目标速度和插值，源逻辑状态须另存；不能每帧无条件瞬移。跨async的共享值与发射器写序按具体卡安排，不额外启动互相竞争的位置写任务。主要等待/首发/周期照原文保留；目标帧末体碰相位的既有差异仍须在卡报告中说明，新的精度许可不等于任意更改时序。

按用户批准，目标无需复制原生百分位floor或CRT/f32边界细节，使用现有fx/angle三角运算即可。固定周期可从帧计数计算相位，保持主要周期；无需设计通用高精度补偿。舍入尾差不能再单独作为blocked或返工理由。
