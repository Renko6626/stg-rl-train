# TH18 ECL 转写总体纲要

适用 **TH18 v1.00a**。本书用于把原作ECL按独立攻击转写为stg-engine训练卡；其他高版本作品可沿用组织方式，指令编号、参数和行为须分别核验。

## 三层资料

| 层次 | 内容与入口 | 什么时候读 |
|---|---|---|
| 总体纲要 | 本页：任务边界、执行模型、查询顺序 | 初次接手，了解各文档职责 |
| 原作指令表 | [instructions.md](instructions.md)：编号、名字、顺序参数、参数语义、已核范围 | 读到具体调用，先查它的含义 |
| 子系统专题 | 下表：共享状态、时序、方程、目标配方、示例与限制 | 指令涉及复杂机制或需要组合目标实现 |

原作参数定义集中在指令表，专题只在解释公式或配方时引用必要参数。目标语法与API签名以任务提供的引擎 `docs/ecl-lang.md` 为准。原作TH18行为与已批准转换许可由本书维护；引擎手册中泛指ZUN/TH06或“原作尚未核”的旧说明不覆盖本书的TH18专用结论。同一目标API的行为若确实矛盾，交主会话核清。

## 一张卡怎么读

1. 从task/source确认入口、结束、难度、必要初始化和源帧／卡帧关系。主会话交接边界；作者不恢复整关流程。
2. 先读懂反编译中的难度掩码、裸值压栈和栈索引，再查指令表。恢复每条实际调用的参数，不能逐参数独立pop。
3. 按涉及的子系统查专题，保留本卡的状态共享、取样时点、主要轨迹和内部时序；直接使用已批准的省略与精度口径。
4. 用引擎公开API组合目标卡，执行角色说明规定的自检或独立审核。编译／机器验收通过只证明目标程序的运行约束，不等于源语义正确。

参考库按需查询，无需通读。作者和审核职责已经由执行器注入，不再重复读取本作旧契约；具体检查次数、报告和verdict格式只由通用角色说明规定。

## 贯穿各子系统的执行模型

- **时间**：指令时间标签是脚本时间门，wait与跳转可能改脚本时钟；世界帧、脚本时间、敌存活时间和段超时计时器分开理解。
- **状态归属**：局部栈属于调用上下文；I/F与发射器配置属于敌，多个async可共享；目标任务的发射器槽却各自独立。源ID也不等于目标句柄。
- **位置**：敌有ABS与REL两层，FINAL为最终位置；出生继承、镜像、限位、发射口各按自己的规则合成。TH18不套TH06的x减192。
- **取样与相位**：配置、每弹出生、效果进入、持续更新是不同时间。随机数／玩家位置在哪一步读取要保留；源移动→ECL与目标ECL→移动的差异按专题配方处理。
- **外壳与差异**：训练采用独立无敌躲弹场景；普通奖励、纯表现、出生阶段及波次交接按公共口径处理。曲线激光依赖暂缓，不删除危险区或自行换形。

## 遇到缺口

指令表区分本作已核、部分已核、社区说明与待核。社区来源不自动构成阻塞，也不要求作者重做验证；具体未知字段或冲突按实际影响处理。源定义明确但需要调用前状态时，先读task/source；给定资料缺状态则交准备者。源定义缺失或互相冲突时，报告具体源位置、疑问和影响，由主会话补回对应条目／专题。源行为明确但没有通用目标配方时，作者可用公开API组合；无法表达则交回，不猜测、删行为或自行逆向。

配方的样本条件仍有效；一个已验证样本不代表所有mode、并行组合和其他作品都支持。已获准的简化不重新变成缺口，未使用或确证不可达的机制也不阻塞当前卡。
