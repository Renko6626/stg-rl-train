# TH16 敌人、移动层与段入口状态

适用TH16 v1.00a。

本章补充[基础语义§3–4](mapping.md#3-时间调用栈和并行任务)，提供本卡所需的状态规则。入口状态由工作包交接，不要求作者恢复整场战斗。

## 1. 敌默认判定与 flags

| 状态 | TH18 已核事实 | 目标处理与边界 |
|---|---|---|
| 受击框 `500 setHurtbox` | 默认两值都是24.0。伤害路径在普通圆形模式取第一值×0.5，矩形分支另取宽高 | `set_hurtbox(r)` 管被自机弹/伤害区打中；目标默认 r=16。普通受击圆的源24对应源半径12，但这不证明两边完整伤害规则一致 |
| 体碰框 `501 setHitbox` | 默认两值都是24.0；普通圆体碰分支取第一值×0.5 | `set_hitbox(r)` 管敌撞自机。普通圆形setHitbox(24,24)对应r=12，(48,48)对应r=24；不套TH06的min(w,h)/3，不外推矩形、旋转框或自定义判定 |
| 无敌 | 原作永久位与倒数计时器分别存在；无敌不自动关体碰 | `set_invuln(frames)` 是0..65535帧倒数，不是永久位。单段无敌须覆盖整段时长；不能仅因敌无敌就省掉体碰 |
| 临时禁体碰 `541 noHitboxDur` | 本作逻辑检查独立 `no_hitbox_timer` | 可在明确单一写者、已保存原状态的样本中设置 `ENEMY_NO_BODY`，等待后恢复；并发覆盖与恢复顺序需另核 |

`set_hitbox`、`set_hurtbox`、`set_enemy_flag`、`set_invuln` 都要求敌 owner。关卡 `main` 为 STAGE owner；把初始化放进新敌的主任务，再启动其发弹任务。目标 `ENEMY_NO_BODY` 只关体碰，仍可受击；需要两种都关时要分别表达。源宽高不等、旋转框或自定义碰撞函数不能用一个圆半径宣称准确复现；确实影响避让时标 `blocked` 或等待明确近似方案。

以下仅列TH18研究核到、在此供TH16对照的位子集。数值属于原作敌flags，**不能原样传入目标 `set_enemy_flag`**。

| 原位 | 已核消费者/行为 | 转写边界 |
|---|---|---|
| `0x2` | 体碰入口检查 `flags & 0x22 == 0`；受击入口检查的是 `flags & 0x21` | 仅这一位的禁体碰用途可表达为 `ENEMY_NO_BODY`，清位反向映射；同时存在其他禁体碰原因时不能盲目清目标位 |
| `0x4` / `0x8` | 分别跳过横/纵屏外回收；TH18五面首符flag303实际同时使用 | 目标敌仍有出界回收。无交互、无其他实体查询的发射体可按值任务保存独立世界坐标，坐标用普通变量保存在STAGE派生任务中；只适用于不需要敌体碰、受击或被其他敌查询的发射体 |
| `0x10` | 同函数伤害扣血路径要求该位为0且无敌计时器到期 | 只核到阻止扣血；`set_invuln` 有期限且目标事件行为不同，不等于复制整位 |
| `0x20` | 同时进入受击门 `0x21` 与体碰门 `0x22`；502/503还遍历ANM做状态操作 | 同时影响交互及动画，不能只解释成禁体碰或纯外观；按样本拆出必要行为 |
| `0x1000` | 伤害路径选择圆/宽高分支；体碰也切到另一几何路径 | 不能作为目标公开 flag 写入；所需形状/朝向缺少配方时交回 |
| `0x20000` | 移动限位开关，504写入四边界并置位，505清位 | 目标无常驻限位写口，见 §3 |
| `0x80000` | 镜像开关；424按参数置清，创建helper也读取 | 保存在脚本状态；按具体移动指令与创建顺序处理，见 §2–3 |

目标ENEMY_KILLALL_EXEMPT没有一个已核的、覆盖TH18所有清场入口的单一源位映射。若本卡依赖具体清场过滤而本书未定义，应交回，不能从TH18照搬。

## 2. 创建子敌：名字与继承顺序

精确助记名以本机 `th16.eclm` 为准。`A` 族使用绝对坐标；它不是异步标记。下面的“相对”是在父镜像处理之前，加父最终位置；不是加父 ABS 或 REL 单层坐标。

| opcode / 助记名 | 父镜像处理前的出生位置 | 子镜像初始位 | 附加条件 |
|---|---|---:|---|
| 300 `enmCreate` | 父 FINAL + 输入(x,y) | 0 | 普通创建 |
| 301 `enmCreateA` | 输入(x,y) | 0 | 普通创建 |
| 304 `enmCreateM` | 父 FINAL + 输入(x,y) | 1 | 普通创建 |
| 305 `enmCreateAM` | 输入(x,y) | 1 | 普通创建 |
| 309 `enmCreateF` | 父 FINAL + 输入(x,y) | 0 | F分派先检查boss0是否仍可找到 |
| 310 `enmCreateAF` | 输入(x,y) | 0 | 同F条件 |
| 311 `enmCreateMF` | 父 FINAL + 输入(x,y) | 1 | 同F条件 |
| 312 `enmCreateAMF` | 输入(x,y) | 1 | 同F条件 |

若父镜像位0x80000置位，在上表加父坐标之后将最终出生x取负，并翻转子镜像初始位，y不变。因此普通相对创建为 `-(parent_final_x + input_x)`。该规则不外推到所有移动或发弹。F族找到boss0时不执行创建，F不表示继承全部flags。

用户确认Stage01 MainSub05的F创建用于奖励提前击破道中Boss。训练切分已批准将该奖励编队固定为Boss后的完整独立一波，保留编队内部时序和参数，见[统一口径](transcription-policy.md#已批准击破速度奖励波单独训练)。这不改变上面的原生F门语义。

创建helper还打包父4个int和8个float槽的12值快照及父敌ID。本机TH16 eclmap将它们命名为 `I0–I3/F0–F7`（F4–F7位于-9935..-9932）；不要误用只列F0–F3的旧摘要当作完整变量表。目标 `spawn_enemy` 返回不透明句柄，不能把原作ID直接当目标句柄；目标新敌共享槽默认清零，按实际读取传参，并在子主任务首部 `set_self_int/set_self_fx` 初始化。共享值转 `fx` 或 `angle` 时按用途换单位，不能把浮点位模式原样塞进去。原作score/item与目标drop_table/score/sprite顺序不同，须逐参重排。

子敌初始化清单：

1. 确认具体创建变体、父FINAL与镜像状态、F条件是否成立；记下实际出生坐标和首次执行帧。
2. 追踪子敌会读的继承槽、父ID/跨敌查询、传参的求值时点；只读快照与持续读父状态分开。
3. 确定子敌自己的框、交互flags、无敌、移动层和发射器初始化；**没有证据时不继承父et配置/出弹偏移**。
4. 在子敌首部完成共享槽/判定设置后，再启动依赖它们的async；同敌所有async共用敌槽，目标各任务的 `sh_*` 配置却独立。
5. 核子敌退场与父退场关系、屏外继续发射时间、存活查询和取消路径。目标出生次帧首跑，不能仅靠创建坐标正确就认定调度等价。

A表示绝对坐标，M表示子镜像初值；父镜像还按上表独立作用。

## 3. 绝对、相对、镜像与限位如何组合

TH18有ABS与REL两套位置/速度状态，最终位置为两层合成。402 movePosRel写REL层，不等于给当前世界坐标加偏移。两层同时运动、插值未结束或需要读回层变量时，应分别保留状态。

对一个具体样本，先列以下状态，再选实现：

| 必须恢复的状态 | 目标路径 | 必须检查的差异 |
|---|---|---|
| 仅一层位置、另一层恒零、无残余速度 | `move_to(dur,x,y,EASE_*)` | 原400写位置不必然清速；目标 `move_to(0,...)` 会硬停并清在飞插值，不能机械替换 |
| 单层极坐标速度 | `move_vel`、`move_angle`、`move_speed` | 源角用弧度，目标BAM；目标转角走最短弧，源角轨迹必须核；静止时保留脚本角状态，不靠速度推角 |
| ABS和REL共同改变位置 | 保存两层位置/速度/插值状态，每帧算本帧两层贡献，再写目标位置 | 按本书相位规则安排脚本读取与发弹；属于组合方案，不是现成双层内建 |
| 镜像开启 | 在实际指令写入点显式换算x/角/角速度，并保存开关 | `428–431 moveVelNM*` 是需要单独核的非镜像路径；不把镜像自动施加到发弹角、offset或全部坐标 |
| 504/505限位 | 样本若从不到边界可证明无效；确实到边则按帧夹位置 | 仅夹最终目标点不能替代每帧限位；当前没有原生常驻约束，碰边速度、ABS/REL回写和发弹相位未证等价 |
| 随机/圆周/椭圆/Bezier/追敌 | 按给定ECL参数和本书配方恢复轨迹 | 412见[moveRand配方](movement.md)，当前圆周/椭圆样本见[方程与基础时序](circular-motion.md)；其余路径不套TH06 wander公式或凭名字选曲线 |

目标 `move_to` 会停止旧速度缓动并清除先前的速度意图；要在位置补间结束后继续飘，须在 `move_to` **之后**调用速度动词重新设置，位置补间活跃期间速度可推进但不叠加位移。将速度写在move_to前面再期望到点自动恢复，会丢掉这条意图。

组合顺序应记录为“指令写哪一层、是否受镜像、各层如何推进、何时合成、限位何时夹、发弹读取哪个位置”。不要自行认定统一顺序后套全库。本轮没有补全所有原生移动消费者；尤其复杂轨迹、镜像+双层+限位的完整组合仍属 `需上下文`，要求准确而又无法证明时 `blocked`。

## 4. 同一敌人的段入口：恢复状态而非重置模板

HP/超时中断、外部换sub通常仍在同一只敌上运行；新sub的第一行不是新敌出生。八槽HP/超时表与`time_in_ecl`的细节沿用TH18研究，TH16具体调用应按本作入口状态核对；`time_alive`是另一计时器。`513 timerReset` 不可据名字当成清空所有时钟，`TIME`、TIMEOUT和脚本时间也不能合成一个计数。

独立取一段时，准备者沿调用者与前一段找最近一次写入，随工作包交接以下实际需要的状态；作者核对本卡内部读取，缺资料就交回：

- 实际位置、ABS/REL层、速度/方向、在飞插值、镜像和限位；入口前尚未完成的移动不能默认为静止。
- 受击框、体碰框、形状、相关flags、临时禁碰/无敌剩余时间。段中没有设置不代表使用构造默认。
- I/F槽、局部参数、跨敌/全局值和难度分支；保留共享与快照差别。
- 每个et槽的普通字段、offset、EX记录与追加游标；目标每任务4槽，不能把前段配置遗漏或跨async假共享。
- 仍存活的子敌、async、子弹、激光及句柄；中断到底取消哪些任务、留下哪些实体。
- 攻击首发相对入口的延迟、已消耗的随机读取、使用的计时器，以及这段终止依据。

若用户已指定固定rank、单段无敌练习，段外完整血线/UI/收卡流程可按任务单裁剪；本攻击内部仍影响危险行为的部分继续保留。**攻击内部**回调若会再次发弹、切换配置、移动、生成/删除子敌、解冻、清弹或取消async，仍是攻击内容，不能因为名字叫“回调/中断”就整条删除。目标 `spell_begin/phase_begin` 管自身段生命周期，不是原作通用八槽中断表；`556 setDeath` 也不能写入目标死亡脚本字段就声称已执行回调。

取消边界同样重要：原 `17 killAsync` 按同敌用户ID查找，`21 killAllAsync` 遍历同敌async；目标 `kill` 的任务标识与 `KILL_CHILDREN` 的直系子树范围不同。只有能静态证明有限任务集合、取消对象和帧顺序时才改写；其他情形保留缺口，不加未经批准的通用任务管理机制。

## 6. Stage01试切后补核的非阻塞项

以下定义可直接使用；unknown助记名不等于语义未核。

- **573 unknown573、574（ins_574）**：限时额外掉落和奖励窗口/计时，属于普通道具省略范围，不是等待或发弹配置。
- **569 unknown569、570 unknown570**：569登记并增加章节计数权重；570在章节匹配时结算并清零。所述调用不改运动/发射配置，省略范围见统一口径。
- **401 movePosTime在frames≤0时**：只取消该位置插值，不把x/y写成当前位置；不能改成目标move_to(0,...)瞬移。后续正时长移动从当前实际位置开始。
- **525 enmKillAll与死亡回调**：对通过源flag过滤的敌执行非空setDeath程序；571的另一清场路径先清回调。当前攻击内部的回调仍按源行为保留，纯交接尾部按[统一口径](transcription-policy.md#系统性省略与外壳接管)处理。

本章仅给已核规则；未覆盖的复杂组合不自动变为目标支持，实际需要时交主会话。
