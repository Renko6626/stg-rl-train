## 指令入口和调用顺序

Priw8 的 [ECL 指令说明](https://priw8.github.io/js/ecl/ins.js)只给通用语义：632 `funcSet(id)` 安装逐帧函数，637 `funcCall(id)` 当场调用一次，639 `funcSet2(id)` 安装逐帧函数并把另一个标志设为 1。TH16 原生 `EnemyData__ecl_run_over_300` 的 `0x4202b6`、`0x4202db`、`0x420336` 分别执行这些动作；632/639 写敌人 `+0x4518` 函数指针、`+0x451c` 标志（分别 0/1）。`EnemyData__on_tick` 的 `0x41d33a` 在 ECL 执行后读取 `+0x4518`，以当前敌人为 `ECX` 调用，然后才进入 `EnemyData__step_logic`。637 直接取同一函数表调用。现有六面源仅使用 632。

函数表 `0x4917b8` 的槽 0 为 null，槽 1 为 `0x4252d0`，槽 2 为 `0x4253b0`。本六面源中的 `funcSet(0)`（如 `st06bs.ecl` 第 1298、1435、1600 行）清除逐帧回调；id 1/2 分别在本卡设置，切段时恢复 0。`funcSet(0)` 没有调用清弹、清场或重置生命的动作。

## id 1：近玩家的标记弹跳到另一段运动脚本

`BossCard4` 第 1319–1320 行先把敌人 F0 设为 96，再 `funcSet(1)`。原生回调 `0x4252d0` 遍历全局弹链。对 `bullet+0xc4c == 1` 且弹坐标 `+0xc20/+0xc24` 与玩家位置的平方距离小于 `enemy+0x29c`（该敌 F0）的平方的弹，它写：

- `bullet+0xc60 = 8`：弹运动 VM 的下一执行槽；
- `bullet+0xc4c = 2`：避免继续满足 `==1`；
- `bullet+0xc68 = 0`：清除当前运动效果位。

本卡 `BossCard4_at` 中 `etEx(..., 32768, 1, ...)` 设置 EX_REACT 标记 1，`etExSet` 在槽 8–12 安排后续效果（源第 1363 行起）。`bullet_vm_exec` `0x413860` 从 `+0xc60` 取下一指令、按 `+0xc68` 执行运动效果，且 EX_REACT 将参数写入 `+0xc4c`。因此 id 1 是**逐弹、玩家邻近触发的弹运动切换**，会改实际弹轨迹/危险区；它不直接修改敌人 HP/时间、玩家判定或场界。回调遍历全局弹链，但只处理 `+0xc4c == 1` 的弹；该卡发出的弹满足此标记。renkolab 旧弹幕文档对 EX_REACT 消费者的“未发现”记录已被此函数补足。

**已批准转写（2026-11-07）**：用户选择将`th16_s6_b8`实现为任务弹的纯运动学行为，不用xform模拟本卡触发器。保留逐弹首次进入玩家96px范围的严格距离条件、触发前运动、触发时终止旧运动及触发后变速。采用源type19/color3对应的固定目标弹型和基础半径，省略BRIGHT、SIZE、HITBOX切换，其他非运动状态按普通目标弹处理；不增加动态弹半径/尺寸写口，不因此再次阻塞。样式效果删去后不补回仅由这些效果造成的等待；源显式wait、120/60帧运动参数和随机/共享关系仍保留。

任务每帧只控制自己的弹；触发仅一次，不能触发后重新进入检测循环。后段变速结束后任务可返回，弹继续运动，避免无用地持有任务槽。当前任务池256，段池2048，不因许可自动扩池；作者按现有代表运行与执行器验收检查实际容量，不用理论峰值替代实测，也不减弹绕过。若发现真实任务池满，按具体日志交回。纯运动学方案已可交给作者，尚未证明整卡运行通过。

## id 2：压制玩家火力和季节槽

四季 `BossCard6/7/8/9` 分别在六面源第 1623、1964、2305、2636 行 `funcSet(2)`。原生回调 `0x4253b0` 每帧将 `CURRENT_SEASON_POWER` 及 `CURRENT_POWER` 设为 0（若各自上限为负，则钳到该上限），然后调用 `PlayerInner__repopulate_options` `0x4440e0` 和 `season_gauge_render_42c600` `0x42c600`。子机重建读取当前火力/季节档位，因而主/副射击能力被压制；后一个调用刷新季节槽显示。回调本身没有读取或写入敌人生命、阶段计时、弹对象、弹发射器、激光、玩家受击判定或场界。

**转写结论**：已批准的无敌敌人躲弹外壳不按玩家射击 DPS 推进四季内部阶段；玩家火力及季节槽也不作为这四卡的攻击脚本输入。因而在这个外壳中可省 id 2 对玩家火力、子机和 UI 的压制，继续按各卡原脚本的 `$LIFE/$TIME` 条件及已定时间分支处理。`funcSet(2)` 本身不提供生命回退，也不改变 7200 帧时限；`BossCard6` 的起始 life 5000、`BossCard8/9` 自行设置的 3200/5300 仍按各自源脚本判断。该判断只适用于当前训练外壳，不宣称原作玩家射击行为等价。
