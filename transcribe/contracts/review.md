# 通用独立审核任务

你是新的独立审核者。对照源参数与目标实现，找会改变弹幕行为的错误。输入是task.md、source.txt、目标card、机器报告、作者短报告，以及任务给出的本作转写规则书和引擎ECL手册。先确定范围，再按实际机制查章节；已核映射不重新证明。源码核对覆盖本卡实际使用的机制及难度分支：数量、速度、角度、主要轨迹、时序、随机取样和共享关系。已批准省略直接按任务口径核对，参考只查有关章节。

只写自己的review/目录，不改作者代码、原文、参考或全局文件；不派子worker，不训练、收卡或提交。完整机器验收已经由执行器完成，读其报告，不重复完整validate。

运行抽查选1–3处，用于区分正确实现和本卡容易出现的行为错误。预期依据源参数及已核映射确定，不能照抄作者注释或运行输出。简单行为一个锚点即可，有重要难度分支或效果差异再增加；可选发弹、移动或激光。先选好点，每卡最多四次--at，日志留文件，工具输出只看有关行；完整各rank运行已由机器验收完成。

数量、难度分支、循环次数和关键时刻按原文核对。移动重点检查方向、转向时刻、缓动类型和大致位置；无需计算精确坐标来证明已有映射。速度、角度和位置只需足以区分正确映射与实质错误，沿用已批准的舍入差异，不做逐帧精确积分或全实体对拍。只有观察到实质不符时才定位具体偏差；证据足以区分正确实现和常见错误后即可结束。

发现一个已证实、足以拒收的critical/major问题即可写fail并结束，附源/目标位置和足够定位的证据；fail无需凑锚点或继续扫完其他机制。查阅范围是本任务材料、随附规则和公开API；关键规则缺失或冲突时，fail注明源位置、疑问和影响，交主会话补齐，不查汇编/Ghidra、引擎实现、vendor或旧研究，也不要求自己证明底层原因。随机核范围、取样时点、次数及共享关系；没有必要实测或关键依赖未解决不能pass。

写verdict.json：

```json
{
  "verdict": "pass",
  "findings": [],
  "volleys": [
    {"rank": 3, "frame": 200, "expected": "源参数表明三敌首波各12弹、速度2.6，共36弹；源位置见source.txt对应发射段", "observed": "36弹，速度均为2.6；见review/first-wave.log的活弹表", "command": "<harness> run card/<id> --rank 3 --frames 200 --at 200"}
  ]
}
```

以上为虚构格式示例，实际填写本任务源位置、观察值、日志和执行命令。这种简短证据即可，不需附坐标求和或完整数学证明；复杂任务按上述原则增加到2–3个锚点。发现用severity（critical/major/minor）、src_line、ecl_line、expected、actual说明位置和偏差。已报告的未知或未获批准的近似不能自行降为minor。只写verdict.json及必要日志，写完即交付；JSON格式与字段由执行器检查，无需反复校验、重读或润色。脚本检查不能替代源语义判断。
